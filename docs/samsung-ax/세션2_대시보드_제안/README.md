## 주신 대시보드 요구 → 화면 어디에

| 주신 요구 | 화면 어디 | 어떻게 |
|---|---|---|
| 총 매출 | 1 한눈에 | 이번 달 · 올해 누계 |
| 판매처별 · 수요처별 · 파트별 · 모델/품목별 매출 | 4 나눠 보기 | 버튼 다섯 개(판매처별 · 수요처별 · 파트별 · 품목별 · 모델별) |
| 월별 매출 | 2 월별 매출 | 올해 · 작년 선 그래프. 달을 누르면 그 달이 기준월 |
| 일별 매출 | 3 일별 매출 | 하루 막대. 누르면 **그날 내역** 표 |
| 전년 매출 | 1 · 2 · 4 · 5 | 작년 선을 겹쳐 그림. 표마다 '작년 대비' 열 |
| 드릴다운 (또는 버튼 선택) 시 값 변경 | 조건 칸 · 4 나눠 보기 | 조건 칸 넷(기준월 · 파트 · 수요처 · 품목)을 고르면 화면 전체가 바뀜. 표의 줄을 누르면 그 안으로 — 판매처 → 수요처 → 품목 → 모델. 화면 위 ✕로 풀기 |
| 보직장 — 일 매출을 매일, 피벗으로 뜯어봄 | 3 일별 · 4 나눠 보기 · 6 판매처 표 | |
| 임원 — 전년비 · 전월비, "요즘 왜 이런 거야?" | 1 한눈에 · 2 월별 · **5 왜 이렇게 됐나** | 증감을 '어디서' 났는지로 쪼개고, 작년 큰 건을 보여 줌. 따로 고를 것 없이 처음 화면에 나옴 |
| 품목 담당 — 품목별 | 4 「품목별」 버튼 · 조건 칸의 품목 | 품목 하나를 고르면 월별 · 일별 · 왜까지 그 품목으로 바뀜 |
| 판매처(대리점) 1곳이 수요처 몇 곳을 관리하나 | 6 판매처가 맡은 수요처 | 대리점 × 수요처 표 + 맡은 수요처 수 + 두 곳 이상이 맡는 수요처 표시 |

**비개발자가 쓰는 화면으로 줄였습니다.** 고르는 칸 넷, 버튼 한 줄(4번), 나머지는 누르는 표입니다. 용어도 회의에서 쓰는 말로 바꿨습니다 — 동기간 → "같은 날짜까지", 피벗 → "나눠 보기", 드릴다운 → "눌러서 들어가기".

### 이 구성에서 일부러 넣은 원칙 넷

| 원칙 | 왜 |
|---|---|
| **모든 비교는 같은 날짜까지** — 9월이 24일까지면 8월도 작년 9월도 24일까지 | 8월 **전체**와 견주면 9월이 −40%로 보이지만, 같은 날짜까지 자르면 **+2.8%**입니다. 이 팀은 월말 7일에 매출의 42%가 몰립니다 |
| **'왜'는 '어디서'까지만** | 화면은 감소가 어디서 났는지까지 보여 줍니다. 원인은 사람이 확인합니다 |
| **작년 쪽도 본다 (기저효과)** | 9월 전년비 −46.9%의 116%가 한 수요처인데, 그 대부분이 **작년 9월 일회성 납품 4건**입니다. 빼면 −1.9%입니다 |
| **직판은 '직판' 한 줄** | 헤더 설명대로 직판은 판매처 = 수요처라, 묶지 않으면 판매처가 아홉 곳처럼 보입니다 |

공유해 주신 열 설명과 **우리 데이터가 실제로 넣은 값**을 나란히 둡니다. 다르게 보신 부분이 있으면 그 줄만 짚어 주십시오.

| 열 | 주신 설명 | 우리 데이터 | 확인 |
|---|---|---|---|
| 영업기회 번호 | 영업기회별 관리번호 | `OPP-2025-0001` 형식, 연도별 일련번호, 1건 = 1행 | **①** |
| 영업기회 유형 | 선행영업이냐 트렌드냐 | 선행영업 30% · 트렌드 70% | |
| 그룹명 | 영업담당 조직_그룹 | 한국총괄 B2B영업그룹 / B2B유통그룹 | |

| 판매처명 | 판매한 대리점 이름 (ex. oo정보통신) | 남해정보통신 · 동백시스템 · 가야네트웍스 / 직판은 수요처명 | |

## 확인 부탁드리는 것

| # | 질문 | 왜 필요한가 |
|---|---|---|
| ① | **한 영업기회에 매출이 여러 번** 잡히는 게 정상입니까 | 지금은 1건 = 1행으로 만들었고, 지시문은 중복을 만나면 멈추고 물어보게 되어 있습니다. 정상이면 합산하도록 한 줄만 바꿉니다 |
| ② | **파트명과 주문유형이 1:1**이 맞습니까 | 지금 데이터는 유통주문이 전부 경로1파트입니다. 실제로 섞인다면 파트별 매출이 달라집니다 |
| ③ | **직판일 때 판매처 주소**에 무엇이 들어갑니까 | 지금은 `—`로 비워 두었습니다 |
| ④ | **실제 모델명**을 주실 수 있습니까 | 가상 모델명을 썼습니다. 조회 가능한 실제 모델명이면 **세션4에서 사양을 찾아보는 흐름과 이어집니다** |
| ⑤ | **단가(공급가) 열**을 넣을 수 있습니까 | 지금 헤더로는 `단가 × 수량 = 금액` 검산을 할 수 없습니다. **아래를 꼭 봐 주십시오** |
| ⑥ | 실제 데이터의 **수요처 수**는 몇 곳 규모입니까 | 4번 표와 5번 막대는 15곳이 넘으면 길어집니다. 상위 N + 기타 기준을 미리 정하겠습니다 |
| ⑦ | 실제 추출 때 **작년 같은 기간이 같은 파일에** 들어갑니까 | 전년비는 작년 데이터가 같은 파일에 있어야 나옵니다. 지금은 2년치를 넣었습니다 |
| ⑧ | **추출일(기준일)**은 보통 언제입니까 | 이번 달을 같은 날짜까지 자르는 기준입니다. 지금은 9월 24일로 두었습니다 |

### ⑤번을 따로 적는 이유 — 단가 열이 없으면 검산 실습이 약해집니다

기존 데이터 분석 실습의 중심은 **`공급가 × 판매수량 = 판매금액`을 전 행에서 맞춰 보고, 어긋나면 멈추는 것**이었습니다.
"AI가 낸 숫자를 그대로 믿지 않는다"를 손으로 겪게 하는 장치였는데, 새 헤더에는 단가가 없어 그대로는 성립하지 않습니다.

그래서 **다섯 축 소계 파일을 따로 내려 주고, 원본에서 다시 더해 대조하게** 바꿨습니다.
검산은 살아 있고, 다섯 축이 한 줄에서 같이 어긋나면 **어느 행인지까지 좁혀집니다**. 다만 행 단위로 틀린 것을 바로 잡지는 못합니다.

- **단가 열을 주실 수 있으면** 원래 실습을 되살리고 소계 대조와 둘 다 돌리겠습니다.
- **어려우시면** 지금 안(소계 대조)으로 갑니다. 이 경우 화면에 "단가 열이 없어 검산식을 세울 수 없음"을 명시하고 넘어갑니다.

## 세션2 ↔ 세션4 연결
