# 시연 로그 — A_sensing_b2b

> 도입 15분 시연은 이 순서 그대로 진행합니다.
> 실행 기록: **미실행** — Gemini Enterprise 에이전트(또는 ChatGPT)에서 실행 후 "실제 대화" 표를 채웁니다. 기대 응답은 `04_answer/` 기준입니다.

## 올린 파일
1. `01_data/rss_feed.csv` (30건 4열)
2. `01_data/target_builders.csv` (건설사 6곳)

## 붙여넣은 프롬프트
`02_prompt/prompt_3_분석.md`의 ✂ 사이. 스킬이 열려 있으면 `07_skill/SKILL.md` 등록.
클릭 경로: 사이드바 [에이전트] → [+ 새 에이전트] → **"수동으로 빌드"** → 지침 붙여넣기 → 참조 파일 → 저장. (`common/tool_paths.md` 2장)

## 시연 앞 3분 — 단계 1과 예약을 보여줍니다
구글 뉴스 RSS 주소에 검색어를 넣어 결과가 나오는 것을 한 번 보여주고, **예약 화면**을 엽니다 (`common/tool_paths.md` 6장).
그리고 말합니다. **"수집은 매주 같습니다. 그래서 사람이 아니라 주기가 돌립니다. 우리가 만드는 건 그 주기에 걸 절차입니다."**
RSS 접속이 막혀 있으면 `01_data/rss_sources.md`의 검색어 조합표로 대체합니다.

## 첫 메시지
```
rss_feed.csv와 target_builders.csv를 올렸어. 기준일은 2026-09-01이야.
지침 순서대로 대시보드를 만들어줘.
```

## 첫 응답에서 확인할 것
- [ ] 수집 요약에 **원본 30건 → 중복 3건 제외 → 27건**이 나오는가
- [ ] 우선순위 1위가 **한울종합건설**인가 (대성건설이 아닌가)
- [ ] **서진이엔씨가 `보류`** 로 분류되는가

## 안 나오면 되묻는 문장
```
우선순위를 규모가 아니라 접근 시점 기준으로 다시 정렬해줘.
접근 시점은 준공 예정일에서 6개월을 뺀 값이야.
그리고 실적이 악화된 수요처는 기회가 아니라 보류로 분류해줘.
```

## 참가자에게 짚어줄 한 문장
"1.2조 수주한 회사가 3순위입니다. 규모가 아니라 **언제 사양이 정해지는가**로 줄을 세웠기 때문입니다."

## 두 번째 장면 — 단계 2를 즉석에서 (4분)
새 대화에서 `prompt_2_프로파일.md`를 붙여넣고 `프로파일 만들어줘.`만 보냅니다.
**회사명부터 묻는지** 확인하고, 두세 개는 답하고 하나는 일부러 "모른다"고 답합니다.
`확인 필요`로 비워 두고 넘어가면 말합니다. **"빈칸이 남은 프로파일이 채워진 가짜 프로파일보다 낫습니다."**

## 세 번째 장면 — 실패 테스트 (2분)
`03_tests/rss_feed_실패.csv`를 올리고 같은 요청을 보냅니다. **개인정보 3행을 짚고 멈추는지** 확인합니다.
