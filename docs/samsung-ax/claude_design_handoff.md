## [복붙 프롬프트] — claude.ai/design 채팅에 붙여넣기

[ROLE]

당신은 대기업 사내 교육 자료를 전문으로 하는 15년차 시니어 프레젠테이션 디자이너입니다.
전자·제조 대기업의 영업 조직 대상 실습형 교육 deck을 다수 설계해 왔습니다.
슬라이드가 강의장에서 "띄워놓고 따라 하는 화면"으로 기능하도록 만드는 데 강합니다.

[GOAL]

삼성전자 B2B 영업 담당자(B2B팀·B2B유통전략팀)가 1일 8시간 과정 중
강사 담당 6시간 동안 **업무용 AI Agent 4개를 직접 만들어 보는** 실습 과정의
발표용 슬라이드 deck을 만들어 주세요.

각 슬라이드는 강사가 띄워놓고 설명하거나, 참가자가 보면서 따라 하는 용도입니다.
설명 슬라이드는 한 장당 핵심 메시지 1개가 3초 안에 읽혀야 하고,
실습 슬라이드는 좌측 시간 배분·우측 체크리스트가 한눈에 들어와야 합니다.

[AUDIENCE]

삼성전자 B2B 영업 담당자 차수당 40~50명.
- **B2B팀** — 대기업·공공 수요처 직접 영업. 산업별 담당이 나뉨
- **B2B유통전략팀** — SMB 대상, 파트너사를 통한 경로 영업
AI 활용 역량 편차가 크고 기초 단계 비중이 절반을 넘습니다.
전원 개인 노트북으로 **웹 브라우저에서** ChatGPT·Gemini를 씁니다. 앱·설치 도구는 쓰지 않습니다.

[PAGES] (7블록 구조 · 53슬라이드)

■ 오프닝 (6장)
- 표지: "B2B 영업 AI Agent 실습 — 시장·고객 분석 / 제안자료 작성 / 데이터 분석 / 삼성전자 2026"
- 오늘 만드는 것: Agent 4개가 하나의 영업 여정으로 이어지는 체인 다이어그램
- 오늘의 흐름: 6시간 타임라인 (② 2h → ③ 2h → ④ 2h). 앞뒤 ①⑤는 회색 처리
- 시작 전 준비: 탭 두 개(AI 창 + 메모장)·저장 폴더·업로드 테스트·가상 데이터만
- **웹 환경에서 결과를 남기는 법**: 화면 복사 → 메모장 → 저장 → 다음 모듈 업로드 (4단계 그림)
- **지시문은 메모장에 먼저**: 세션이 끊기면 채팅창 지시문은 사라짐 (좌우 대비)

■ 공통 방법론 (11장)
- 왜 Agent를 팀마다 따로 만들지 않는가 (✗ 6개 제작 / ○ 공통 골격 + 팀별 데이터)
- 컨텍스트를 데이터로: 안 바뀌는 것 / 바뀌는 것 2열 표
- 일반 대화와 업무 Agent의 차이
- **그럴듯함 ≠ 정확함**: 51 : 49 — 채택된 답 / 조용히 버려진 예외 (숫자 크게)
- **시작은 RACS, 익숙해지면 7블록**: RACS 4줄 코드블록 + 7블록 대응표
- IPO 명세: INPUT·PROCESS·OUTPUT·STOP·APPROVAL·TEST 6칸
- 지시문 7블록: ①역할 ②업무범위 ③입력검사 ④처리순서 ⑤출력형식 ⑥중단·보안 ⑦성공기준
- 나쁜 문장 vs 좋은 문장 (검증 가능하게 쓰기, 3쌍 대조)
- 테스트 3종: 정상 · 경계 · 실패 (3열) — "중단은 실패가 아니라 성공 행동"
- 사람이 하는 일: AI 초안 / 사람 확정 2열
- 오늘의 완주 기준: 최소 완주 라인 / 확장 라인

■ 모듈 ② 시장·고객 분석 Agent (9장) ← **팀별 분기 구간**
- 모듈 표지 (Sensing · 2.0h)
- 지금은 이렇게 일합니다 **[팀별]**
- 오늘 만들 결과물 **[팀별]** — B2B팀은 HTML 대시보드, 유통전략팀은 Word 보고서
- 입력 데이터 **[팀별]**
- 실습 1: IPO 작성 (20분)
- 도구 화면: Gemini Deep Research + Gemini Notebook (경고 — 1인 1회)
- 실습 2: Agent v0 (35분)
- 이 데이터의 함정 **[팀별]**
- 실습 3: 테스트 3종 (25분)

■ 모듈 ③ 제안자료 작성 Agent (9장) — 전원 공통
- 모듈 표지 (Action · 2.0h)
- 앞 단계에서 받은 것 (체인 ②→③ 강조)
- 제안서 순서는 정해져 있습니다: 회사소개 → 제안내용 → 제품소개 → 유지보수
- 공통과 팀별: 틀은 같고 자료가 다름
- 실습 1: IPO 작성 — 독자를 반드시 지정
- 도구 화면: Gemini 에이전트 + 참조 파일
- 실습 2: Agent v0 (35분)
- **이건 절대 쓰면 안 됩니다**: 가격·납기·할인은 확정 문구 금지 (참고 단가 표기)
- 실습 3: 테스트 3종 — 확정 견적 요구 프롬프트를 슬라이드에 그대로

■ 모듈 ④ 데이터 분석 Agent (9장) — 전원 공통
- 모듈 표지 (Analysis · 2.0h)
- 보고서보다 먼저 오는 것: 0번 데이터 점검
- 이 파일을 그대로 믿으면 안 됩니다: 표지 합계 vs 상세 합계 대조
- 입력 데이터와 두 갈래 경로: 코드 실행 O 원본 / X 소계본
- 실습 1: IPO 작성 — 합계 대조를 PROCESS에
- 실습 2: Agent v0 (35분)
- **분모를 밝힙니다**: 같은 데이터에서 두 개의 비율이 나옴
- **없는 값은 채우지 않습니다**: 자료에 없으면 "확인 필요"
- 실습 3: 테스트 3종

■ Skill과 MCP (6장)
- 오늘 만든 것에는 이름이 있습니다: 지시문 7블록 + 참조 파일 = Agent Skill
- **SKILL.md 세 부분**: name · description · 본문 (코드블록 + 규칙 3줄)
- description이 따로 있는 이유: 설명만 항상 읽히고 본문은 필요할 때 (✗/○ 대조)
- **Agent 워크플로우 5패턴**: 체이닝 / 라우팅 / 병렬화 / 오케스트레이터-워커 / 평가자-최적화 — 우리 4개 배지 표시
- **오늘 만들어도 되는 일인가**: CANNOT 7항목 체크리스트 + 좋은 과제 3원칙
- 다음 단계: Skill은 어떻게 일할지, MCP는 무엇에 접근할지 (계단 그림)

■ 클로징 (3장)
- 내 업무로 옮기려면: 바꿀 5가지 / 안 바꿀 것 (상단에 As-Is → To-Be 한 줄)
- **다섯 가지 원칙**: 보안 최우선 · Human-in-the-Loop · 할루시네이션 관리 · 작은 범위 · 결과 검증
- 7일 계획: DAY1 범위 → DAY2 자료 → DAY3 규칙 → DAY4 테스트 → DAY5 검토 → DAY7 기록

[TONE]

절제된, 실무적인, 신뢰감 있는, 명료한.
삼성전자 B2B 조직다운 단정함 + 기초 참가자도 부담 없는 친절함의 균형.
"가르치는 톤"보다 "같이 만들어 보는 톤". 과장·감탄사 없이.

[REFERENCE / 비주얼 방향]

- 삼성 CI 고려: 삼성 블루 메인 + 그레이·차콜 보조, 포인트 컬러 1개로 경고/강조.
- 절제된 그리드, 굵은 헤드라인, 모듈 라벨(②③④) 구조.
- 슬라이드 좌하단 또는 우상단에 **모듈 라벨 + 페이지 번호** 일관 배치.
- **실습 슬라이드 전용 레이아웃**: 좌측 시간 배분(분 단위 스텝), 우측 체크리스트 박스. 이 레이아웃이 12장 반복되므로 마스터로.
- 대조표(✗/○), 3열 비교, 체인 다이어그램, 계단 그림, 체크리스트를 적극 활용.
- 경고 박스 스타일 1종 필요 — "가격 확정 금지", "실행 1회 제한" 같은 금지·제한 문구용.

[CONSTRAINTS]

- 발표용 16:9 슬라이드. 한국어. 슬라이드당 텍스트 최소화(핵심 1메시지).
- **웹 브라우저 전용 환경** — 데스크톱 앱·CLI·설치 도구 화면은 등장하지 않습니다.
- **[팀별] 표시 9장은 B2B팀 / B2B유통전략팀 두 벌**이 필요합니다. 나머지 44장은 공유하므로, 팀 버전만 교체 가능한 구조로 설계해 주세요.
- 실습 슬라이드는 "🖐 핸즈온" 배지로 구분되게. 시간(20분/35분/25분)을 배지에 표기.
- 데이터·고객사·실적은 **전부 가상**입니다. 슬라이드 하단에 가상 데이터 표기를 넣을 수 있는 자리 확보.
- 삼성 실제 로고·제품 이미지는 미포함 — 자리표시자로 두고 컬러·무드만 CI 방향에 맞춰 주세요.
- 도구 화면(ChatGPT·Gemini) 캡처는 자리표시자 프레임만. 실제 캡처는 고객사에서 받습니다.
- 90분 축약판 운영이 있으므로, **잘라내도 흐름이 끊기지 않는 장**을 시각적으로 구분 가능하게(예: 보조 라벨).

[AI 슬롭 회피]

진부한 폰트(Inter·Roboto·Arial)·보라 그라데이션·천편일률 3-카드 그리드 금지.
아이콘만 나열한 장식성 슬라이드 금지 — 모든 도식은 실제 절차나 데이터 구조를 설명해야 합니다.
스톡 일러스트·추상적 AI 이미지(뇌·회로·로봇) 남발 금지. 절제된 도식과 표 위주.
"혁신", "미래", "게임 체인저" 같은 공허한 카피 금지. 이 deck의 문장은 전부 지시·절차·기준입니다.
