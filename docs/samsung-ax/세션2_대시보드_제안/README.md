# 세션2 매출 대시보드 — 제안 폴더

> 공유해 주신 **매출 데이터 16개 열**을 그대로 받아 대시보드를 만드는 세션2 전반부의 실물입니다.
> 지시문 한 장, 가상 데이터 한 장, 그 데이터로 실제 나온 결과 화면 한 장이 들어 있습니다.
> **디자인은 아직 손대지 않았습니다.** 내용과 열 구조를 먼저 확정하기 위한 초안입니다.

## 들어 있는 것

| 파일 | 무엇인가 |
|---|---|
| `지시문_대시보드.md` | 참가자가 에이전트 「지침」란에 붙여넣는 지시문. `✂` 사이가 붙여넣는 부분 |
| `매출데이터_예시.csv` | 공유해 주신 16개 열 구조로 만든 **가상** 매출 데이터 57행 |
| `대시보드_예시.html` | 위 데이터와 위 지시문으로 나온 결과 화면. 브라우저로 열면 됩니다 |

**데이터는 전부 가상입니다.** 실제 거래처·파트너·모델명·단가·실적은 한 줄도 들어 있지 않습니다.
열 이름과 값의 성격만 공유해 주신 헤더에 맞췄습니다.

## 가상 데이터의 모양

| 항목 | 값 |
|---|---|
| 행 수 | 57행 (영업기회 번호 중복 없음, 1건 = 1행) |
| 기간 | 2026-01-15 ~ 2026-09-25 |
| 매출금액 합계 | 836,670,000원 |
| 수요처 | **6곳** (해솔호텔·대성건설·한울종합건설·미래로병원·세종교육재단·서진리테일) |
| 판매처 | 9곳 |
| 품목구분 | 5종 (사이니지·TV·PC·에어컨·모니터) / 모델명 10종 |
| 주문유형 | 직판주문 55.4% · 유통주문 44.6% |
| 영업기회 유형 | 트렌드 79.8% · 선행영업 20.2% |

수요처를 6곳으로 맞춘 것은 메일에서 말씀해 주신 **"고객사 숫자는 일관성 있게 6개로 유지"**를 그대로 따른 것입니다.
세션1·세션3의 실습 데이터도 같은 6곳을 씁니다.

## 이 데이터를 일부러 이렇게 만든 이유

**틀린 데이터를 심지 않았습니다.** 다른 모듈에는 검산이 어긋나는 행을 일부러 넣은 함정 파일이 있었는데, 세션2에서는 뺐습니다.
대시보드는 "숫자를 의심하는 법"보다 **"무엇으로 나눠서 볼 것인가"**를 배우는 자리라서, 데이터 오류 찾기가 끼면 초점이 흐려집니다.

대신 **이 헤더에서 실제로 걸리는 것**을 교육 소재로 남겼습니다.

| 심어 둔 것 | 참가자가 만나는 것 |
|---|---|
| 단가 열이 없음 | 검산식을 세울 수 없음 → 에이전트가 「확인 필요」에 그 사실을 적고 넘어간다 |
| 3분기가 9월까지만 있음 | 그대로 비교하면 무조건 감소로 보임 → 덜 찬 분기를 비교에서 빼는 판단 |
| 상위 2개 품목이 60% | 쏠림인지 원래 구조인지 데이터만으로는 못 판단 → 세션2 후반 인사이트 질문으로 이어짐 |

## 결과 화면이 실제로 내놓는 것

`대시보드_예시.html`을 열면 다섯 덩어리입니다.

- **한눈에** — 836,670,000원 / 57건 / 건당 14,678,421원 / 2026-Q2 −12.4%
- **어디서 나왔나** — 품목구분(사이니지 30.6% · TV 29.1%, 상위 2개 60%) · 주문유형 · 수요처명(한울종합건설 33.1%, 상위 2개 56%)
- **지난 기간과 견주면** — Q1 355,070,000 → Q2 311,160,000. **3분기는 기간이 덜 차서 비교에서 제외**
- **눈에 띄는 것** — TV −58% · 에어컨 +55% · 사이니지 +43%. 항목마다 근거 행 번호
- **확인 필요** — **단가 열이 없어 검산식이 없음** 등 4건

## 확인 부탁드리는 것

| # | 질문 | 왜 필요한가 |
|---|---|---|
| 1 | **단가(또는 공급가) 열**을 넣을 수 있습니까 | 지금은 `단가 × 수량 = 금액` 검산을 할 수 없습니다. 열이 있으면 0번 점검이 실질적으로 강해집니다. 없으면 지금 안대로 "검산식 없음"을 명시하고 갑니다 |
| 2 | **한 영업기회에 매출이 여러 번** 잡히는 게 정상입니까 | 지금 지시문은 영업기회 번호 중복을 만나면 멈추고 물어보게 되어 있습니다. 정상이라면 합산하도록 한 줄 바꿉니다 |
| 3 | 실제 데이터의 **수요처 수**는 몇 곳 규모입니까 | 15개를 넘으면 표가 길어져 대시보드가 깨집니다. 상위 N + 기타로 묶는 기준을 미리 정해 두겠습니다 |
| 4 | 집계 축 **세 개(품목구분·주문유형·수요처명)**가 맞습니까 | 파트명·영업기회 유형·판매처 주소도 축으로 쓸 수 있지만 기본에서 뺐습니다. 현장에서 실제로 쪼개서 보는 기준이 다르면 바꾸겠습니다 |
| 5 | `매출일자` 외에 **수주일자·예상 매출일**이 따로 있습니까 | 선행영업과 트렌드를 기간으로 구분하려면 매출일자만으로는 부족할 수 있습니다 |

## 세션2 ↔ 세션3 연결

헤더가 바뀌면서 세션3(제안자료)이 세션2의 결과를 그대로 물려받기 어려워진 부분이 있습니다.

- 세션2의 결과물은 **대시보드 한 장**이고, 세션3이 필요한 것은 **한 수요처의 요구조건**입니다. 단위가 다릅니다.
- 지금 안은 세션2 후반 인사이트 질문의 결과(줄어든 수요처, 쏠린 품목)에서 **수요처 한 곳을 고르는 것**으로 잇고 있습니다.
- 다만 이 데이터에는 **제안에 필요한 정보(요구조건, 설치 환경, 경쟁 상황)가 없습니다.** 세션3용 요구조건 파일은 별도로 유지하는 쪽이 맞다고 보고 있습니다.

이 연결을 (a) 세션2의 수요처 하나를 골라 세션3으로 넘기는 방식으로 할지, (b) 세션2와 세션3을 각자 완결시킬지 의견 주시면 그에 맞춰 정리하겠습니다.
