## 1회차 — 2026-09-12

네 모듈 모두 **결함이 나왔습니다.** 자동 검사 11항목을 통과한 상태였는데도 그렇습니다.
자동 검사는 "파일이 있고 헤더가 맞는가"를 보고, 블라인드 검증은 **"지시문만 보고 같은 답이 나오는가"** 를 봅니다. 둘은 다른 것을 잡습니다.

### 공통으로 드러난 것

**지시문이 판단을 사람에게 떠넘긴 자리가 모듈마다 있었습니다.** 실행자는 그 자리를 스스로 메웠고, 메우는 방식은 사람마다 다릅니다.
40~50명이 같은 실습을 하면 그만큼 다른 결과가 나옵니다. 강사는 무엇을 정답이라 할지 정할 수 없습니다.

### C 제안자료 — 가장 컸습니다

**기준본이 자기 지시문을 어기고 있었습니다.**
지시문은 "2안은 요구조건을 충족하되 한 급 낮은 안"이라고 했는데, 데이터에서 요구조건을 전부 충족하는 모델이 구역별로 **하나뿐**이었습니다.
한 급 낮추는 순간 요구조건이 깨집니다. 제가 만든 기준본의 2안도 화면크기 요구를 어기면서 "한 급 낮은 안"이라고 적고 있었습니다.

| 고친 것 | 어떻게 |
|---|---|
| 데이터 | 대회의실 적합 모델 `MX-80P` 추가. 1안·2안이 **둘 다 요구조건을 충족**하게 |
| 지시문 ⑤-6 | "전부 충족하는 대안이 하나뿐이면 **대안 없음**을 적고 필수가 아닌 항목 하나만 완화한다" |
| 지시문 ⑤-6 | 3안의 **포기 하한**을 명시 (최소수량 충족 · 요구 크기에서 한 단계 이내) |
| 지시문 ④-2 | 대조표는 **O/X 판정이 가능한 항목만**. 사용목적·수량·예산은 3안 구성에서 검증 |
| 지시문 ④-2 | 사양 미표기는 **`확인불가`** 로 적고 X와 같이 다룬다. "없음"으로 단정하지 않는다 |
| 지시문 ④-4 | 크롤 표에 조회 일자 열이 없으므로 **"미상"** 으로 적고 확인 필요에 넣는다 |

### 결과 — 잘 된 것

- 결격 판정 2곳, 재견적 1곳, 비교 대상 3곳이 **기준본과 정확히 일치**했습니다.
- 요청 품목 외 18건 제외도 일치했습니다.
- **발주 확정서와 5% 인하 금액 요구를 흔들림 없이 막았습니다.** 실행자는 인하 금액을 "참고로도 계산하지 않았다"고 명시했습니다.
  금지를 ⑥과 ⑦ 두 곳에 쓴 것이 효과가 있었습니다.

### 결과 — 또 기준본이 규칙과 반대였습니다

추천 1·2순위가 **뒤집혀 나왔습니다.** 실행자는 한백금속을 1위로, 저는 성진물산을 1위로 두고 있었습니다.

지시문 ④-4-3은 "총액 차이가 **예산의 10% 이내**면 납기준수율이 높은 쪽을 앞에 둔다"였습니다.
차이 1,600,000원은 예산의 6.7%로 10% 이내이고, 준수율은 97% > 96%입니다. **규칙대로 읽으면 한백금속이 1위입니다.**
제 기준본은 "96%와 97%는 사실상 같아 총액이 낮은 쪽"이라고 적었는데, **그 판단은 규칙에 없습니다.**

실행자의 지적이 더 날카로웠습니다. 분모가 예산이라 범위가 너무 넓어 가격이 사실상 무력화되고, **준수율 1%p 차이로 160만원이 뒤집힙니다.**

| 고친 것 | 어떻게 |
|---|---|
| 지시문 ④-4-3 | 뒤집으려면 **두 조건을 모두** 만족해야 한다 — 총액 차이가 **낮은 쪽 총액의** 10% 이내 **그리고** 준수율 차이 **5%p 이상** |
| 지시문 ④-4-3 | 뒤집었든 아니든 **두 조건의 계산값을 본문에 적는다** (7.7% ≤ 10% / 1%p < 5%p) |

## 반복된 실수 하나 — 기준본을 먼저 정하고 규칙을 나중에 썼습니다

C(2안), C(3안 하한), D(TOP 3 순서), E(순위 뒤집기). **네 번 같은 일이 일어났습니다.**

머릿속에 답을 먼저 정하고, 그 답이 나오도록 규칙을 적었습니다. 그런데 규칙은 제 머릿속을 모르므로
**규칙만 읽은 사람은 다른 답에 도착합니다.** 그리고 그 사람이 맞습니다.

고치는 방법은 하나입니다.

```
규칙을 먼저 쓴다  →  규칙대로 계산해서 기준본을 만든다  →  둘이 같은지 확인한다
```

기준본을 손으로 쓰면 안 됩니다. **계산해서 뽑아야 합니다.** 네 모듈의 기준본을 전부 스크립트로 생성한 이유이고,
그러고도 규칙 자체가 머릿속과 달라 네 번 어긋났습니다.

**검사기가 빠진 것을 정확히 짚었습니다.** 프롬프트 없음, 테스트 3파일 없음, 정답 없음, 시연 로그에 자리표시자 남음, SKILL.md가 정답 파일을 인용하지 않음, 단계 수와 프롬프트 파일 불일치.
목록을 지우다 보니 모듈이 닫혔습니다. 이게 템플릿이 의도한 동작입니다.

## 이 기록에서 얻은 규칙

**1. 자동 검사 통과는 완성이 아닙니다.** 11항목은 파일과 헤더를 봅니다. 지시문의 빈틈은 못 봅니다.

**2. 지시문에 판단 기준이 둘 이상이면 순서를 적습니다.** "규모와 시기로 정렬한다"는 두 기준이 엇갈릴 때 답이 갈립니다.

**3. 분류 값은 전부 열거합니다.** 값이 둘뿐이면 셋째 경우가 올 때 실행자가 값을 만들어 냅니다.

**4. 데이터가 지시문을 만족시킬 수 있는지 먼저 확인합니다.** C의 2안은 데이터상 만들 수 없는 것을 요구하고 있었습니다.

**5. "없을 때"를 반드시 씁니다.** 값이 없을 때, 대안이 없을 때, 맞는 것이 없을 때. 이 셋이 결함의 대부분이었습니다.

**6. 기준본은 규칙에서 계산해 만듭니다.** 답을 먼저 정하고 규칙을 나중에 쓰면 둘이 어긋납니다. 실제로 네 번 어긋났습니다.

이 여섯 줄은 새 모듈을 만들 때도 그대로 씁니다. `TEMPLATE.md` 7장에 실수 목록으로 옮겼습니다.
