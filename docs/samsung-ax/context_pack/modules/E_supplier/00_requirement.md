# 업무 상황

제조사 구매 담당자다. 자재 한 품목을 발주해야 하는데 공급사 여섯 곳에서 견적을 받았다.
단가만 보면 어디가 싼지 금방 알 수 있지만, **최소주문수량·납기·규격·견적 유효기간**을 하나씩 대조해야 실제로 발주가 가능한지 알 수 있다.
게다가 과거 납기를 잘 지켰는지, 품질 이슈가 있었는지는 견적서에 안 적혀 있다. 매번 이력 파일을 따로 열어 맞춰 본다.

한 품목에 30분이 걸리고, 월 20품목이면 하루가 사라진다.

# 케이스 — 왜 이 업무인가

1. **결격 판정이 먼저 와야 하는 일입니다.** 싼 순으로 줄을 세우고 나면 그중 절반이 발주 불가인 경우가 흔합니다.
2. **가격 밖의 기준이 결과를 바꿉니다.** 납기준수율과 품질이슈는 별도 파일에 있고, 이걸 붙여야 판단이 됩니다.
3. **확정은 사람이 합니다.** 발주서와 단가 협상은 구매 담당자와 결재선의 일입니다.

# Input / 처리 / Output

- 견적 `quotes.csv` 8열 24행 (6공급사 × 4품목)
- 공급사 이력 `supplier_history.csv` 4열 6행
- 구매 요청 `purchase_request.md` 5항목
- 처리: 결격 판정 → 비교 → 추천 → 확인 필요
- 출력: `compare_E.html` 6절
