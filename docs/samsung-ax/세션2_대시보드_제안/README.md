## 확인 부탁드리는 것

| # | 질문 | 왜 필요한가 |
|---|---|---|
| ① | **한 영업기회에 매출이 여러 번** 잡히는 게 정상입니까 | 지금은 1건 = 1행으로 만들었고, 지시문은 중복을 만나면 멈추고 물어보게 되어 있습니다. 정상이면 합산하도록 한 줄만 바꿉니다 |
| ② | **파트명과 주문유형이 1:1**이 맞습니까 | 지금 데이터는 직판파트가 직판주문만, 경로파트가 유통주문만 가지고 있습니다. 실제로 섞인다면 필터 조합이 달라집니다 |
| ③ | **직판일 때 판매처 주소**에 무엇이 들어갑니까 | 지금은 `—`로 비워 두었습니다. 수요처 주소가 들어간다면 지역 축을 하나 더 쓸 수 있습니다 |
| ④ | **실제 모델명**을 주실 수 있습니까 | 가상 모델명을 썼습니다. 설명대로 조회 가능한 실제 모델명이면 **세션3에서 사양을 찾아보는 흐름과 이어집니다** |
| ⑤ | **단가(공급가) 열**을 넣을 수 있습니까 | 지금 헤더로는 `단가 × 수량 = 금액` 검산을 할 수 없습니다. **아래를 꼭 봐 주십시오** |
| ⑥ | 실제 데이터의 **수요처 수**는 몇 곳 규모입니까 | 15곳이 넘으면 표가 길어져 대시보드가 깨집니다. 상위 N + 기타 기준을 미리 정하겠습니다 |
| ⑦ | 집계 축 셋과 **필터 셋**이 맞습니까 | 축은 품목구분·주문유형·수요처명, 필터는 기간·조직·주문유형입니다. 필터의 '조직'을 파트명으로 뒀는데 그룹명이 맞는지도 봐 주십시오 |
| ⑧ | `매출일자` 외에 **수주일자·예상 매출일**이 있습니까 | 선행영업과 트렌드를 기간으로 구분하려면 매출일자만으로는 부족할 수 있습니다 |

### ⑤번을 따로 적는 이유 — 단가 열이 없으면 검산 실습이 사라집니다

기존 데이터 분석 실습의 중심은 **`공급가 × 판매수량 = 판매금액`을 전 행에서 맞춰 보고, 어긋나면 멈추는 것**이었습니다.
"AI가 낸 숫자를 그대로 믿지 않는다"를 손으로 겪게 하는 장치였는데, 새 헤더에는 단가가 없어 그대로는 성립하지 않습니다.

그래서 **소계 파일(`매출데이터_소계.csv`)을 따로 내려 주고, 원본에서 다시 더해 대조하게** 바꿨습니다.
검산 자체는 살아 있지만 한 단계 약합니다. 행 단위로 틀린 것은 못 잡고 합계만 맞춰 보기 때문입니다.

- **단가 열을 주실 수 있으면** 원래 실습을 되살리고 소계 대조와 둘 다 돌리겠습니다.
- **어려우시면** 지금 안(소계 대조)으로 갑니다. 이 경우 화면에 "단가 열이 없어 검산식을 세울 수 없음"을 명시하고 넘어갑니다.

## 필터

화면 맨 위에 필터 세 개가 있습니다. **기간 · 조직(파트명) · 주문유형**입니다. 바꾸면 아래 숫자가 전부 다시 계산됩니다.

셋으로 끊은 이유는 한 줄에 들어가야 하기 때문입니다. 품목구분과 수요처명은 표에 이미 다 보이니 필터로 또 두지 않았습니다.

여기에 교육 소재가 네 개 들어 있습니다.

| 걸리는 것 | 참가자가 배우는 것 |
|---|---|
| 필터를 걸면 "지금 보고 있는 것" 줄이 바뀝니다 (예: 2026-Q2 · 직판1파트 · 직판주문 → 54건 중 13건 · 전체 금액의 25.8%) | **필터를 거는 순간 사람들은 전체를 잊습니다.** 그래서 전체 대비 위치를 항상 같이 적습니다 |
| 품목이 빠져도 남은 품목의 색은 그대로입니다 | **색은 항목을 따라가지 순위를 따라가지 않습니다.** 어제 파란색이던 게 오늘 주황색이면 화면을 못 믿게 됩니다 |
| 분기 비교 표만 기간 필터를 빼고 계산합니다 | 기간을 2분기로 걸어 둔 채 분기를 견주면 **비교할 상대가 사라집니다.** 예외를 둘 때는 화면에 적어야 합니다 |
| 조건을 다 걸어 0건이 되면 0을 그리지 않습니다 | **0원짜리 막대는 "실적 0"처럼 보입니다.** 비워 두고 어느 필터를 풀면 되는지 적습니다 |

걸어 둔 조건은 주소창에 남습니다. 링크를 복사해 보내면 상대도 같은 화면을 봅니다.

## 이 데이터를 일부러 이렇게 만든 이유

**정상 파일에는 틀린 행을 넣지 않았습니다.** 대시보드는 "무엇으로 나눠서 볼 것인가"를 배우는 자리라 오류 찾기가 끼면 초점이 흐려집니다.
대신 **함정은 별도 파일**(`매출데이터_함정.csv`)로 분리해서, 0번 점검을 보여 줄 때만 바꿔 올립니다.

| | 심어 둔 것 | 에이전트가 해야 할 행동 |
|---|---|---|
| 정상 파일 | 단가 열이 없음 | 소계 파일과 대조하고, 검산식이 없다는 사실을 화면에 적는다 |
| 정상 파일 | 3분기가 9월까지만 | 덜 찬 분기를 비교에서 뺀다 |
| 함정 파일 | 매출일자 하나가 `2026/02/01` | 형식이 섞였다고 보고하고 **어느 쪽으로 읽을지 물어본다** |
| 함정 파일 | 같은 코드에 `대성건설` / `대성 건설` | 코드를 정본으로 쓰고 표기 차이를 보고한다 |
| 함정 파일 | 영업기회 번호 중복 1건 | 지우지 않고 **몇 건인지 보고하고 물어본다** |
| 함정 파일 | 매출금액 음수 · 매출수량 0 | 표로 보여 준다 |
| 함정 파일 | 소계 파일과 합계 불일치 | **0번에서 멈춘다.** 멈추는 게 성공 행동이다 |

## 세션2 ↔ 세션3 연결

말씀드린 (가)안 — 세션2에서 고른 수요처를 세션3으로 넘기는 방식 — 으로 **만들어 두었습니다.** (나)를 원하시면 되돌리겠습니다.

- 세션2가 넘기는 것은 **"누구를 고를 것인가"까지**입니다(`대상수요처_세션3인계.md`).
- 매출 헤더에는 요구조건 · 설치 환경 · 경쟁 상황이 없으므로, 세션3의 `고객요구조건.md`는 **영업담당이 현장에서 받아 온 것**으로 따로 둡니다. 파일 머리에 "세션2에서 넘어온 수요처"라고 적어 두었습니다.
- 고른 기준이 **금액 1위(대성건설)가 아니라 움직인 곳(미래로병원)**이라는 판단 자체가 세션2 후반의 결과물입니다.
- **모델명이 실제 모델명이 되면**(위 ④) 세션3에서 사양을 찾아보는 흐름이 더 자연스럽게 이어집니다.
