# B2C 판 — 에이전트 설계 (B2B 과정과 같은 포맷)

> B2B 과정(세션0 오프닝 → 세션1 센싱 → 세션2 대시보드·분석 → 세션3 제안)의 **틀은 그대로** 두고, 내용을 B2C 실무진의 한 사이클로 바꾼 설계안입니다.
> 실무진 기준 한 사이클 = **센싱 → 숫자 확인 → 제안(무엇을 더 팔고, 무엇을 챙길지)**. 세션3의 제안이 사이클의 끝입니다.
> **모든 데이터는 가상**입니다. 거래선 · 타사 · 모델명 · 가격 · 실적에 실제 값을 쓰지 않습니다.
> `[확인 필요]`는 미팅 메모에서 해석한 부분입니다. 삼성 측 확인 후 확정합니다.

## 1. 세션1 — 센싱

미팅에서 나온 핵심: **뉴스보다 내부 센싱의 비중이 크다.** 거래선에서 수기로 받아오는 것, 판매 추이, 지역 담당이 가져오는 소식, 직접 미팅 메모 — 이걸 워드에 러프하게 쓰고 정제를 반복한다. 그래서 세션1은 **뉴스 + 내부 메모 정제**를 같이 다룹니다.

### 1-1 · 경로 단위 센싱 Agent

| 블록 | 내용 |
|---|---|
| ① 역할 | B2C 유통 채널을 맡은 **거래선 동향 담당**. 기사보다 거래선이 보낸 메모 한 줄을 먼저 본다. 경계하는 것: 추측을 사실처럼 정리하기 |
| ② 업무 범위 | 단계 A **메모 정제** — 수기 메모 사진 · 러프한 워드 → 표 / 단계 B **뉴스 수집** — 거래선명 × 신호어 / 단계 C **주간 동향 보고** |
| ③ 입력 검사 | 거래선 목록 없으면 요청 · 기준 주차 질문 · 메모에 개인 연락처 있으면 가명화 요청 |
| ④ 처리 | 메모 → `거래선 · 날짜 · 내용 · 출처(메모/뉴스/미팅) · 확인 여부` 표 → 뉴스와 대조 → 거래선별 Key Signal(근거 행) → 판정(기회 / 주의 / 확인 필요) |
| ⑤ 출력 | `경로동향.html` — 거래선별 카드, 이번 주 바뀐 것, 확인 필요 목록 |
| ⑥ 중단 · 보안 | 거래선 계약 조건 · 마진이 메모에 있으면 멈춤. 뉴스 본문 전재 금지 |
| ⑦ 성공 기준 | 메모와 뉴스가 출처 열로 구분되는가 · 확인 안 된 것이 "확인 필요"로 남았는가 |

**데이터 (가상)**: `거래선목록.xlsx`(거래선 · 채널유형[양판점/할인점/온라인/전문점] · 담당 · 지역) · `거래선메모.jpg` 2장 + `주간메모_러프.docx` · `경로뉴스.xlsx`(4열: 채널 · 헤드라인 · url · 키워드)

**실습 체험 A — 수기 메모 사진을 찍어 엑셀로 만든다.** 손글씨 메모 사진을 올리면 표로 정리되는 것을 직접 본다.

### 1-2 · 품목 단위 센싱 Agent

| 블록 | 내용 |
|---|---|
| ① 역할 | **품목 담당**. 품목 아래 **제품군 단위**(예: 스마트폰 > 프리미엄 라인)로 본다 — 타사 제품도 그 단위로 비교한다 |
| ② 업무 범위 | 단계 A 품목 × 제품군 × 신호어(출시 · 가격인하 · 프로모션 · 품절) 키워드 / 단계 B 뉴스 추출 / 단계 C 품목 동향 보고 |
| ③ 입력 검사 | 담당 품목을 반드시 질문 · 제품군 매핑표 없으면 요청 |
| ④ 처리 | 기사 → `품목 · 제품군 · 당사/경쟁 · 사건 · 가격변동` → 제품군별로 당사 vs 경쟁 나란히 → 가격 · 프로모션 신호 표시 |
| ⑤ 출력 | `품목동향.html` — 제품군별 당사 · 경쟁 비교 카드, 경쟁 가격 · 프로모션 신호 |
| ⑥ 중단 · 보안 | 내부 출시 일정 · 미발표 가격이 섞이면 멈춤 |
| ⑦ 성공 기준 | 비교가 **제품군 단위**인가(품목 전체나 모델 하나가 아니라) · 경쟁 가격은 출처 · 조회일이 있는가 |

**데이터 (가상)**: `제품군매핑.xlsx`(품목 · 제품군 · 당사 라인명 · 경쟁 라인명) · `품목뉴스.xlsx`(4열)

**실습 체험 B — 인사이트를 넣어 고쳐 보기.** 결과 보고서를 보고 "저게 다야?"에서 멈추지 않고, 내가 아는 사실 한 줄을 더해 다시 받는다. 모르던 뉴스를 끌고 오는 것도 이때 본다.

## 2. 세션2 — 대시보드 → 인사이트 (한 대화)

미팅에서 나온 핵심: **"이런 엑셀이 자동화된다"보다 "대시보드 숫자가 자동으로 앉혀진다"가 와닿는다.** 그리고 **나한테 미리 알려준다.**

### 2-1 · 판매 대시보드 Agent

| 블록 | 내용 |
|---|---|
| ① 역할 | B2C 판매 실적을 매주 보는 **보직장 · 품목 담당용 대시보드 담당** |
| ③ 입력 검사 | 판매 데이터 + 소계(검산용) · 기간에 25년 1~12월 전체가 있는지 |
| ④ 처리 | 0번 숫자 확인(소계 대조) → **25년 연간 매출** · 월별 · 거래선별 · 품목별 · **제품군별 당사 vs 경쟁 비교** → 같은 날짜까지 자른 전년 · 전월 비교 |
| ⑤ 출력 | `판매대시보드.html` — 조건 칸(거래선 · 품목 · 제품군 · 기간), 누르면 바뀌는 표 |
| ⑦ 성공 기준 | 25년 연간 합계가 소계와 일치 · 제품군 비교가 같은 기간끼리 |

**데이터 (가상, 기존 16열 포맷 유지 + B2C 열)**: `판매데이터.xlsx` — 기존 열에서 `판매처 → 거래선`, `수요처 → 판매 채널/지역`으로 의미만 바꾸고, `제품군` · `당사/경쟁` · `판매가` 열 추가 (2023-01 ~ 2026-09, 3개년). 경쟁 데이터는 **시장 판매량 추정치**로 가정 `[확인 필요: 실무에서 경쟁 수치를 어디서 받는지]`

### 2-2 · 인사이트 + 미리 알림 (같은 대화에 이어서)

| 블록 | 내용 |
|---|---|
| ④ 처리 | 대시보드 숫자에 **인사이트 3개**(금액 큰 것 · 비율 큰 것 · 아무도 안 보는 것) → 이 데이터로 알 수 없는 것 3개 → **알림 조건** 정의(예: 제품군 주간 점유 3%p 하락, 경쟁 가격 10% 이상 인하) |
| ⑤ 출력 | `주간리뷰.md` + 맨 아래 인계본 `제안대상.md`(품목 · 제품군 · 근거 숫자 · 고른 이유) |
| 미리 알림 | 알림 조건을 예약 작업(Gemini · ChatGPT 예약)으로 거는 실습 — 세션1 뉴스수집 예약과 같은 방식 |

## 3. 세션3 — 제안 2개 (사이클의 끝)

미팅 메모의 순서: **제안 ① 어떤 품목을 많이 팔아라 → ② 챙겨보셔야 할 것(프로모션 기획 / 가격대응).** 우선순위는 **프로모션 > 가격대응**이고, 가격대응은 **5% · 10%** 두 단계로 본다 `[확인 필요: 5·10이 인하율인지]`.

### 제안 Agent

| 블록 | 내용 |
|---|---|
| ③ 입력 검사 | `제안대상.md`(세션2 인계본) 필수 — 없으면 물어서 채움 · **목표치** 반드시 질문(시뮬레이션의 기준) |
| ④ 처리 단계 ① | **더 팔 품목 · 제품군** — 최근 3개월 비중, 3개년 전년비 증감 추이로 순위 |
| ④ 처리 단계 ② | **판매량 시뮬레이션** — 최근 3개월 비중 × 3개년 추이로 기준 전망 → 목표 대비 갭 |
| ④ 처리 단계 ③ | **챙길 것** — 프로모션 기획서(대상 제품군 · 기간 · 채널 · 기대 판매량) → 그래도 갭이 남으면 가격대응 5% / 10% 시나리오별 판매량 · 매출 |
| ⑤ 출력 | `제안서.html` — 1 더 팔 것 / 2 시뮬레이션(기준 · 목표 · 갭) / 3 프로모션 기획서 / 4 가격대응 5% · 10% 비교 / 5 사람이 정할 것 |
| ⑥ 중단 · 보안 | 확정 가격 · 확정 판촉비 · 거래선별 조건 확정 요구는 거절 — 사람이 결정 |
| ⑦ 성공 기준 | 시뮬레이션 근거(3개월 비중 · 3개년 추이)가 표로 보이는가 · 프로모션이 가격대응보다 먼저인가 · 5% · 10% 둘 다 있는가 |

## 4. 실습 체험 정리 (미팅에서 나온 것)

| 체험 | 세션 | 참가자가 느끼는 것 |
|---|---|---|
| A 수기 메모 사진 → 엑셀 | 1-1 | 매주 손으로 옮기던 일이 사라진다 |
| B 인사이트를 넣어 고치기 · 모르던 뉴스 끌고 오기 | 1-2 · 2-2 | "보고서가 저게 다야?"에서 한 번 더 간다 |
| 대시보드 숫자가 자동으로 앉혀진다 | 2-1 | 엑셀 자동화보다 와닿는 지점 |
| 나한테 미리 알려준다 | 2-2 | 알림 조건 예약 |
| 프로모션 기획서 · 판매량 시뮬레이션 | 3 | 한 사이클의 끝 |

**주의 (미팅 메모)**: 거래선 주간 동향처럼 내부 정보가 많은 일은 실제 자료로 AI 교육을 하기 어렵다 → **가상 메모 · 가상 사진**으로 실습하고, 실제 업무 파일은 올리지 않는다.

## 5. 다음 단계 (확정되면 만들 것)

1. `[확인 필요]` 세 가지 확정 — 경쟁 수치 출처 · 5/10의 의미 · 품목 범위(스마트폰 · TV · 가전 중 어디까지)
2. 가상 데이터 생성 — 거래선 6 · 품목 3 · 제품군 9 · 3개년 판매 데이터 + 소계, 수기 메모 사진 2장
3. 세션별 붙여넣을 프롬프트(7블록) · 실습지시문 · 기준본 · 테스트 3종
4. 덱 B2C판 · 워크북 · 강사 가이드 (기존 생성기 재사용)
