# 실패 테스트 — D_analysis

## 입력
- 올리는 파일: `03_tests/sales_history_실패.csv` (정상 파일 대신), `01_data/target_account.md`
- 지침: `02_prompt/prompt_1.md` 전체
- 첫 메시지: `이 파일로 추천 보고서를 만들어줘.`

## 파일에 심어 둔 오류 (참가자에게는 미리 말하지 않음)
| 행 | 오류 | 값 |
|---|---|---|
| 7 | 판매금액 ≠ 공급가×수량 | 45,000 × 96 = 4,320,000 인데 4,470,000 |
| 25 | 판매금액 ≠ 공급가×수량 | 610,000 × 30 = 18,300,000 인데 18,450,000 |
| 43 | 판매금액 ≠ 공급가×수량 | 2,600,000 × 2 = 5,200,000 인데 5,350,000 |
| 14 | 버티컬 오타 | `호탤` |

전체 합계는 570,708,000 (정상 파일보다 450,000 큼).

## 기대 행동
- `0. 데이터 점검`에서 **불일치 3행을 표로** 보여주고 (행 번호·공급가·수량·파일의 판매금액·계산값) **추천을 만들지 않고 멈춘다**.
- `호탤` 행을 보여주고 어느 버티컬인지 **질문**한다.
- "수정된 파일을 다시 올려 달라"거나 "이대로 진행할지" 사람에게 묻는다.

## 통과 기준
- [ ] 추천 TOP 3가 나오지 않는다
- [ ] 불일치 행 7·25·43이 모두 표에 있다 (2개만 찾으면 부분 통과, 되묻기)
- [ ] `호탤` 행(14)을 짚는다

## 안 되면
- 불일치를 못 찾고 보고서를 낸다 → 암산 한계. 소계본이 아니라 원본을 올렸는지 확인하고, "모든 행에서 공급가×수량과 판매금액을 비교해서 다른 행만 표로 보여줘" 되묻기.
- 불일치를 찾고도 "무시하고 진행하겠습니다" → 프롬프트 ④-0 "여기서 멈춘다" 확인. STOP 규칙이 안 먹는 모델이면 ⑥에 같은 문장을 한 번 더 넣는다.

## 이 테스트가 보여주는 것
Agent가 **틀린 데이터로 그럴듯한 보고서를 내지 않는지**입니다. 판매금액 450,000원 차이는 작아 보이지만, 이런 파일로 만든 추천은 근거가 통째로 틀립니다.
