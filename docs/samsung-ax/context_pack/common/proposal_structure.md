# 제안서 공통 구조 (삼성 확정)

9/7 사전 모임 슬라이드에서 두 팀 공통으로 확정된 순서입니다. 팀이 달라도 이 순서는 바뀌지 않습니다.

```
1. 회사소개
2. 제안내용
3. 제품소개
4. 유지보수
```

## 섹션별 작성 규칙

| 섹션 | 들어가는 것 | AI 작성 | 사람 확인 | 근거 파일 |
|---|---|---|---|---|
| 1. 회사소개 | 사업 영역, 레퍼런스, 담당 조직 | 초안 | 레퍼런스 사용 가능 여부 | `company_intro.md` (공통) |
| 2. 제안내용 | 고객 과제 → 해결 방향 → 기대 효과 | 초안 | 과제 인식이 맞는지 | `customer_profile.md` (② 인계물) |
| 3. 제품소개 | 품목, 사양, 구성 | 초안 | 사양 정확성 | `product_catalog.csv` (팀별) |
| 4. 유지보수 | 서비스 범위, 대응 체계 | 초안 | **가격·납기·SLA 확정** | `service_terms.md` (팀별) |

## 제안서 Agent의 STOP 조건

즉시 중단하고 사람에게 넘깁니다.

- 가격, 할인율, 납기를 **확정 문구로** 쓰라는 요청
- 계약 조건·SLA 수치를 자료 없이 채우라는 요청
- 고객 담당자 실명·연락처가 입력에 포함된 경우
- `customer_profile.md` 없이 제안내용을 쓰라는 요청 (고객 과제 추정 금지)

질문 후 계속합니다.

- 제품 정보 파일이 없을 때 → 어떤 품목인지 질문
- 독자(구매팀장 / 실무 담당 / 파트너)가 지정되지 않았을 때
- 제안 규모·기간이 명시되지 않았을 때

## 출력 형식

```
[제안서 초안]
1. 회사소개 …
2. 제안내용 …
3. 제품소개 …
4. 유지보수 …

[근거표]
| 문장 | 근거 파일 | 위치 |

[확인 필요]
- 가격·납기: 영업 담당 확정 필요
- (자료 없어 비운 항목들)

[승인] 팀장 확인 후 대외 발송
```
