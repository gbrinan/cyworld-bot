# 업무 상황 (삼성 양식 1-1 원문)

B2B 영업 담당자로서 현재 관리하고 있거나 장기적으로 영업 대상이 될 수 있는 주요 수요처를 특정하고, 해당 산업과 수요처에 대해 최근 언론 기사, 업계 미디어, 기업 발표자료, 시장 조사 자료를 찾아 최근 어떤 변화가 발생했는지, 고객의 투자·구매 수요가 무엇인지, 어떠한 사업기회가 예상되는지를 파악하고, 최종적으로 영업 담당자가 공략 가능한 영업기회를 분석하고 접근 방향까지 제안해야 함.

# 케이스 — 상장 건설사 신규 개척

이 모듈은 **상장 건설사**를 대상으로 합니다. 이유가 셋입니다.

1. **신호가 공개돼 있습니다.** 상장사는 수주를 공시합니다. `단일판매·공급계약체결` 공시에는 현장·계약금액·**공사기간**이 들어 있습니다.
2. **날짜가 박혀 있어 역산이 됩니다.** 준공 예정일에서 거꾸로 세면 디스플레이 사양이 확정되는 시점이 나옵니다. "언제 갈 것인가"에 답할 수 있습니다.
3. **건설사는 수요처이자 통로입니다.** 건설사가 짓는 현장이 곧 상업시설·호텔·병원·오피스입니다. 한 곳을 뚫으면 현장이 따라옵니다.

**Key Signal을 "무슨 일이 있었나"에서 멈추면 안 됩니다.** "그래서 언제 발주가 뜨는가"까지 가야 Action Plan이 나옵니다.

# 일 분해 (task_decomposition.md 순서)

| # | 내가 하는 일 | 꼬리표 | 어디로 |
|---|---|---|---|
| 0 | 어떤 회사를 볼지 고른다 (상장·주력공종·지역으로 후보를 추림) | ✍️ | **단계 1 앞** |
| 1 | 매주 담당 건설사·산업 뉴스를 검색한다 | ⚙️ | **단계 1** (주 1회 반복) |
| 2 | 품목·헤드라인·url·키워드로 정리한다 | ⚙️ | 단계 1 |
| 3 | 새로 뜬 회사가 어떤 회사인지 조사한다 | ✍️ | **단계 2** |
| 4 | 모르는 것은 선배·담당자에게 물어 채운다 | ✍️ | 단계 2 (질문이 기능) |
| 5 | 기사에서 무슨 변화가 있었는지 뽑는다 | ✍️ | **단계 3** Key Signal |
| 6 | 그 변화가 어떤 구매 수요인지 해석한다 | ✍️ | 단계 3 Needs |
| 7 | 언제 발주가 뜰지 역산한다 | ✍️ | 단계 3 Sales Opportunity |
| 8 | 갈래를 나눠 본다 (빠를 때 / 늦을 때, 직접 / 시공사 경유) | ✍️ | 단계 3 시나리오 |
| 9 | 누구에게 무엇을 들고 갈지 정한다 | ✍️ | 단계 3 Recommended Action |
| 10 | 연락하고 미팅을 잡는다 | 🔒 | **경계** |
| 11 | 견적·가격을 제시한다 | 🔒 | 경계 |

**0~9번 사이에 🔒이 하나도 없습니다. 그래서 에이전트는 하나입니다.**
성격이 다른 세 덩어리(수집 / 되묻기 / 판단)라 **한 에이전트 안의 단계 셋**으로 둡니다. 10·11번이 🔒이라 거기서 잘립니다.
🔒이 없는데 에이전트를 늘리면 관리할 것만 늘어납니다. `agent_and_skill_split.md` 2장 참고.

# 단계 2가 특별한 이유 — 묻는 것이 기능인 단계

다른 모듈에서 "질문한다"는 **경계 테스트의 통과 조건**이었습니다. 입력이 빠지면 지어내지 말고 물으라는 뜻이었습니다.
단계 2는 다릅니다. **묻는 것이 이 단계의 일**입니다.

| | 다른 모듈 | 단계 2 |
|---|---|---|
| 질문 | 입력이 빠졌을 때만 | 처음부터 항목을 하나씩 |
| 사용자가 다 알면 | 바로 진행 | 붙여넣으면 **빠진 것만** 묻는다 |
| 모르는 항목 | 요청하고 중단 | 비워 두고 "확인 필요"로 남기고 계속 |

신규 고객 조사는 원래 이렇게 합니다. 아는 것부터 적고 모르는 것을 표시해 두고, 채워지는 대로 갱신합니다.
