1. `01_data/naver_news_dummy.json` (30건, API 응답 형식)

## 붙여넣은 프롬프트
`02_prompt/prompt_2_추출.md`의 ✂ 사이. 스킬이 열려 있으면 `07_skill/SKILL.md` 등록.
클릭 경로: 사이드바 [에이전트] → [만들기] → [지침] 붙여넣기 → [파일 업로드] 4개 → 저장.

## 시연 앞 2분 — JSON을 열어 보여줍니다
`naver_news_dummy.json`을 메모장으로 열어 `items[]` 구조를 보여주고 말합니다.
**"사내에 API 연동은 없습니다. 이건 연동이 됐다고 가정한 모양입니다. 연동이 생기면 이 자리만 바뀌고 지침은 그대로입니다."**

## 첫 메시지
```
파일 4개를 올렸어. 담당 권역은 부산 해운대야. 단계 1 검색 키워드부터 만들어줘.
```

## 첫 응답에서 확인할 것
- [ ] 조합 결과와 함께 **뺀 조합의 이유**가 나오는가
- [ ] `해운대` 단독처럼 너무 넓은 조합을 **안 만들었는가**
- [ ] 카페 개점을 개별 검색어로 넣지 않고 **상가 개점으로 묶었는가**

## 안 나오면 되묻는 문장
```
만들지 않은 조합과 그 이유도 표로 적어줘.
권역 단독이나 상태 단독 검색어를 왜 안 쓰는지 한 줄씩 적어줘.
```

## 두 번째 메시지 (단계 2·3)
```
이제 기회를 추출해줘. 규모 하한은 객실 50실 또는 연면적 3,000㎡야.
```
이어서 `02_prompt/prompt_3_보고서.md`의 ✂ 사이를 보냅니다.

확인할 것
- [ ] **타 권역 12건 제외**가 보고되는가
- [ ] 기회가 **3건**이고 카페·의원·학원이 목록에 없는가
- [ ] 3순위에 **"해당 파트너 없음"** 이 나오는가

## 참가자에게 짚어줄 한 문장
"카페 세 곳은 기회 목록에 없지만 요약에는 남아 있습니다. **버리지도 올리지도 않는 자리**가 이 Agent의 핵심입니다."

## 세 번째 장면 — 실패 테스트 (2분)
`03_tests/partner_info_실패.csv`로 바꿔 올리고 같은 요청을 보냅니다. **계약단가·마진율을 짚고 멈추는지** 확인합니다.
멈추면 말합니다. **"파트너 단가는 파트너의 영업 비밀입니다. 한 번 올라가면 되돌릴 수 없습니다."**
