# B2B팀 통합 시나리오 — 수요처 AX전략 기반 NBM Lead 발굴

> 출처: 9/7 사전 모임 슬라이드 STEP 3의 B2B팀 후보 예시
> 사전과제 목적대로 **영업 여정(Sensing → Action → Analysis)을 1개 시나리오로 통합**했습니다.
> 확정본은 9/8 전달 자료(팀별 Workflow 리스트, AX T/F 과제 리스트) 반영 후 갱신합니다.

---

## 상황

당신은 B2B팀에서 유통·서비스 업종 대기업을 담당합니다.
분기 목표 중 하나가 **휴면·신규 고객에서 NBM(New Business Model) Lead를 발굴**하는 것입니다.

지금은 이렇게 일합니다.

1. 아침마다 업종 뉴스를 훑어보며 담당 고객사 소식을 찾습니다. 놓치는 날이 많습니다.
2. 신호를 찾으면 과거 거래 이력을 열어보고 제안 여부를 판단합니다.
3. 제안하기로 하면 매번 제안서를 처음부터 씁니다.
4. 월말에 파이프라인 현황을 정리해 보고합니다. 표지 합계와 상세가 안 맞아 다시 세는 일이 있습니다.

---

## 세 Agent가 이어지는 흐름

```
② Sensing   업종 뉴스 + 고객사 마스터
            → 어떤 고객에게 어떤 신호가 있는가, 무엇을 제안할까
            → customer_profile.md

③ Action    customer_profile.md + 제품 카탈로그 + 서비스 조건
            → 회사소개 → 제안내용 → 제품소개 → 유지보수
            → proposal_draft.md

④ Analysis  Lead/BO 파이프라인 + 월 요약
            → 단계별 현황, 전월 대비, 특이사항
            → report_draft.md
```

---

## 모듈별 실습 정의

### ② 시장·고객 분석 Agent (Sensing)

| 항목 | 내용 |
|---|---|
| 업무 상황 | 유통·서비스·공공 업종 뉴스에서 담당 고객사의 투자·조직 신호를 찾아 제안 우선순위를 만든다 |
| 입력 | `data/industry_news.csv` (48행), `data/target_accounts.csv` (15행) |
| 필수 컬럼 | 보도일, 업종, 고객사명, 신호유형, 관련품목군, 신뢰도 / 고객사코드, 거래상태, 최근거래품목군 |
| 기준일 | 2026-09-04, 분석 기간 최근 3개월 (2026-07-01 ~ 2026-09-03) |
| 관심 지표 | 신호 건수, 신뢰도, 거래 상태(신규/기존/휴면), 최근 거래 품목과의 차이 |
| 우선순위 기준 | ① 신뢰도 '높음' 신호 수 ② 휴면·신규 여부 ③ 최근 거래 품목과 다른 품목군 신호 |
| 출력 | `customer_profile.md` — 우선순위 표 + 상위 3건 상세 + 근거표 |
| 이 데이터의 함정 | **중복 기사가 있습니다.** 같은 고객사·같은 신호유형이 다른 매체·다른 날짜로 두 번 실립니다. 중복을 세면 우선순위가 틀립니다 |

### ③ 제안자료 작성 Agent (Action)

| 항목 | 내용 |
|---|---|
| 업무 상황 | ②에서 뽑은 1순위 고객에게 보낼 제안서 초안을 회사 표준 순서로 만든다 |
| 입력 | `handoff/customer_profile.md`(② 결과), `data/product_catalog.csv` (8행), `data/service_terms.md` |
| 독자 | 고객사 총무·구매 담당 팀장 |
| 제안 규모 | 사무동 1개 층 기준, 2026년 4분기 집행 검토 |
| 출력 | `proposal_draft.md` — 회사소개 / 제안내용 / 제품소개 / 유지보수 + 근거표 + 확인 필요 |
| 이 팀 특성 반영 | **HVAC 통합 제안**: SAC 단품이 아니라 SAC + 중앙 제어 + 유지보수를 묶습니다. **품목 확대**: 최근 거래 품목과 다른 품목군을 함께 제안합니다 |
| 이 데이터의 함정 | 카탈로그의 단가는 **참고 단가**입니다. 확정 가격으로 쓰면 안 됩니다 |

### ④ 데이터 분석 Agent (Analysis)

| 항목 | 내용 |
|---|---|
| 업무 상황 | 월말 파이프라인 현황을 단계별로 정리하고 전월 대비 증감과 특이사항을 보고한다 |
| 입력 | `data/lead_bo_pipeline.csv` (66행), `data/monthly_summary.csv`, `data/report_template.md` |
| 필수 컬럼 | LeadID, 고객사명, 담당경로, 품목군, 단계, 예상규모(백만원), 확률(%), 전환여부, 마감예정월 |
| 기준월 | 2026-09, 비교 2026-08 |
| 핵심 지표 | 단계별 건수·금액, 가중 파이프라인(금액×확률), 수주 전환율, 경로별·품목군별 분포 |
| 특이사항 기준 | 단계별 금액이 전월 대비 ±20% 이상 변동, 마감예정월이 지난 건, 확률 0%(실주) 누적 |
| 출력 | `report_draft.md` — 데이터 점검 / 요약 / 지표 현황 / 특이사항 / 근거표 |
| 이 데이터의 함정 | **표지(`monthly_summary.csv`)와 상세 합계를 대조해야 합니다.** 경계 테스트 파일에서는 일부러 어긋나 있습니다 |

## 완주 체크

```
□ ② customer_profile.md 저장 — 중복 기사를 걸렀는가
□ ③ proposal_draft.md 저장 — 가격을 확정 문구로 쓰지 않았는가
□ ④ report_draft.md 저장 — 합계 정합성을 먼저 확인했는가
□ 테스트 3종 로그 기록
□ 내 업무 전환 표 작성
```
