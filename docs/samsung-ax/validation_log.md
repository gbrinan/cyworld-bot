## 1회차 — 2026-09-12

네 모듈 모두 **결함이 나왔습니다.** 자동 검사 11항목을 통과한 상태였는데도 그렇습니다.
자동 검사는 "파일이 있고 헤더가 맞는가"를 보고, 블라인드 검증은 **"지시문만 보고 같은 답이 나오는가"** 를 봅니다. 둘은 다른 것을 잡습니다.

### 공통으로 드러난 것

**지시문이 판단을 사람에게 떠넘긴 자리가 모듈마다 있었습니다.** 실행자는 그 자리를 스스로 메웠고, 메우는 방식은 사람마다 다릅니다.
40~50명이 같은 실습을 하면 그만큼 다른 결과가 나옵니다. 강사는 무엇을 정답이라 할지 정할 수 없습니다.

### C 제안자료 — 가장 컸습니다

**기준본이 자기 지시문을 어기고 있었습니다.**
지시문은 "2안은 요구조건을 충족하되 한 급 낮은 안"이라고 했는데, 데이터에서 요구조건을 전부 충족하는 모델이 구역별로 **하나뿐**이었습니다.
한 급 낮추는 순간 요구조건이 깨집니다. 제가 만든 기준본의 2안도 화면크기 요구를 어기면서 "한 급 낮은 안"이라고 적고 있었습니다.

| 고친 것 | 어떻게 |
|---|---|
| 데이터 | 대회의실 적합 모델 `MX-80P` 추가. 1안·2안이 **둘 다 요구조건을 충족**하게 |
| 지시문 ⑤-6 | "전부 충족하는 대안이 하나뿐이면 **대안 없음**을 적고 필수가 아닌 항목 하나만 완화한다" |
| 지시문 ⑤-6 | 3안의 **포기 하한**을 명시 (최소수량 충족 · 요구 크기에서 한 단계 이내) |
| 지시문 ④-2 | 대조표는 **O/X 판정이 가능한 항목만**. 사용목적·수량·예산은 3안 구성에서 검증 |
| 지시문 ④-2 | 사양 미표기는 **`확인불가`** 로 적고 X와 같이 다룬다. "없음"으로 단정하지 않는다 |
| 지시문 ④-4 | 크롤 표에 조회 일자 열이 없으므로 **"미상"** 으로 적고 확인 필요에 넣는다 |
| 기준본 | 위 규칙대로 다시 생성 |

### B 파트너 — 매칭이 0건이 되는 구조였습니다

파트너 담당권역은 `부산·경남`, 사용자가 주는 권역은 `부산 해운대`입니다.
지시문의 "담당권역이 같고"를 문자 그대로 적용하면 **맞는 파트너가 하나도 없습니다.**

| 고친 것 | 어떻게 |
|---|---|
| 지시문 ④-6 | 파트너 담당권역이 대상 권역을 **포함하면** 맞는 것으로 본다 |
| 지시문 ④-6 | **시공가능규모 ≥ 사업 규모.** 단위가 다르면 붙이지 않고 "단위 불일치". 같은 값이면 충분하되 **"여유 없음"** 을 논의사항에 |
| 지시문 ④-2 | 기사에 규모가 없으면 상권정보에서 채우고 `(상권정보 기준)` 표시. 양쪽 다 없으면 `규모 불명`으로 기회 제외 |
| 지시문 ④-5 | **예정시기 가까운 순**, 같으면 규모 큰 순 (두 기준의 순서를 명시) |
| 지시문 ④-7 | 파트너가 없는 기회는 `담당 파트너 미정` 블록으로. 지표 기사는 1절 근거로만 |

### D 데이터 분석 — 3위가 사람마다 달라집니다

"판매수량·수요처 수·조합 반복 횟수를 기준으로 3개를 고른다"에 **순위가 없었습니다.**
수량만 보면 `HX-50T`(80대)가 `BX-65S`(8대)의 10배입니다. 어느 쪽을 3위로 올려도 지시문 위반이 아니었습니다.

| 고친 것 | 어떻게 |
|---|---|
| 지시문 ④-3 | 선정 순서를 다섯 단계로 고정. 용도 축 → 후보 → **수요처 수 → 판매수량 → 조합 횟수** → **한 축에서 1위 하나만** |
| 지시문 ④-2/3 | **조합 = 같은 수요처가 같은 달 또는 인접 1개월 이내에 함께 산 모델 쌍.** 같은 달과 연속월을 나눠 센다 |
| 지시문 ④-5 신설 | 수량은 대상 규모와 과거 비율에서만. **행 번호와 계산식**을 적고 보간이면 `추정`으로 범위 제시 |
| 지시문 ④-0 | 중복은 **모든 열이 같은 행만**. 날짜만 다르면 별개 거래 |
| 지시문 ④-1 | 체인 판정은 **수요처명 앞부분 일치**. 지역명만 같은 것은 체인이 아니다 |
| 지시문 ④-6 | 출력은 **완전한 HTML 문서** |

### A 직판 Sensing — 갈 곳 없는 신호가 있었습니다

판정값이 `기회`와 `보류` 둘뿐이라 **일정 연기·준공 완료** 같은 신호가 어디에도 못 갑니다. 실행자는 `관망`이라는 값을 스스로 만들었습니다.

| 고친 것 | 어떻게 |

## 이 기록에서 얻은 규칙

**1. 자동 검사 통과는 완성이 아닙니다.** 11항목은 파일과 헤더를 봅니다. 지시문의 빈틈은 못 봅니다.

**2. 지시문에 판단 기준이 둘 이상이면 순서를 적습니다.** "규모와 시기로 정렬한다"는 두 기준이 엇갈릴 때 답이 갈립니다.

**3. 분류 값은 전부 열거합니다.** 값이 둘뿐이면 셋째 경우가 올 때 실행자가 값을 만들어 냅니다.

**4. 데이터가 지시문을 만족시킬 수 있는지 먼저 확인합니다.** C의 2안은 데이터상 만들 수 없는 것을 요구하고 있었습니다.

**5. "없을 때"를 반드시 씁니다.** 값이 없을 때, 대안이 없을 때, 맞는 것이 없을 때. 이 셋이 결함의 대부분이었습니다.
