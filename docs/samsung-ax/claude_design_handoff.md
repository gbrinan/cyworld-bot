■ 일을 보는 법 · 에이전트로 옮기는 법 (9장) — **이 과정의 첫 시간. 지시문보다 먼저 옵니다**
정본은 `context_pack/common/task_decomposition.md` + `agent_and_skill_split.md`.
- **에이전트를 못 만드는 진짜 이유**: 프롬프트를 못 써서가 아니라 지금 일이 어떻게 흘러가는지 적어 본 적이 없어서 (문제 제기 1장)
- **설계 6단계**: ① As-Is 프로세스 → ② 단계별 IPO → ③ 꼬리표 → ④ 묶기 → ⑤ 에이전트/스킬 → ⑥ 7블록·SKILL.md (가로 흐름 1장, 이후 장의 목차 역할)
- **① As-Is 프로세스**: 단계·누가·시간·막히는 곳 4열 표. C 모듈 9단계 실물. **90분짜리 한 단계에 색을 입혀** 시간이 어디 몰리는지 보이게
- **② 단계별 IPO**: I/P/O 3열. 규칙 3개를 우측에 — Input은 꺼낼 수 있는 것 / Output은 파일 이름으로 / **앞 O와 다음 I가 다르면 거기를 사람이 메우고 있다**
- **틈이 에이전트 자리입니다**: 화면에서 복사한 텍스트 → (틈) → 4열 표. 이 틈에서 C 모듈 프롬프트 ⓪이 나온 것을 화살표로 (1장)
- **③ 꼬리표 4종**: 🔒 사람만 / ✍️ AI 초안 / ⚙️ AI 반복 / 🔌 밖에서 가져옴. 하단에 판단 기준 한 줄 — "이 단계가 틀리면 누가 책임지는가"
- **④ 묶으면 에이전트가 나옵니다**: C 모듈 IPO표 → 프롬프트 ⓪①② + STOP. 오른쪽에 묶음 괄호 (1장)
- **⑤ 에이전트와 스킬 나누기**: 좌 "누가 써도 같은 것 = 스킬(절차·양식·금지·검수)" / 우 "우리 팀 것 = 에이전트(참조 파일·용어·예약)". 하단에 세 가지 질문
- **⑥ 분해표가 지시문이 됩니다**: 왼쪽 IPO표 / 오른쪽 7블록·SKILL.md 5섹션, 화살표로 연결 (1장)
