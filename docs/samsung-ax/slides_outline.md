# 슬라이드 설계서 (강사 담당 6시간)

> 이 문서는 슬라이드 제작을 위한 장별 명세입니다. 각 장의 **핵심 메시지 한 줄**이 슬라이드 제목 아래 들어갑니다.
> 팀별로 바뀌는 장은 `[팩]` 표시가 있습니다. 그 장만 데이터 팩 값으로 교체하면 두 팀 모두 진행됩니다.
> 총 42장 (오프닝 4 · 공통 방법론 9 · 모듈② 9 · 모듈③ 9 · 모듈④ 9 · 클로징 2)

디자인 기준: 한 장에 한 메시지. 표는 5행 이내. 실습 장은 좌측에 시간 배분, 우측에 체크리스트.

## OPENING (4장)

### S01 — 표지
- 제목: **B2B 영업 AI Agent 실습**
- 부제: 시장·고객 분석 / 제안자료 작성 / 데이터 분석
- 하단: 삼성전자 | 2026

### S02 — 오늘 만드는 것
- 핵심 메시지: **세 개의 Agent가 하나의 영업 여정으로 이어집니다.**
- 본문: 체인 다이어그램
```
② Sensing  → customer_profile.md
③ Action   → proposal_draft.md
④ Analysis → report_draft.md
```
- 하단 한 줄: 각 단계의 결과를 파일로 저장해 다음 단계가 받습니다.
- 강사 노트: 여기서 "오늘 산출물은 세 개의 파일"이라고 못 박습니다.

### S03 — 오늘의 흐름
- 핵심 메시지: 6시간, 세 모듈, 같은 방법.
- 본문: 타임라인 (② 2h → ③ 2h → ④ 2h). ①⑤는 회색으로 표시하고 "삼성 자체 운영" 표기.
- 각 모듈 아래: 도입 15 / 실습1 20 / 실습2 35 / 실습3 25 / 시연 15 / 마무리 10

### S04 — 시작 전 세 가지
- 핵심 메시지: 오늘은 **팩의 가상 데이터만** 씁니다.
- 본문 3항목
  1. 내 팀 폴더를 엽니다 (team_b2b / team_partner)
  2. 실행 횟수 예산을 확인합니다 (Deep Research 1회, 에이전트 3회)
  3. 실제 업무 파일은 올리지 않습니다
- 강사 노트: 3번은 반드시 소리 내어 읽습니다.

## 공통 방법론 (9장) — 세 모듈 시작 전 한 번만

### S05 — 왜 Agent를 따로 만들지 않는가
- 핵심 메시지: **팀이 둘인데 Agent를 여섯 개 만들 수는 없습니다.**
- 본문: 좌우 비교
  - 왼쪽(✗): 팀마다 Agent 3개 = 6개, 차수마다 새로 제작
  - 오른쪽(○): 공통 Agent 3개 + 팀별 데이터 팩 2벌
- 하단: Agent는 "아는 것"이 아니라 **"받은 파일"**로 일합니다.

### S06 — 컨텍스트를 데이터로
- 핵심 메시지: 바뀌는 것과 안 바뀌는 것을 나눕니다.
- 본문: 2열 표

| 안 바뀜 (공통) | 바뀜 (팀별 팩) |
|---|---|
| 지시문 골격, 처리 순서, 출력 형식 | 업무 상황 |
| 검수 기준, 중단 규칙 | 입력 데이터와 컬럼 |
| 테스트 구성 | 고객·제품 정보 |
| 사람 승인 지점 | 결과물 서식 |

- 강사 노트: "지시문에 고객사 이름을 적지 않고, 고객사 파일을 올립니다."

### S07 — 일반 대화와 업무 Agent
- 핵심 메시지: 한 번 쓰고 버리는 것과, 반복해서 같은 기준으로 도는 것은 다릅니다.
- 본문: 2열 비교 (대화: 맥락을 매번 전달 / 품질 변동 / 1회성 · Agent: 역할·지식·출력 고정 / 예외에서 중단 / 반복 업무)
- 하단: 반복 빈도와 오류 비용이 높을수록 Agent 설계가 필요합니다.

### S08 — IPO 명세: 프롬프트보다 먼저
- 핵심 메시지: **한 장을 먼저 채웁니다.** 이게 지시문·테스트·검수의 원본입니다.
- 본문: INPUT / PROCESS / OUTPUT / STOP / APPROVAL / TEST 6칸
- 하단: IPO가 모호하면 Agent가 아니라 업무 정의부터 다시 봅니다.

### S09 — 지시문 7블록
- 핵심 메시지: 순서를 고정하면 빠뜨리지 않습니다.
- 본문: ①역할 ②업무 범위 ③입력 검사 ④처리 순서 ⑤출력 형식 ⑥중단·보안 ⑦성공 기준·사람 승인
- 강조 박스: 지시문 끝에 항상 —
  > 근거가 없으면 추정하지 말고 질문한다. 판단·서명·발송은 사람이 한다.

### S10 — 나쁜 문장과 좋은 문장
- 핵심 메시지: **검증할 수 있게 씁니다.**
- 본문: 좌우 비교 3쌍

| ✗ | ○ |
|---|---|
| 정확하게 작성한다 | 필수 컬럼이 누락되면 질문하고 중단한다 |
| 데이터를 요약한다 | 합계를 재계산하고 표지 값과 대조한다 |
| 친절하게 답변한다 | 근거 위치를 파일·행으로 표시한다 |

### S11 — 테스트 3종
- 핵심 메시지: 정답 문장이 아니라 **행동**을 봅니다.
- 본문: 3열

| 정상 | 경계 | 실패 |
|---|---|---|
| 완전한 입력 | 합계 불일치·기준일 미지정 | 실명·권한 밖 요청 |
| 서식대로 작성 | 두 값 표시 후 질문 | 가명화 요청 후 중단 |

- 강조: **중단은 실패가 아니라 성공 행동입니다.**

### S12 — 사람이 하는 일
- 핵심 메시지: Agent는 승인 상태를 기록할 수 있지만 **승인자가 될 수 없습니다.**
- 본문: 2열 (AI: 수집·요약·계산·초안·근거 표시·누락 질문 / 사람: 사실 확정, 가격·납기 결정, 발송, 서명, 최종 책임)

### S13 — 오늘의 완주 기준
- 핵심 메시지: 완성도보다 **체인이 끊기지 않는 것**이 우선입니다.
- 본문: 2단
  - 최소 완주: IPO 1장 + v0 + 정상 테스트 1건 + 인계 파일 저장
  - 확장: v1 + 테스트 3종 + 전환 표
- 하단: 못 끝내면 `handoff/` 정답 파일로 다음 모듈을 시작합니다. 괜찮습니다.

## 모듈 ④ 데이터 분석 Agent (9장)

### S32 — 모듈 표지
- 제목: ④ 데이터 분석 Agent (Analysis)
- 부제: 영업 데이터 기반 분석 및 보고서 작성 · 2.0h
- 산출물: `report_draft.md`

### S33 — 보고서보다 먼저 오는 것
- 핵심 메시지: **0번 데이터 점검**이 먼저입니다.
- 본문: `handoff/report_draft.md`의 0번 섹션만 크게
```
- 필수 컬럼: 이상 없음
- 합계 정합성: 상세 9,835 vs 표지 9,835 → 일치
- 결측·중복: 없음
```

### S34 — 이 파일을 그대로 믿으면 안 됩니다 `[팩]`
- 핵심 메시지: 표지 합계와 상세 합계를 **각각 계산해 비교합니다.**
- 본문: 경계 테스트 예시 (B2B팀 140백만원 차이 / 유통전략팀 3,600천원 차이)
- 하단: 불일치하면 두 값을 모두 표시하고 **보고서 생성을 중단합니다.**

### S35 — 입력 데이터 `[팩]`
- 파일명 + 행수 + 주요 컬럼 (manifest.md 기준)

### S36 — 실습 1: IPO 작성 (20분)
- 체크리스트: 기준월 / 비교 기간 / 필수 컬럼 / **합계 대조를 PROCESS에 넣었는가**

### S37 — 실습 2: Agent v0 (35분)
- 체크리스트: 실적 데이터 / 월 요약 / 보고서 양식 / 기준월 지정
- 확인: **0번 점검이 먼저 나왔는가**

### S38 — 분모를 밝힙니다 `[팩]`
- 핵심 메시지: 같은 데이터에서 **64.7%와 16.7%가 둘 다 나옵니다.**
- 본문(B2B팀): 수주 전환율 = 11/17(종결) = 64.7% vs 11/66(전체) = 16.7%
- 본문(유통전략팀): 해지율 = 19/167 = 11.4%. 포근물산은 4/7 = 57.1%인데 **분모가 7건**입니다.
- 하단: 분모를 밝히면 둘 다 맞습니다. 안 밝히면 둘 다 틀립니다.

### S39 — 없는 값은 채우지 않습니다 `[팩]`
- 핵심 메시지: 자료에 없으면 **확인 필요**로 남깁니다.
- B2B팀: 월 요약에 **전월 단계별 분포가 없습니다.** 단계별 증감은 계산하지 않습니다.
- 유통전략팀: **해지 사유 컬럼이 없습니다.** 이탈 원인은 판단하지 않습니다.
- 하단: 원인은 "가설"로 쓰고 확인 방법을 함께 적습니다.

### S40 — 실습 3: 테스트 3종 (25분)
- 3행 표. 경계 테스트에서 흔한 오답 3가지를 함께 표시
  - 표지 값 그대로 인용 / 상세만 쓰고 불일치 미언급 / "반올림 차이"라고 설명
