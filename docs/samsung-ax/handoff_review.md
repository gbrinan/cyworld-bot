# 핸드오프 검토 — 이 자료로 사내강사가 실습을 운영할 수 있는가

> 검토 방법: 자료를 처음 받은 사내강사 후보(양성과정 9/16~17 참가자)가 `claude_design_handoff.md`로 만든 슬라이드를 띄우고, `context_pack/`을 배포하고, 2시간 모듈 하나를 40~50명에게 진행한다고 가정하고 처음부터 끝까지 걸어갔습니다.
> 막히는 지점마다 **증거(파일·grep 결과) → 영향 → 제안**을 적었습니다.
> 검토일 2026-09-11 · 양성과정까지 5일

## 판정

**지금 상태로는 운영할 수 없습니다.** 슬라이드 설계(v2, Agent 4개·TV/디스플레이)와 실습 자료(v1, Agent 3개·SAC/HVAC/DMFP)가 서로 다른 과정입니다. 강사가 슬라이드에 "입력 헤더 [품목][헤드라인][원본url][키워드]"를 띄우면 참가자 팩에는 그 파일이 없습니다.

방법론층(7블록·테스트 3종·검수·웹 환경 절차)은 그대로 쓸 수 있습니다. 막힌 것은 **실습 자료층**이고, 그중 세 가지는 없으면 실습 자체가 안 됩니다.

## P0 — 없으면 실습이 안 됨

### F1. 슬라이드는 v2, 팩·정답·지시문은 v1

| 항목 | 슬라이드·핸드오프 (v2) | 팩 (v1) |
|---|---|---|
| Agent 수 | 4 (A·B 팀별 + C·D 공통) | 3 × 팀별 2벌 |
| 품목 | TV·디스플레이 | SAC·모바일·IT·DMFP |
| A 입력 | `[품목][헤드라인][원본url][키워드]` | `industry_news.csv` 9열 |
| C 출력 | HTML, 제안 제품 3개 비교 | `proposal_draft.md` HVAC 통합 제안서 |
| D 입력 | 판매실적 10열, 버티컬 축 | Lead/BO 파이프라인 12열 |

**증거** — `grep -rl "SAC\|HVAC\|DMFP"` → 팩·설계서·가이드·워크북 **47개 파일**이 v1 품목 기준.

**영향** — 강사가 슬라이드대로 진행할 수 없고, `handoff/` 정답 파일(진도 편차 안전망)도 다른 과정의 정답이라 못 씁니다. **핸드오프 프롬프트가 첨부하라는 파일(`slides_outline.md`, `context_pack/`, `handoff/`)이 전부 v1이라, 지금 Claude Design에 넣으면 v1 내용의 슬라이드가 나옵니다.**

**제안** — v2 팩을 D → C → A → B 순으로 제작(김승진 프로가 요청한 Agent별 순차 공유와 같은 순서). 각 Agent에 데이터·테스트 케이스·정답·완성 프롬프트·시연 로그를 한 세트로. 완성 전에는 Claude Design에 v1 파일을 첨부하지 않도록 핸드오프 문서에 게이트를 넣습니다.

### F2. 복붙 가능한 완성 프롬프트가 없다

**증거** — `instruction_templates/*.md`에 `{{팀명}}` `{{입력 파일 목록}}` `{{우선순위 기준}}` 등 **미채움 자리 20개**.

**영향** — 참가자가 실습 2(35분) 안에 자리 20개를 스스로 채워야 합니다. 기초 참가자 절반이 여기서 멈춥니다. 삼성 9/7 시나리오 pptx도 B Agent에 **"(제공) 프롬프트 3종"** 을 명시했습니다 — 삼성은 완성 프롬프트를 받는 것으로 알고 있습니다.

**제안** — Agent × 팀별 **완성 프롬프트**를 별도 파일로.

```
context_pack/team_b2b/agentA_sensing/prompt/agentA_prompt.md      ← 자리 0개, 그대로 붙여넣기
context_pack/team_partner/agentB_sensing/prompt/agentB_prompt_1_키워드.md
context_pack/team_partner/agentB_sensing/prompt/agentB_prompt_2_API연동.md
context_pack/team_partner/agentB_sensing/prompt/agentB_prompt_3_양식출력.md
context_pack/common/agentC_prompt.md   (공통)
context_pack/common/agentD_prompt.md   (공통)
```
템플릿(`{{ }}`)은 "내 업무로 전환" 단계용으로 남기고, 실습에서는 완성본을 씁니다.

### F3. HTML·Word 결과물을 만드는 절차가 없다

**증거** — `web_environment.md` `instructor_guide.md` `workbook.md`에서 `.html` `.docx` `브라우저에서 열기` 검색 결과 **0건**. 삼성 확정 출력은 **HTML 3개(A·C·D) + Word 1개(B)**.

**영향** — 참가자가 AI로부터 HTML 코드 덩어리를 받고 무엇을 해야 할지 모릅니다. 현재 절차("복사 → 메모장 → .md 저장")로는 대시보드가 안 보입니다.

**제안** — `web_environment.md`에 절 추가.

```
[HTML 결과 보기]
① AI 출력의 코드 블록 전체를 복사
② 메모장에 붙여넣기
③ 저장 — 파일 이름 dashboard.html, 파일 형식 "모든 파일"
   (.txt로 저장되면 안 열립니다)
④ 저장한 파일을 더블클릭 → 브라우저가 열림
⑤ 다음 모듈에서 쓸 때는 이 .html 파일을 그대로 업로드

[Word 보고서 (Agent B)]
① AI 출력을 복사 → Word 새 문서에 붙여넣기 (마크다운 표는 표로 붙습니다)
② 회사 양식이 있으면 양식 파일을 먼저 열고 붙여넣기
③ 코드 실행이 켜져 있으면 "docx 파일로 만들어줘"도 가능 — 리허설 C4 결과에 따라
```
삼성 pptx의 "확장프로그램 활용"이 무엇인지 확인이 필요합니다(리허설 질문에 추가).

### F4. 시연 대화 로그가 없다

**증거** — `handoff/`에는 **최종 결과물만** 있습니다(`customer_profile.md` 등 6개). "어떤 지시문을 붙여넣고, 어떤 파일을 올리고, AI가 뭐라고 답했고, 어디서 되물었는지"가 없습니다.

**영향** — 사내강사 17명이 각자 돌리면 17가지 결과가 나오고, 자기 결과가 맞는지 판단할 기준이 없습니다. 도입 15분 시연에서 강사가 무엇을 보여줘야 하는지도 없습니다.

**제안** — Agent마다 `demo_transcript.md`.

```
## 시연 순서 (도입 15분)
1. 올린 파일: sales_history.csv, target_account.md
2. 붙여넣은 지시문: agentD_prompt.md 전체
3. 첫 응답에서 확인할 것:
   □ "0. 데이터 점검"이 먼저 나오는가
   □ 합계 ___가 표지와 일치한다고 말하는가
   □ 추천 TOP3에 근거 행 번호가 붙는가
4. 안 나오면 이렇게 되묻는다: "합계를 직접 다시 계산해서 표지 값과 비교해줘"
5. 참가자에게 짚어줄 한 문장: "보고서보다 점검이 먼저 나온 걸 보세요"
```
정답 파일은 이 로그의 "기대 응답"으로 연결합니다.

### F5. 도구 클릭 경로가 없다

**제안** — `tool_paths.md`. 9/11 캡처로 경로는 확인됐습니다.

```
ChatGPT 에이전트 만들기
```

### F6. 도구 배분이 v2 입력 형태와 안 맞는다

**제안** — 도구 매핑을 v2 기준으로.

| A | CSV 4열 | ChatGPT 프로젝트 또는 Gemini Notebook + 에이전트 | 강사 라이브 시연 1회만 ("실제로는 이렇게 수집한다") |

## 검토에서 문제없다고 확인한 것

- 방법론층(`methodology.md` `test_cases_guide.md` `review_criteria.md` `fit_check.md` `skills_and_mcp.md`)은 v1/v2 무관하게 그대로 씁니다. 품목 언급이 없습니다.

- 강사 가이드 골격(큐시트 2h/90분·되묻기·보조강사 운영·진도 관리)은 유지. 모듈별 함정 표만 v2 데이터로 교체하면 됩니다.
- 워크북 골격도 유지. 함정 확인 칸의 문항만 교체.
- 핸드오프 프롬프트의 [팀별] 9장 분기, 실습 템플릿 12장, 웹 전용, 가상 데이터 명시는 정확합니다.
