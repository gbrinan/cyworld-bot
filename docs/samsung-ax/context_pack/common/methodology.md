# 공통 방법론 — 3개 Agent에 똑같이 적용합니다

이 문서는 모든 팀·모든 Agent에 공통입니다. 팀별로 바뀌는 것은 데이터 팩(`team_*/`)뿐입니다.

---

## 1. 왜 "컨텍스트를 데이터로" 다루는가

같은 Agent라도 B2B팀과 B2B유통전략팀은 고객도, 품목도, 관리 지표도 다릅니다. 그렇다고 Agent를 팀마다 따로 만들면 6개가 되고, 사내강사가 차수마다 새로 만들어야 합니다.

대신 이렇게 나눕니다.

| 바뀌지 않는 것 (공통) | 바뀌는 것 (팀별 데이터 팩) |
|---|---|
| 지시문 골격, 처리 순서, 출력 형식 | 업무 상황(비즈니스 Context) |
| 검수 기준, 중단(STOP) 규칙 | Input 더미데이터와 컬럼 헤더 |
| 테스트 3종 구성 방식 | 고객·제품·파트너 정보 |
| 사람 승인 지점 | 최종 결과물 서식 |

**Agent는 "아는 것"이 아니라 "받은 파일"로 일합니다.** 그래서 지시문에 고객사 이름을 적지 않고, 고객사 파일을 올립니다. 팀이 바뀌면 파일만 바꿉니다.

---

## 2. 영업 여정 체인 — 세 Agent는 파일로 이어집니다

```
② 시장·고객 분석 (Sensing)
      ↓  customer_profile.md  (분석 결과를 파일로 저장)
③ 제안자료 작성 (Action)
      ↓  proposal_draft.md    (제안서 초안을 파일로 저장)
④ 데이터 분석 (Analysis)
      ↓  report_draft.md      (실적·전환 보고서)
```

규칙:
- 각 모듈이 끝나면 **출력물을 파일로 저장**합니다. 화면에만 있으면 다음 Agent가 못 씁니다.
- 도구가 달라도(② Gemini → ③ Gemini → ④ GPT) 파일로 이어지므로 끊기지 않습니다.
- 앞 모듈을 못 끝냈으면 팩의 `handoff/` 정답 파일로 시작합니다. **뒤처져도 다음 실습은 반드시 시작합니다.**

**웹 환경에서 "파일로 저장"하는 방법** — 사내 환경은 브라우저에서 ChatGPT·Gemini를 불러 쓰는 방식입니다. AI에게 파일을 만들어 달라고 하지 말고, **화면 출력을 복사해 메모장에 붙여넣어 저장**합니다. 자세한 절차는 [`web_environment.md`](web_environment.md)에 있습니다. 이 문서를 실습 전에 먼저 읽습니다.

## 3. IPO 명세 — 프롬프트보다 먼저 씁니다

Agent를 만들기 전에 한 장을 채웁니다. 이 한 장이 지시문·테스트·검수 기준의 원본입니다.

| 구분 | 무엇을 적나 |
|---|---|
| 목적·독자·기준일 | 누가 읽는 무엇을, 언제 기준으로 만드는가 |
| INPUT | 허용 파일명·필수 컬럼·기간·권한 |
| PROCESS | 검사 → 계산·분류 → 비교 → 초안 → 근거 연결 (순서로) |
| OUTPUT | 결과물 서식, 근거표, 확인 필요 목록 |
| STOP | 무엇이 나오면 멈추고 물어보는가 |
| APPROVAL | 누가 무엇을 확인한 뒤 발송·제출하는가 |
| TEST | 정상·경계·실패 입력에서 각각 어떻게 행동해야 하는가 |

IPO가 모호하면 Agent가 아니라 **업무 정의부터 다시 봅니다.**

## 4. 지시문 7블록 — 순서 고정

지시문은 아래 일곱 블록 순서로 씁니다. IPO 내용을 그대로 옮기고, "친절하게" 같은 성격 문장은 최소화합니다.

```
① 역할        — 너는 [팀]의 [업무]를 돕는 Agent다
② 업무 범위    — 하는 일 / 하지 않는 일
③ 입력 검사    — 필수 컬럼·기준일·권한 확인, 없으면 질문
④ 처리 순서    — 검사 → 변환 → 비교 → 작성
⑤ 출력 형식    — 서식, 근거표, 확인 필요 목록 분리
⑥ 중단·보안    — STOP 조건, 업로드 금지 데이터
⑦ 성공 기준·사람 승인 — 합격 조건, 승인자
```

지시문 끝에는 항상 이 문장을 넣습니다.

> 근거가 없으면 추정하지 말고 질문한다. 판단·서명·발송은 사람이 한다.
> 결과는 파일 첨부가 아니라 화면에 마크다운 텍스트로 출력한다.

마지막 줄은 웹 환경 때문입니다. AI가 만든 파일은 다운로드가 막히는 경우가 많아, 화면에 텍스트로 받아 복사하는 편이 확실합니다.

**지시문은 내 PC의 메모장에 먼저 씁니다.** 웹 채팅은 세션이 끊기면 지시문이 사라집니다. `agent02_prompt.md` 처럼 저장해 두고 붙여넣어 쓰면, 세션이 끊겨도 다음 차수에도 그대로 씁니다.

## 5. 테스트 3종 — 정답 문장이 아니라 행동을 봅니다

| 구분 | 입력 | 합격 행동 |
|---|---|---|
| 정상 | 완전한 데이터 1건 | 지정 서식으로 작성하고 근거 위치를 표시 |
| 경계 | 합계 불일치, 기준일 임계, 규정 상충 | 두 값을 함께 표시하고 확인 질문 후 중단 |
| 실패 | 실명·연락처 포함, 권한 밖 요청 | 가명화를 요청하고 결과물을 만들지 않음 |

**중단은 실패가 아니라 성공 행동입니다.** 실패 입력에서 보고서가 만들어지면 그 Agent는 아직 못 쓰는 상태입니다.

테스트 로그는 답변이 아니라 **수정 근거**를 남깁니다.

| 케이스 | 관찰 결과 | 수정 규칙 |
|---|---|---|
| 정상 | 서식·근거 일치 | 유지 |
| 경계 | 질문 없이 한쪽 값만 씀 | ⑥에 합계 대조 규칙 추가 |
| 실패 | 실명을 그대로 출력 | ⑥에 가명화·중단 규칙 추가 |

---

## 6. 사람 승인 — AI가 할 수 없는 일

| AI가 하는 것 | 사람이 하는 것 |
|---|---|
| 자료 수집·요약·분류 | 사실 확정, 참여 여부 결정 |
| 계산·비교·추이 정리 | 가격·납기·할인 결정 |
| 초안 작성, 근거 위치 표시 | 대외 발송, 서명, 제출 |
| 누락 질문, 확인 필요 표시 | 최종 책임 |

Agent는 승인 상태를 기록할 수 있지만 **승인자가 될 수 없습니다.**

## 7. 오늘의 완주 기준

| 라인 | 조건 |
|---|---|
| 최소 완주 | IPO 1장 + Agent v0 + 정상 테스트 1건 통과 + 인계 파일 저장 |
| 확장 | v1(수정 반영) + 테스트 3종 통과 + 내 업무 전환 표 작성 |

최소 완주 라인을 넘기면 다음 모듈로 넘어갑니다. 완성도보다 **체인이 끊기지 않는 것**이 우선입니다.
