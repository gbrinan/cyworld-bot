# 영업 매출 대시보드 — 채운 예시

> `dashboard_sales.md`의 `채우는 칸`을 **세션2 실습 데이터로 채워 본 것**입니다.
> 자기 업무로 옮길 때 "이 자리에 이런 걸 적는구나"를 보라고 만든 참고본입니다.
> 아래 수치는 `modules/D_analysis/01_데이터/매출데이터.csv`(16개 열, 가상)에서 실제로 나오는 값이라 **그대로 재현됩니다.**
> 결과 화면은 `modules/D_analysis/04_기준본/대시보드.html`입니다.

---

## 1. 채우는 칸을 이렇게 채웠습니다

| 자리표시자 | 채운 값 | 왜 이렇게 |
|---|---|---|
| `{{팀명}}` | 한국총괄 B2B영업 | |
| `{{실적 파일}}` | `매출데이터.csv` | 세션2에서 올린 그 파일 |
| `{{검산 방법}}` | `매출데이터_소계.csv`의 다섯 축 합계와 대조 | **이 헤더에는 단가 열이 없어** `단가 × 수량 = 금액` 검산을 못 합니다. 소계 대조가 그 자리를 대신합니다 |
| `{{필수 컬럼}}` | 매출일자, 판매처명, 수요처명, 파트명, 품목구분, 모델명, 매출금액 | 16개 열 중 화면에 꼭 필요한 일곱 개 |
| `{{금액 컬럼}}` | 매출금액 | |
| `{{날짜 컬럼}}` | 매출일자 | |
| `{{나눠 볼 기준}}` | 판매처, 수요처, 파트, 품목, 모델 | 삼성 측 요구 그대로. 다섯 개가 한계 |
| `{{조건 칸}}` | 기준월, 파트, 수요처, 품목 | 판매처는 나눠 보기에서 줄을 눌러 고르게 하고 칸에서는 뺐습니다 |
| `{{들어가는 순서}}` | 판매처 → 수요처 → 품목 → 모델, 파트 → 수요처 | |
| `{{묶을 값}}` | 직판주문은 판매처 = 수요처라 '직판' 한 줄로 | 안 묶으면 수요처 여섯 곳이 판매처 여섯 곳처럼 보입니다 |
| `{{보는 사람}}` | 보직장 — 일 매출 · 나눠 보기 / 임원 — 전년비 · 전월비 · 왜 / 품목 담당 — 품목별 | |

**조건 칸을 넷으로 줄인 게 이 예시의 핵심입니다.** 열은 16개지만 칸을 16개 만들면 아무도 안 씁니다.

## 2. 이렇게 나옵니다 (실습 데이터 기준)

### 0. 숫자 확인

```
1,093행 · 매출일자 2025-01-02 ~ 2026-09-24 → 기준일 2026-09-24
소계 다섯 축(품목구분 · 주문유형 · 수요처명 · 파트명 · 판매처명) 전부 일치
전체 합계 8,623,580,000원 (직접 합산)
단가 열 없음 → 검산식은 못 세우고 소계 대조로 대신함
```

### 1. 한눈에 (기준월 2026년 9월, 24일까지)

| 칸 | 값 | 원래 금액 |
|---|---|---|
| 이번 달 (9/1~9/24) | 267,360,000원 | |
| 지난달 같은 날짜까지와 비교 | **+2.8%** | 8월 1~24일 260,070,000 → 267,360,000 |
| 작년 같은 달 같은 날짜까지와 비교 | **−46.9%** | 2025년 9월 1~24일 503,400,000 → 267,360,000 |
| 올해 누계 (1/1~9/24) | 3,780,640,000원 | 작년 같은 기간 3,614,570,000 대비 **+4.6%** |

아래 한 줄: *"8월 한 달 전체(445,480,000원)와 견주면 −40.0%로 보이지만, 8월도 24일까지만 자르면 +2.8%입니다."*
이 팀은 8월 25일 이후 7일에 한 달 매출의 **42%**가 몰립니다. 24일 기준으로 한 달 전체와 견주면 매달 폭락한 것처럼 보입니다.

### 4. 나눠 보기 — 품목별 (단위 백만원)

| 품목 | 이번 달 | 지난달 대비 | 작년 대비 | 올해 누계 | 누계 작년 대비 |
|---|---|---|---|---|---|
| TV | 60.7 | −4.7% | +192.9% | 1,047.0 | +4.4% |
| 사이니지 | 95.8 | +111.7% | +39.8% | 952.6 | **+75.3%** |
| PC | 45.6 | −42.5% | −87.9% | 948.9 | −21.0% |
| 모니터 | 20.0 | −62.8% | −5.3% | 470.1 | −6.0% |
| 에어컨 | 34.7 | +675.0% | +244.4% | 299.0 | −7.6% |
| 청소기 | 10.5 | −22.0% | +128.7% | 63.1 | +44.1% |
| 합계 | 267.4 | +2.8% | −46.9% | 3,780.6 | +4.6% |

품목 담당이 볼 것은 맨 오른쪽 열입니다 — 사이니지가 올해 누계로 **+75.3%**(543,250,000 → 952,560,000)입니다.
"이번 달" 열의 큰 증감률(에어컨 +675%)은 작은 금액에서 나온 것이라 원래 금액을 같이 봐야 합니다.

### 5. 왜 이렇게 됐나

> 작년 같은 달 같은 날짜까지 대비 **−236,040,000원 (−46.9%)**. 가장 크게 줄어든 수요처는 **미래로병원**(−274,970,000원) — 감소분의 **116%**입니다. 나머지는 합쳐서 +38,930,000원으로 오히려 늘었습니다.

그 아래 작년 큰 건 표에 **2025년 9월 「미래로병원 노트북 일괄 교체 납품건」 4건, 231,000,000원**이 보입니다. 올해가 나빠진 게 아니라 작년이 유난히 컸던 것 — **기저효과**입니다. 화면은 여기까지만 말하고, 원인 확인은 리뷰(`지시문_2_분석.md`)와 사람의 몫입니다.

## 3. 이 예시에서 배울 것 셋

**하나. 비교는 같은 날짜까지.** 24일까지만 있는 달을 한 달 전체와 견주면 −40%, 같은 날짜까지 자르면 +2.8%입니다. 숫자 하나로 회의 방향이 바뀝니다.

**둘. 비율만 쓰면 안 됩니다.** `−46.9%` 옆에는 `503,400,000 → 267,360,000`이 있어야 합니다. 에어컨 +675%처럼 비율은 크기를 숨깁니다.

**셋. 검산식이 없으면 대조할 다른 숫자를 받습니다.** 단가 열이 없는 헤더라 소계 파일을 같이 받았습니다. 대조할 숫자가 하나도 없으면 그 화면은 아무리 예뻐도 믿을 근거가 없습니다.
