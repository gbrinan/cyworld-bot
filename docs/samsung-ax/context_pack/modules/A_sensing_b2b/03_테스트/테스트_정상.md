# 정상 테스트 — A_sensing_b2b

## 입력
- 올리는 파일: `01_데이터/기사수집.csv`, `01_데이터/대상고객사.csv`
- 지침: `02_지시문/지시문_3_분석.md`의 ✂ 사이 (또는 `07_스킬/SKILL.md` 등록)
- 첫 메시지: `기사수집.csv와 대상고객사.csv를 올렸어. 기준일은 2026-09-01이야. 지침 순서대로 대시보드를 만들어줘.`

## 기대 행동
1. 수집 요약에 **원본 30건 → 중복 3건 제외 → 27건**이 나온다.
2. 수요처별 기사 수가 대성건설 4 · 한울종합건설 3 · 서진리테일 2 · 세종교육재단 2 · 해솔호텔 1 · 미래로병원 1이고, **회사가 특정되지 않는 `무관` 기사 14건**이 따로 집계된다. 목록 밖 개별 회사(`기타`)는 0건이다.
   7행 「한울종합건설 시공 해솔호텔 재개관」은 **한울종합건설**에 묶이고 해솔호텔은 `관련 수요처`로 적힌다.
3. Key Signal에 근거 행 번호가 붙는다.
4. 수요처마다 판정이 **`기회` / `관망` / `보류` / `정보 부족`** 넷 중 하나로 붙는다.
   - 한울종합건설 · 대성건설 → **`기회`**
   - 서진리테일 → **`보류`** (출점 보류·영업손실 확대)
   - 세종교육재단(신관 설계 공모 연기) · 해솔호텔(별관 준공 완료 = `기회 지남`) → **`관망`**
   - 미래로병원(신관 증축 설계 착수, 준공 시기 없음 = `시점 미상`) → **`정보 부족`**
   - `기회`만 4절 우선순위 표에 **현장 단위로** 올라간다
5. 우선순위가 **접근 시점 기준**으로 정렬된다.

| 순위 | 수요처 | 준공 | 접근 시점 | 기준일 대비 |
|---|---|---|---|---|
| 1 | 한울종합건설 · 해솔호텔 리뉴얼 | 2027-03 | **2026-09** | 지금 |
| 2 | 대성건설 오피스동 | 2028-06 | 2027-12 | 내년 이후 (15개월 뒤) |

   한울종합건설의 나머지 호텔 1곳은 시기가 없어 `정보 부족`으로 표 밖에 따로 적힌다.

6. **대성건설이 1순위가 아니다.** 수주 1.2조로 규모는 크지만 시점이 멀다.
7. 1순위에 **시나리오 2개 이상**이 있고 갈래마다 행동이 다르다.
8. 한울종합건설은 접점이 없지만 **해솔호텔은 기존 거래 고객**이라, 해솔호텔에 직접 가는 갈래가 시나리오에 들어간다.

## 통과 기준
- [ ] 중복 3건 제외가 보고된다
- [ ] 서진리테일이 보류, 세종교육재단·해솔호텔이 관망, 미래로병원이 정보 부족으로 분류된다
- [ ] 7행이 한울종합건설에 묶이고 해솔호텔이 관련 수요처로 적힌다
- [ ] Needs가 `대상고객사.csv`의 주력공종 매핑대로 옮겨진다 (상식으로 채우지 않는다)
- [ ] 접근 시점이 준공에서 6개월 뺀 값으로 계산된다
- [ ] 1순위가 한울종합건설이다 (대성건설이 아니다)
- [ ] 시나리오가 2개 이상이고, 해솔호텔(기존 거래)에 직접 가는 갈래가 있다

## 안 되면
- 대성건설을 1순위로 올린다 → 규모로 정렬한 것. "우선순위를 접근 시점 기준으로 다시 정렬해줘" 되묻기.
- 서진리테일을 기회에 넣는다 → 지침 ④-6 판정 표를 다시 읽게 한다.
- Needs를 상식으로 채운다 → ④-3 매핑 표만 쓰게 한다. 표에 없는 공종(주택·토목)이 내 업무 데이터에 섞이면 "매핑 없음"이 된다 — 이 실습 데이터에는 해당 회사가 없다.
- 해솔호텔 기사(7행)를 따로 세어 한울종합건설이 2건으로 줄어든다 → ④-1의 "목록의 회사가 둘 나오면 앞의 회사에 묶는다"를 확인.
- 접근 시점을 안 낸다 → "준공 예정일에서 6개월을 빼서 접근 시점을 계산해줘".
- 시나리오가 하나다 → `지시문_3_분석.md`의 대화 시작 예시 3번을 보낸다.
