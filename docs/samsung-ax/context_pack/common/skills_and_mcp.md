# Skill과 MCP — 오늘 만든 것이 어디로 이어지는가

> 이 문서는 ③ 모듈 마무리 또는 과정 클로징에서 다룹니다.
> 9/11 캡처로 **ChatGPT 에이전트 편집 화면에 「스킬 추가」 버튼이 있음**을 확인했습니다. 실습 가능 여부는 리허설 C10~C13에서 봅니다.
> Skill 형식은 Claude·ChatGPT·Codex·Cursor·Gemini CLI가 **같은 파일**을 읽는 오픈 표준입니다. 강사 입장에서 한 형식만 가르치면 됩니다.

---

## 1. 오늘 만든 것은 이미 "Skill"입니다

```
지시문 7블록 (agent_prompt.md)  +  참조 파일 (팀 프로필, 데이터, 양식)
```

이 조합의 이름이 **Agent Skill**입니다. 한마디로 **AI를 위한 매뉴얼**입니다. 지시·자료·(선택)스크립트를 담은 폴더이고, AI가 필요할 때 스스로 찾아 불러 씁니다.

```
내-업무-스킬/
├─ SKILL.md          ← 이름·설명 + 지시문 본문
└─ (참조 자료)        ← 양식, 예시, 가격 가이드, 데이터
```

GPTs·Gems보다 발전된 형태입니다. 조건에 맞을 때만 호출되고, 스킬 안에서도 필요한 부분만 읽기 때문에 **한 에이전트 안에서 여러 스킬을 함께 쓸 수** 있습니다.

---

## 2. SKILL.md 해부 — 세 부분

```markdown
---
name: recommending-products-by-vertical
description: 신규 수요처의 버티컬과 프로젝트 용도를 받아 과거 B2B 판매 실적에서
             유사 버티컬의 판매 패턴을 분석하고 추천 제품 TOP3와 근거를 만든다.
             영업 담당자가 제안 전에 제품 후보를 좁힐 때 쓴다.
---

(본문 = 지시문 7블록)
```

| 부분 | 규칙 | 왜 |
|---|---|---|
| `name` | 소문자·하이픈, **동명사형(verb+ing)**, 64자 이내 | 파일·폴더명으로 그대로 쓰임 |
| `description` | **가장 중요.** "무엇을 + 언제 쓰는지"를 **3인칭**으로 | AI가 이 설명만 보고 스킬을 고른다 |
| 본문 | 단계별 지시 + **입출력 예시** | "이 스킬을 쓰면 결과가 어떻게 나오는지"를 보여준다 |

### description이 왜 따로 있나 — 점진적 공개

```
① 이름·설명       → 항상 읽힘
② SKILL.md 본문   → 관련될 때만 읽힘
③ 부속 파일       → 필요할 때만 읽힘
```

그래서 설명이 모호하면 AI가 언제 이 스킬을 써야 할지 모릅니다.

| ✗ | ○ |
|---|---|
| 보고서를 잘 만들어 줍니다 | 월말 파이프라인 데이터를 받아 단계별 현황과 전월 대비 증감을 담은 초안을 만든다. 합계가 안 맞으면 중단한다 |

우리 지시문 ②번(업무 범위)을 "하는 일 / 하지 않는 일"로 나눠 쓴 이유가 이것입니다.

### 본문 5개 섹션 — 7블록을 이렇게 접습니다

| SKILL.md 본문 | 지시문 7블록 |
|---|---|
| 1. 역할 및 목표 | ① 역할 ② 업무 범위 |
| 2. 출력 형식 | ⑤ 출력 형식 |
| 3. 금지 사항 | ⑥ 중단·보안 |
| 4. 검토 기준 | ⑦ 성공 기준·사람 승인 |
| 5. 작업 처리 단계 및 **입출력 예시** | ③ 입력 검사 ④ 처리 순서 + **정답 예시(handoff)** |

**5번이 SKILL.md에서 새로 추가되는 것입니다.** 팩의 `handoff/` 정답 파일이 그대로 입출력 예시가 됩니다. 실습에서 만든 결과물을 버리지 않고 스킬 안에 넣는 셈입니다.

### 노코드 팁

지시문 7블록을 다 쓴 뒤 이렇게 시킵니다.

```
위 지시문을 SKILL.md 형식으로 정리해줘.
name은 소문자-하이픈 동명사형으로, description은 무엇을 언제 쓰는지 3인칭으로,
본문은 역할·출력형식·금지사항·검토기준·작업단계(입출력 예시 포함) 순서로.
```

AI가 초안을 만들어 줍니다. 사람은 description이 정확한지만 봅니다.

## 3. Agent 워크플로우 5패턴 — 우리 4개는 어디에

| 패턴 | 동작 | 삼성 Agent |
|---|---|---|
| **프롬프트 체이닝** | 순차 실행, 단계마다 검증 게이트 | **A·B** 수집→요약→기회→액션 / **D** 분석→추천→근거 |
| 라우팅 | 입력 유형별로 담당 스킬 분기 | (확장) 문의 유형별 제품 Q&A |
| 병렬화 | 나눠서 동시 처리 후 집계 | (확장) 수요처 여러 곳 동시 센싱 |
| 오케스트레이터-워커 | 중앙이 쪼개 위임하고 종합 | (확장) 권역별 취합 보고 |
| **평가자-최적화** | 하나가 만들고 하나가 검증 | **C** 제안 3개 → 상호 비교·시장가 대조. 우리 **테스트 3종·검수 기준**이 이것 |

핵심 원칙 — **단순하고, 단계를 순차로 분명하게, 검증 루프를 돌게.** 오늘 4개는 전부 체이닝 + 평가자 조합입니다. 나머지 셋은 사내 연동이 열리면 다음 단계입니다.

## 4. "매번 달라지는 것은 지침에 넣지 않는다"

Project(프로젝트)·에이전트 지침에 넣을 것과 넣지 않을 것.

| 지침에 고정 (반복됨) | 지침에 넣지 않음 (매번 다름) |
|---|---|
| 목적, 출력 형식, 금지 사항, 검토 기준 | 이번 달 수요처 이름, 이번 분기 실적 파일 |
| 팀 프로필, 제안서 순서, 버티컬 목록 | 특정 고객의 요구 조건 |

**금지 사항과 검토 기준을 지침에 고정하면 보안·검수 원칙이 매 대화에 자동 적용됩니다.** 이것이 "컨텍스트를 데이터로"의 실무 규칙입니다. 반복되는 건 지침(Skill)에, 매번 바뀌는 건 파일로.

## 5. 이 환경에서 되는 것과 안 되는 것

| 도구 | Skill 대응 | 상태 (9/11 캡처 기준) |
|---|---|---|
| **ChatGPT** | 에이전트 편집 → **「스킬 추가」** | **버튼 확인됨.** 실습 사용 여부는 리허설 C10~C13 |
| **ChatGPT** | 조직 디렉터리 (`Samsung Electronics - DX`) | 사내 공유 중. 사내강사 10차수 재사용 경로 |
| **Gemini** | 에이전트 (내 에이전트 / Marketplace) | 열려 있음. 참조 파일 첨부 여부 확인 |
| Gemini CLI | SKILL.md 직접 읽음 | 실습 제외 |

### Skills가 실습에서 되면

③ 모듈 마무리 15분:
```
① 지시문 7블록 → "SKILL.md로 정리해줘" (노코드 팁)
② name·description 확인
③ 참조 자료(양식, 팀 프로필) 첨부
④ 에이전트에 「스킬 추가」 → 조직 디렉터리 공유
```

### 안 되면

지금 방식 그대로입니다. **지시문을 메모장에 `agent02_prompt.md`로 보관**하고 붙여넣어 씁니다. 만드는 내용은 똑같고 보관 장소만 내 PC입니다.

## 6. MCP — 이건 무엇이고 왜 오늘 안 쓰나

**MCP(Model Context Protocol)** 는 AI가 외부 시스템에 연결되는 표준 통로입니다. 메일, 캘린더, 사내 DB.

| | Skill | MCP |
|---|---|---|
| 무엇 | **어떻게 일할지** 알려줌 | **무엇에 접근할지** 열어줌 |
| 형태 | 지시문 + 자료 파일 | 서버 연결 |
| 누가 | 현업 담당자 | IT·개발 조직 |
| 오늘 | **함** | **안 함** |

오늘 A 모듈에서 뉴스 CSV를 직접 올립니다. MCP가 연결되면 그 파일을 사내 시스템에서 **자동으로 가져옵니다.** 사람이 올리는 단계가 사라집니다.

### 왜 오늘은 안 하나

| 이유 | 내용 |
|---|---|
| 사내 연동 없음 | 9/9 확인 — ERP 연동은 전사 기획 중, 기한 없음. 현재는 로컬 파일 수준 |
| 관리자 권한 | ChatGPT 커스텀 커넥터는 워크스페이스 관리자가 켜야 하고 기본 비활성 |
| 보안 | 사내 데이터가 외부 서버를 경유. 정보보안 검토 대상 |

### 그래도 알아둘 것

**MCP는 "연결하면 편해지는 것"이 아니라 "무엇을 열어줄지 정하는 것"입니다.** 연결되는 순간 AI가 그 시스템 데이터를 읽습니다. 읽기만인지 쓰기도인지, 누가 쓰는지, 어떤 데이터는 절대 안 나가는지를 조직이 정합니다.

오늘 지시문 ⑥번(중단·보안)에 쓴 규칙이 MCP 환경에서는 **훨씬 더 중요해집니다.** 파일을 사람이 골라 올릴 때는 실수해도 그 파일 하나지만, 시스템이 연결되면 범위가 다릅니다.

**사내 환경에서 개인이 외부 MCP를 붙이지 않습니다.** 필요하면 정보보안·IT를 통해 정식 절차로.

## 7. 정리

```
오늘 만든 것          지시문 7블록 + 참조 파일 + 정답 예시
        ↓
이것의 이름            Agent Skill (SKILL.md) — Claude·ChatGPT·Codex 동일 형식
        ↓
보관 방법              Skills 기능(열려 있으면) 또는 내 PC 파일
        ↓
다음 단계 (조직)       MCP로 사내 시스템 연결 — IT·보안과 함께
```

**오늘 배운 건 맨 윗줄입니다.** 지시문이 모호하면 Skill로 등록해도 모호하고, MCP로 연결해도 모호한 결과가 더 빨리 많이 나올 뿐입니다.
