# 시연 로그 — D_analysis

> 도입 15분 시연은 이 순서 그대로 진행합니다.
> 실행 기록: **미실행** — 삼성 계정(ChatGPT Instant / Gemini Flash)에서 9/12 실행 후 "실제 대화" 표를 채웁니다. 아래 기대 응답은 `04_answer/recommend_D.html`(데이터에서 직접 계산한 기준본) 기준입니다.

## 올린 파일
1. `01_data/sales_history.csv` (52행, 10열)
2. `01_data/target_account.md` (해솔호텔 제주 / 호텔 / 신축 120실 + 로비)

## 붙여넣은 프롬프트
`02_prompt/prompt_1.md` 전체 (수정 없이). 클릭 경로: 사이드바 [에이전트] → [만들기] → [지침]에 붙여넣기 → [파일 업로드] 2개 → 저장.

## 첫 메시지
```
sales_history.csv와 target_account.md를 올렸어. 지시문 순서대로 추천 보고서를 만들어줘.
```

## 첫 응답에서 확인할 것
- [ ] "0. 데이터 점검"이 보고서보다 **먼저** 나오는가
- [ ] 전체 합계 **570,258,000원**, 검산 불일치 **0건**이라고 말하는가
- [ ] 추천 TOP 3가 **HX-55T · ST-H1 · BX-65S**이고, 각각에 **근거 행 번호**(6·22·30·47 / 7·23·31·48 / 8·24·32)가 붙는가

## 안 나오면 되묻는 문장
```
합계를 직접 다시 계산해서 버티컬별 소계와 함께 보여줘. 그다음 각 추천에 근거 행 번호를 붙여줘.
```
그래도 합계가 다르면 → `sales_history_소계.csv`로 교체해 다시 올립니다 (코드 실행이 꺼진 환경의 암산 오류).

## 참가자에게 짚어줄 한 문장
"보고서보다 점검이 먼저 나온 걸 보세요. 그리고 추천마다 행 번호가 붙어 있어서 열어 볼 수 있습니다."

## 시연 중 보여줄 두 번째 장면 (3분)
경계 테스트를 즉석에서: 새 대화에서 `target_account.md` 없이 `추천해줘.` → **버티컬을 묻는지** 확인. 묻지 않으면 그 자리에서 ③ 입력 검사 표를 가리키며 "지침에 있는데 왜 안 물었을까"를 참가자에게 던집니다.
