# 업무 상황 (삼성 양식 1-2 원문)

B2B 경로 영업 담당자로서 특정 권역의 여러 파트너사를 관리하여 담당 권역의 시장상황을 점검하던 중, 최근 신규 상업시설, 호텔, 병원, 오피스, 교육시설 등의 개점·이전·신축·리뉴얼이 증가한다는 정보를 입수. 담당자는 언론기사, 지역 미디어, 기업 홈페이지, 시장조사 자료, 상권정보 등을 각각 검색하여 어떤 변화가 일어나고 있는지 확인하고, 이를 담당 파트너사의 영업기회와 연결해야 한다.
→ 담당 권역을 입력하면 시장·상권 정보를 분석하고, 주요 영업기회를 찾아 해당 기회를 수주로 확정시키기 위해 파트너사와 무엇을 논의해야 할지 제안하는 「시장·고객 분석 Agent」를 만든다.

# 케이스 — 작은 시설은 모아야 보입니다

A 모듈과 정반대입니다. **A는 큰 회사 하나를 깊게, B는 작은 시설 여럿을 넓게** 봅니다.

| | A 직판 | B 파트너 |
|---|---|---|
| 대상 | 상장 건설사 1곳 | 권역 내 시설 수십 곳 |
| 신호 출처 | 공시·기업 발표 (전국 단위) | **지역 뉴스·상권정보** |
| 한 건의 크기 | 큼. 한 건이 기회 | 작음. **한 건씩은 의미 없음** |
| 누가 수주하나 | 우리가 직접 | **파트너** |
| 끝나는 곳 | 우리의 Action Plan | **파트너와 논의사항** |

**작은 시설은 공시에 안 뜹니다.** 규모가 작아 지역 뉴스에만 납니다. 그래서 데이터 소스가 다릅니다.
그리고 한 건씩 보면 "카페 하나 열었다"로 끝납니다. **권역 단위로 모아야 "이 상권이 살아나고 있다"가 됩니다.**

여기서 두 가지를 구분해 가르칩니다.

```
기회 목록에 올릴 것  →  규모가 기준 이상 (객실 50실·연면적 3000㎡)
요약에만 쓸 것      →  규모 미달이지만 추세를 보여주는 것 (카페·의원·학원)
```

작은 건을 다 버리면 추세가 사라지고, 다 올리면 파트너가 못 씁니다.

# Input (원문 + 보완)

- 외부 API 연동 됐다는 가정하의 네이버 뉴스 Data API
- API 데이터 예시, 시장조사, 개별 인터넷 Search, 파트너사 통한 정보
- (보완) `district_info.csv` 상권정보 7열 — 기사만으로는 규모·시기가 안 나옴
- (보완) `partner_info.csv`에 `시공가능규모` 추가 — 매칭에 필요

# 가정한 것

- JSON은 네이버 뉴스 검색 API 응답 구조(`lastBuildDate` `total` `items[]`)를 따르되 값은 전부 가상.
- 시설명·파트너사명은 전부 가상. `originallink`는 가상 도메인.
- 파트너 정보에 단가·마진은 넣지 않습니다. 실패 테스트 파일에만 따로 둡니다.
- 규모 하한선(객실 50실·연면적 3000㎡)은 교육용 가정입니다. 삼성 확인 후 교체합니다.
