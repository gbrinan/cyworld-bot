## 모듈 2 — Copilot 에이전트 교육 (60분)

**학습 목표**: ① 에이전트 = "채용하는 디지털 비서" 개념 이해 ② Copilot Studio 핵심 구성요소(Knowledge·Topics·Tools·Channels) 이해 ③ S.T.I.C로 Instruction을 작성하고 첫 에이전트를 만든다

| 시간 | 슬라이드/활동 | 소스 |
|---|---|---|
| 0–8 | **채팅 vs 에이전트** — 매번 GCSE를 다시 쓰는 대신, 프롬프트·지식·규칙을 '고용계약서'로 고정한 것이 에이전트 | 신규 |
| 8–16 | **Copilot Studio 핵심 구성요소** — Agent = Topics + Knowledge + Tools + Channels (레고 블록 비유) | PDF p7 |
| 16–24 | **에이전트 채용 체크리스트 5단계** (핵심 문제 하나·데이터 유형·모델·도구·한계) | PDF p23 |
| 24–34 | **S.T.I.C 프레임워크** — Situation/Task/Intent/Command로 JD(System Instruction) 작성. 예시: "크레인보전부 주간보고 비서" | PDF p24 |
| 34–42 | **RAG & Knowledge Source** — 왜 파일을 '먹여야' 정확해지는가, 권한 상속·감사 추적, 환각 방지(출처 강제·모르면 모른다고 답하기·에스컬레이션) | PDF p15, p22 부근 |
| 42–56 | **따라하기: 10분 에이전트** — CREATE→CONFIGURE→TEST→PUBLISH 4단계. 실습3 품의서 파일을 Knowledge로 연결한 "품의서 검토 비서"를 전원이 함께 생성, 테스트 채팅에서 "이 품의의 구매 사유를 3줄로 요약해" 검증 | PDF p8 + 실습3 |

## 모듈 3 — 실습 ①: 주간 보고서 만들기 (60분)

**시나리오**: 크레인보전부 담당자. 흩어진 메모·완료일·이슈(실습2 Span 불량)를 실습1 서식의 주간보고로 변환하는 **"주간보고 작성 비서"** 에이전트를 만든다.

**사용 파일**: 실습1(서식+실데이터), 실습2(금주 발생 이슈)

| 시간 | 단계 | 내용 |
|---|---|---|
| 0–5 | 브리핑 | 결과물 시연: 완성된 주간보고 초안 미리보기 |
| 5–15 | Step 1. 데이터 위생 | 실습1을 OneDrive/SharePoint 업로드, 파일명 라벨링 규칙(`YYMMDD_과명_주간업무`) — "파일 정리→라벨링→프롬프트" 원칙 |
| 15–30 | Step 2. 에이전트 생성 | S.T.I.C 기반 Instruction 작성 (아래 템플릿 제공). Knowledge에 실습1·2 연결 |
| 30–45 | Step 3. 초안 생성 | 프롬프트: "이번 주(26/8/4주) 완료 업무와 차주 계획을 실습1 서식 그대로 표로 작성. Span 불량 이슈는 '특이사항'란에 3줄 요약" → 반복 대화로 톤·분량 개선 (Iterative) |
| 45–55 | Step 4. 검증 | Human-in-the-Loop: 날짜·담당자·수치 원본 대조 체크리스트. 환각 1개 이상 찾아내기 게임 |
| 55–60 | 회고 | 조별 결과 공유, "내 부서 서식으로 바꾸려면?" |

**제공 Instruction 템플릿 (슬라이드에 전문 게재)**:
```
[Situation] 당신은 크레인보전부의 주간업무 보고 작성 비서다.
[Task] 연결된 주간업무 파일과 이슈 보고서에서 금주 완료/진행 업무, 차주 계획,
       특이사항을 추출해 부서 표준 서식(과명/항목/금주·차주 업무/완료예정일/담당자)의 표로 작성한다.
[Intent] 담당자가 매주 금요일 30분 걸리던 보고 작성을 5분 검토로 줄인다.
[Command] 파일에 없는 내용은 생성 금지, 불확실하면 "(확인 필요)" 표기.
          날짜·담당자 이니셜은 원본 그대로 유지. 존댓말 개조식.
```

## 모듈 4 — 실습 ②: 입찰내역서 분석 + 데이터 분석 교육 (60분)

**시나리오**: 시설관리 담당자가 협력사 제출 입찰내역서(실습4: 지붕교체·보수공사, 자재비/노무비/중기비 세부내역)를 검증·비교 분석한다.

**사용 파일**: 실습4(주), 실습3(보조 — 견적서 교차 검토)

| 시간 | 단계 | 내용 |
|---|---|---|
| 0–10 | 미니 강의: 데이터 분석 기초 | 구조화 데이터에서 Copilot이 잘/못하는 것 — 셀 범위 지정이 품질의 80%(Excel 공식), 표 서식(Ctrl+T)·머리글 정리가 선행 조건. 집계 vs 판단의 구분 |
| 10–20 | Step 1. 데이터 정리 | 실습4 C.세부내역서를 '분석 가능한 표'로: 병합셀 해제, 머리글 1행화, 표 변환 — Copilot in Excel은 Excel 표를 요구함 |
| 20–35 | Step 2. Excel Copilot 대화형 분석 | "합계 상위 5개 공종은?", "노무비 비중이 50% 넘는 항목 강조", "단가×물량 ≠ 금액인 행 찾기"(검산), 자재/노무/중기비 구성비 차트 생성 |
| 35–50 | Step 3. "입찰 검토 비서" 에이전트 | Knowledge에 실습4+실습3 견적서 연결. 프롬프트: "총괄표 기준 견적금액 요약, 세부내역 중 단가가 0인데 금액이 있는 항목, 안전시설물처럼 '식(LS)' 단위라 검증 불가한 항목을 리스크로 분류해 검토 의견서 초안 작성" |
| 50–60 | Step 4. 리스크 리포트 & 검증 | 임원 보고용 1페이지 요약(GCSE의 E: "표+3줄 인사이트") 생성, 수치 3개 샘플 검산 후 제출. 주의 슬라이드: 금액·계약 판단은 사람 승인 필수(모듈 1 표 재등장) |
| — | 심화(시간 여유 시) | Python in Excel/고급 분석 언급, 이상치 탐지 |

**데이터 분석 교육 포인트 (슬라이드 3장)**:
1. **전처리가 8할** — 병합셀·2단 머리글은 AI의 적
2. **집계는 시키고, 판단은 검증한다** — 검산 프롬프트 습관화
3. **범위·기준·형태** 3요소 지정 ("이 범위에서 → 이 기준으로 → 이 형태로")

## 모듈 5 — 실습 ③: 주간보고서 취합·정리 (60분, Power Automate 없이)

**시나리오**: 파트장이 여러 과의 주간보고(실습1 서식 × 과별 사본)와 이슈 보고서(실습2)를 **에이전트만으로** 부서 통합 주간보고로 취합한다. 자동 트리거(Power Automate) 없이 = **SharePoint 폴더를 Knowledge로 물린 에이전트에게 "취합해줘" 한 번**으로 대체하는 설계.

**사전 준비(강사)**: 실습1 서식으로 3개 과(크레인과/전장과/배관과) 가상 주간보고 사본을 SharePoint `주간보고/26년8월1주` 폴더에 배포.

| 시간 | 단계 | 내용 |
|---|---|---|
| 0–8 | 개념: '트리거 없는 자동화' | Power Automate(이벤트 트리거) vs 에이전트(온디맨드 취합) 비교 — 라이선스·유지보수·거버넌스 관점에서 에이전트 방식의 장단점 |
| 8–18 | Step 1. 폴더 설계 | SharePoint 폴더 규칙(`주간보고/YYYY-WW/과명.xlsx`) — 폴더 단위 Knowledge 연결이 핵심. 권한 = 에이전트 답변 범위 |
| 18–35 | Step 2. "취합 비서" 에이전트 | Instruction: "폴더 내 모든 과별 보고서를 읽어 ① 부서 공통 하이라이트 3개 ② 과별 요약(과당 3줄) ③ 지연 항목(완료예정일 경과) ④ 리스크(이슈 보고서 기반) 순서의 통합 보고서 작성. 과별 원본 파일명을 출처로 명시" |
| 35–48 | Step 3. 취합 실행 & 반복 개선 | 1차 초안 → "지연 항목을 표로", "임원용 5줄 버전 추가" 반복. 누락된 과 찾아내기(3개 과가 다 반영됐는가 = 취합 검증의 핵심) |
| 48–55 | Step 4. 배포 | Teams 채널에 에이전트 게시 → 팀원 누구나 "이번 주 통합보고 초안 줘" 사용. 매주 폴더에 파일만 넣으면 되는 운영 루틴 정의 |
| 55–60 | 전체 과정 랩업 | 5시간 요약 맵(이론→에이전트→3개 실무 비서), 부서 적용 액션 아이템 1개씩 선언, 최종 퀴즈/설문 |
