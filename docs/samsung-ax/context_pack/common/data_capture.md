# 화면의 데이터를 표로 가져오기 — 크롤링 없이

> C 모듈(제안자료)은 **외부 포털의 시장 판매가격**이 필요합니다. A·B 모듈도 기사·상권 정보를 밖에서 가져옵니다.
> 사내 웹 환경에서는 크롤러를 돌릴 수 없습니다. **사람이 화면에서 복사해 오고, AI가 표로 정리합니다.**
> 이 문서는 그 세 가지 경로와, 어느 경로로 오든 **같은 헤더로 맞추는 방법**입니다.

---

## 0. 먼저 정하고 갑니다 — 무엇을 가져올 것인가

가져오기 전에 **받을 표의 헤더를 먼저 적습니다.** 이게 순서입니다.

```
[수요처명]  [모델명]  [온라인가격]  [제품spec.]        ← C 모듈이 요구하는 4열
```

헤더를 먼저 정하지 않고 화면부터 긁으면, 화면마다 다른 모양의 정보가 쌓이고 그걸 다시 사람이 정리합니다.
**"무엇을 채울 것인가"가 먼저이고 "어디서 가져올까"가 나중입니다.** 요구조건서(`00_requirement.md`)가 헤더를 들고 있는 이유입니다.

---

## 1. 세 가지 경로 비교

| | ① 화면 텍스트 복사 | ② 화면 캡처 (확장프로그램) | ③ PlayMCP |
|---|---|---|---|
| 준비물 | 없음 | 브라우저 확장프로그램 설치 권한 | 관리자의 MCP 활성화 |
| 가져오는 것 | 글자 | 이미지 | 검색 API 응답 |
| 표 구조 | 깨짐. AI가 복원 | **유지됨** | 구조화돼 있음 |
| 숫자 정확도 | 정확 (글자 그대로) | 오독 위험 (OCR) | 정확 |
| 가격 정보 | 화면에 보이는 대로 | 화면에 보이는 대로 | **없음** (아래 3장) |
| 이 과정에서 | **기본 경로** | 보조 경로 | 실습 제외 |

**기본은 ①입니다.** 아무것도 설치하지 않아도 되고, 숫자가 글자 그대로 넘어옵니다.
표가 복잡해 ①로 뒤섞이면 ②를 씁니다. ③은 3장의 이유로 이 과정에서 쓰지 않습니다.

## 2. 경로 ① 화면 텍스트 복사 — 기본

```
① 브라우저에서 검색 결과 화면을 연다
② 필요한 영역만 드래그해 복사 (Ctrl+C)
     - 전체 선택(Ctrl+A)은 메뉴·광고·푸터까지 다 잡힙니다
     - 목록 10개면 10개만. 스크롤하며 두세 번 나눠 복사해도 됩니다
③ AI 채팅창에 아래 정제 프롬프트를 먼저 쓰고, 그 아래에 붙여넣는다
④ 결과 표를 메모장에 복사 → naver_crawl.csv 로 저장
     (CSV로 저장할 때는 "쉼표로 구분된 표로 출력해줘"라고 요청)
```

### 정제 프롬프트 (그대로 붙여넣기)

```
아래는 내가 웹 화면에서 복사한 텍스트다. 광고·배송비·리뷰수·판매자 홍보문구가 섞여 있다.

다음 규칙으로 표 하나만 만들어라.
- 열은 정확히 이 네 개다: 수요처명 | 모델명 | 온라인가격 | 제품spec.
- 수요처명에는 판매처(쇼핑몰) 이름을 넣는다
- 온라인가격은 숫자만 넣는다 (원, 콤마, "최저가" 같은 말 제거)
- 제품spec.에는 화면에 실제로 적힌 사양만 넣는다 (인치·해상도·밝기 등)
- 화면에 없는 값은 비워 두고 "확인필요"라고 적는다. 추정해서 채우지 않는다
- 같은 모델이 여러 번 나오면 한 줄로 합치고 가격은 최저값을 쓴다
- 판매자 이름·연락처·사업자번호는 표에 넣지 않는다
- 표 아래에 조회 날짜 한 줄을 적는다

--- 복사한 텍스트 시작 ---
(여기에 붙여넣기)
```

**"화면에 없는 값은 비워 둔다"가 이 프롬프트의 핵심입니다.** 이걸 빼면 AI가 밝기·해상도를 그럴듯하게 지어냅니다. 가격 비교표에서 지어낸 사양은 제안 자체를 틀리게 만듭니다.

## 3. 경로 ② 화면 캡처 — 표가 복잡할 때

Awesome Screenshot 같은 브라우저 확장프로그램으로 영역을 캡처해 이미지로 올립니다. AI가 이미지를 읽어 표로 옮깁니다.

```
① 확장프로그램에서 [Capture selected area] 또는 [Capture visible part]
② 이미지를 PC에 저장 (스크롤 캡처를 쓰면 목록 전체가 한 장에 들어갑니다)
③ AI 채팅창에 이미지를 업로드하고 2장의 정제 프롬프트를 함께 보낸다
④ 결과 표를 메모장에 복사 → 저장
```

**반드시 할 것 — 숫자 두 개를 눈으로 대조합니다.**
이미지에서 읽은 숫자는 틀릴 수 있습니다. `729,000`이 `129,000`으로 읽히면 비교표가 통째로 뒤집힙니다.
표가 나오면 **가장 비싼 것과 가장 싼 것 두 줄만** 원본 화면과 맞춰 봅니다. 두 개가 맞으면 나머지도 대체로 맞습니다.

**확인이 필요한 것** — 사내 PC에서 확장프로그램 설치가 되는지, AI 채팅에 이미지 업로드가 되는지.
삼성 시나리오 문서의 "HTML(확장프로그램 활용)"이 이 계열인지도 함께 확인합니다.

## 4. 화면의 형태가 경로를 정합니다

사이트를 고르기 전에 **그 화면이 글자인지 그림인지**를 봅니다. 이게 경로를 정합니다.

```
화면의 글자를 드래그하면 파랗게 잡힌다   →  경로 ① 텍스트 복사
드래그해도 안 잡힌다 (그림이다)          →  경로 ② 화면 캡처
```

한 페이지 안에서도 갈립니다. 상품 가격은 글자인데 상세 설명은 그림인 경우가 흔합니다. **그럴 때는 둘 다 씁니다.** 가격은 복사하고 설명은 캡처합니다.

## 5. 세 사이트, 서로 다른 문제

| 사이트 | 여기서 얻을 것 | 화면 형태 | 경로 | 조심할 것 |
|---|---|---|---|---|
| **삼성닷컴 비즈니스** | **자사 모델 스펙 (정본)** | 스펙 표가 글자 | ① 복사 | B2B 제품은 가격이 "문의"인 경우가 많음 |
| **네이버 쇼핑 검색** | 모델별 시장가 비교 | 목록이 글자 | ① 복사 | 판매처마다 가격이 다름. 판매처명을 함께 적음 |
| **네이버 스마트스토어 상세** | 구성·옵션·판매 조건 | **가격은 글자, 설명은 그림** | ①+② 같이 | 상세 이미지의 스펙은 판매자가 적은 것 |
| **쿠팡** | 소비자가 참고 | 글자 | ① 복사 | **로그인·회원 등급·지역에 따라 값이 다름** |

### 역할을 나눕니다 — 이게 가장 중요합니다

```
스펙의 근거  →  삼성닷컴(자사) · 경쟁사 공식 사이트 · 사내 가격가이드
시장 가격    →  쿠팡 · 네이버 쇼핑 · 스마트스토어
```

**오픈마켓의 상품 설명은 판매자가 쓴 글입니다.** 밝기·해상도·보증 조건이 실제와 다른 경우가 있습니다.
그걸 근거로 "경쟁사 제품은 사양이 낮습니다"라고 제안서에 쓰면 나중에 뒤집힙니다.

| 쓸 것 | 쓰지 말 것 |
|---|---|
| 오픈마켓에서 **가격** | 오픈마켓 설명의 **스펙** |
| 제조사 공식 페이지에서 **스펙** | 제조사 페이지의 권장소비자가를 시장가로 |

정제 프롬프트(2장)에 이 줄을 덧붙입니다.

```
스펙 열에는 제조사 공식 정보만 넣는다.
판매자가 쓴 설명에서 가져온 값이면 "판매자기재"라고 표시한다.
```

### 쿠팡을 쓸 때 한 줄 더

쿠팡 가격은 로그인 여부와 회원 등급에 따라 달라집니다. 표에 조건을 같이 적지 않으면 다음 주에 다시 보고 "값이 틀렸다"고 합니다.

```
온라인가격 옆에 조건을 적는다. 예) 729,000 (비회원가, 2026-09-12 조회)
```

### 자동 수집은 하지 않습니다

쿠팡을 비롯한 오픈마켓은 이용약관에서 프로그램을 이용한 자동 수집을 금지합니다.
**사람이 화면을 보고 필요한 만큼 복사하는 것**과 프로그램으로 대량 수집하는 것은 다릅니다. 이 과정은 앞의 것만 합니다.
수집한 내용을 사외로 재배포하지 않고, 제안 검토용으로만 씁니다.

### 확인하지 못한 것

**작성자 환경에서는 이 세 사이트에 접속할 수 없어 화면 구조를 직접 확인하지 못했습니다.**
위 표는 일반적으로 알려진 구조입니다. 리허설 C15~C19와 함께 **세 사이트를 각각 한 번씩 열어 확인**하고, 다르면 이 표를 고칩니다.
특히 사내 포털에서 쇼핑몰 접속 자체가 차단돼 있을 수 있습니다. 차단되면 시연도 캡처 이미지로 대체합니다.

## 6. 경로 ③ PlayMCP — 가격에는 쓸 수 없습니다

카카오가 공개한 MCP 서버입니다. 네이버 검색 계열 도구를 제공합니다.
**2026-09-12 실제로 조회해 확인한 결과입니다.**

| 있는 것 | 없는 것 |
|---|---|
| 웹문서·뉴스·블로그·카페·지역 검색 | **상품(쇼핑) 검색** |
| 쇼핑 DataLab — 카테고리·키워드의 **트렌드 지수** | **상품 가격** |
| 트렌드의 연령·성별·기기별 분해 | 모델별 사양 |

쇼핑 DataLab이 돌려주는 값은 **상대 지수**입니다. 기간 내 최대값을 100으로 둔 숫자라 원이 아닙니다.
웹문서 검색을 쓰면 설명문에 가격이 **우연히** 섞여 나오기도 합니다. 실제 조회에서 5건 중 1건에만 가격이 있었습니다. 이걸로는 비교표를 못 만듭니다.

여기에 환경 제약이 더해집니다. ChatGPT는 관리자가 MCP를 켜야 하고(기본 꺼짐), Gemini는 Enterprise 등급에서만 됩니다.

**결론 — C 모듈 가격 수집에는 쓰지 않습니다.** 쿠팡·스마트스토어 가격도 여기서는 나오지 않습니다.
다만 A·B Sensing의 **뉴스 수집**에는 맞는 도구입니다. 사내에서 MCP가 열리면 그때 검토할 후보로 남깁니다. 오늘 실습은 더미 데이터로 진행합니다.

## 7. 실습에서는 이렇게 운영합니다

**강사 시연 1회 — 실제 화면으로.** 네이버에서 검색하고, 드래그해 복사하고, 정제 프롬프트로 4열 표를 만드는 것까지 앞에서 한 번 보여 줍니다. 3분이면 됩니다.

**참가자 실습 — 준비된 더미 파일로.** `01_data/naver_crawl.csv`를 씁니다. 세 가지 이유입니다.

1. 40~50명이 동시에 외부 사이트를 열면 화면이 제각각이라 결과를 비교할 수 없습니다.
2. 정답 파일과 대조가 안 되면 검수 훈련이 안 됩니다.
3. 실제 경쟁사 가격을 교육 자료에 남기지 않습니다.

**가르치는 것은 경로가 아니라 순서입니다.** 헤더를 먼저 정하고 → 화면에서 가져오고 → 없는 값은 비우고 → 두 줄을 대조한다. 이 순서는 어느 사이트, 어느 도구에서도 같습니다.

## 8. 가져온 데이터에 붙이는 꼬리표

수집한 표에는 항상 이 두 줄을 답니다. 제안서에 그대로 따라갑니다.

```
조회일: 2026-09-12
출처: 온라인 쇼핑몰 검색 결과 (참고용 시장가. 실제 제안가는 가격가이드와 대조 후 확정)
```

**온라인 가격은 제안 가격이 아닙니다.** 시점에 따라 바뀌고, B2B 조건과 다릅니다.
`security_rules.md`의 확정 가격 금지 규칙이 여기에도 그대로 적용됩니다.

## 9. 막혔을 때

| 증상 | 대응 |
|---|---|
| 복사한 텍스트가 한 줄로 붙는다 | 그대로 둡니다. 정제 프롬프트가 분리합니다 |
| AI가 가격을 지어낸다 | "화면에 없는 값은 확인필요로 두라"를 한 번 더 강조해 다시 요청 |
| 표 열이 4개가 아니다 | "열은 정확히 네 개다"를 다시 보내고 재출력 요청 |
| 이미지 업로드가 막혀 있다 | 경로 ①(텍스트 복사)로 전환 |
| 확장프로그램 설치가 막혀 있다 | 경로 ①로 전환. 이 과정은 ①만으로 완결됩니다 |
| 사이트 접속 자체가 막혀 있다 | 실습은 더미 파일로 진행. 시연도 캡처 이미지로 대체 |
| 상세 설명을 드래그해도 안 잡힌다 | 그림입니다. 경로 ②로 캡처 (4장) |
| 같은 모델인데 사이트마다 가격이 다르다 | 정상입니다. 판매처명과 조회 조건을 함께 적습니다 (5장) |
| 경쟁사 스펙이 사이트마다 다르다 | 제조사 공식 페이지를 따릅니다. 오픈마켓 설명은 근거로 쓰지 않습니다 (5장) |
