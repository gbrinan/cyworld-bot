## 0. 설계 원칙 — "컨텍스트는 데이터다"

교안은 **방법론 슬라이드 + 에이전트 골격 + 컨텍스트 데이터 팩**의 3층으로 만든다. 팀·업무·도구에 관한 맥락은 프롬프트나 슬라이드 본문에 박지 않고 **파일(데이터)로 분리**한다.

| 층 | 내용 | 팀별로 바뀌는가 |
|---|---|---|
| ① 방법론 슬라이드 | Agent 개념, IPO 명세, 지시문 블록, 테스트 3종, 사람 승인 | 아니오 (공통) |
| ② 에이전트 골격 | 3개 Agent의 지시문 템플릿, 출력 양식, STOP 규칙, 검수 기준 | 아니오 (공통) |
| ③ 컨텍스트 데이터 팩 | 업무상황(비즈니스 Context), Input 더미데이터(엑셀 컬럼 헤더), 양식, 테스트 케이스 | **예 (B2B팀 / B2B유통전략팀)** |

삼성 측이 9/3 메일에 첨부한 **양성과정 결과물 정리표**의 열이 정확히 이 구분과 일치한다: `최종 실습주제 / 업무상황(비즈니스 Context) / Input 더미데이터 스펙(Excel 상세 컬럼 헤더 정의) / AI Agent 상세 활용 내용(Agent의 형태) / Output 최종 결과물(교육생 산출 서식)`. 따라서 데이터 팩의 매니페스트를 이 표 형식 그대로 만들면 양성과정 결과물 정리가 곧 데이터 팩 인덱스가 된다.

9/7 사전 모임 슬라이드(STEP 3)도 같은 결론을 담고 있다: **"팀별 주제와 자료는 달라도 제안자료 Agent의 기본 틀은 공통"**, 공통은 프롬프트·출력·검수 기준, 팀별은 고객·제품 정보. 즉 삼성도 이미 "골격은 공통, 컨텍스트는 팀별 데이터"로 생각하고 있다.

컨텍스트를 데이터로 다루는 네 가지 규칙:
1. **팀 프로필은 `team_profile.md`로.** 9/4 메일의 경로·품목·관리항목을 그대로 구조화해 GPT 프로젝트 파일 / NotebookLM 소스 / Gemini 에이전트 참조 파일로 넣는다.
2. **더미 데이터는 엑셀 컬럼 헤더부터 정의.** 사전과제 양식이 "필요 엑셀 컬럼 헤더 구상"을 요구하므로, 후보 강사가 낸 헤더를 그대로 스키마로 채택한다.
3. **Agent 간 인계물도 파일로.** 영업 여정 통합 시나리오에서 ②의 출력이 ③의 입력, ③의 출력이 ④의 입력이 되므로, 인계물(`customer_profile.md`, `proposal_draft.md`)을 파일로 저장해 다음 Agent에 업로드한다. 도구가 달라도(Gemini↔GPT) 파일로 이어진다.
4. **사전과제도 데이터로.** 후보 강사 17명의 사전과제 응답을 표로 모아 핏코치(Agent-Task Fit) 판정 → 시범강의 주제 4개 선정 → 더미 데이터 생성 입력으로 재사용한다.

## 1. 확정 제약

### 1.0 접속 방식 — 웹 포털
사내 환경은 **브라우저에서 사내 포털을 통해 ChatGPT·Gemini를 불러 쓰는 방식**입니다. 데스크톱 앱, CLI, API, 설치형 도구는 쓰지 않습니다.

이 전제가 설계에 주는 제약이 네 가지입니다.

| 제약 | 대응 |
|---|---|
| AI가 만든 파일의 다운로드가 막힐 수 있음 | 결과를 화면 텍스트로 받아 **복사해 저장**하는 절차를 교안에 명시. 지시문 ⑤블록에 "파일 첨부가 아니라 화면에 출력" 추가 |
| 파일 업로드가 막힐 수 있음 | 모든 데이터의 **마크다운 표 버전**(`paste/`)을 동봉. 최대 6KB로 붙여넣기 가능 |
| 코드 실행(데이터 분석)이 안 될 수 있음 | ④ 모듈용 **소계본**(`*_소계.csv`) 동봉. 세 축 합계가 상세와 일치하도록 검산되어 정합성 학습은 그대로 성립 |
| 세션이 끊기면 지시문이 사라짐 (Gems 불가와 겹침) | 지시문을 로컬 `agent*_prompt.md`로 보관하는 절차. 이것 자체가 "컨텍스트를 데이터로" 원칙의 실천 |

**Skill 기능 — 확인이 필요한 기회 요인**

ChatGPT의 **Skills**는 지시문과 참조 자료를 묶어 등록·공유하는 기능으로, Business·Enterprise·Edu에 제공되며 Enterprise는 2026년 7월부터 자동 활성화된 것으로 알려져 있습니다. 8/18 안내에는 언급이 없었지만 **시기상 이미 열려 있을 수 있습니다.**

이 과정이 만드는 「지시문 7블록 + 참조 파일」이 곧 Agent Skill의 구조(SKILL.md + 자료)이므로, 열려 있다면 다음이 달라집니다.

| | Skills 없음 | Skills 있음 |
|---|---|---|
| 산출물 보관 | 교육생 개인 PC의 메모장 파일 | 워크스페이스에 등록·공유 |
| 사내강사 10차수 | 강사마다 지시문 재작성 | **같은 Skill로 동일 품질** |
| 교육 후 전파 | 구두 인수인계 | 팀에 공유 |

**따라서 리허설에서 가장 먼저 확인할 항목에 Skills를 추가했습니다.** 열려 있으면 ③ 모듈 마무리에 등록 실습 15분을 붙입니다. 안 열려 있으면 현재 설계(메모장 보관) 그대로이며, 만드는 내용은 동일합니다.

**MCP는 실습에서 제외합니다.** ChatGPT는 워크스페이스 관리자가 켜야 하고 기본 비활성이며, 일반 Gemini 앱은 커스텀 MCP를 지원하지 않습니다. 8/18 안내의 플러그인 사용 불가와도 같은 관리 체계입니다. 개념 3장(S40b~d)으로만 다루고, 사내 환경에서 개인이 외부 MCP를 연결하지 않는다는 점을 ① 모듈 보안 내용과 연결해 짚습니다.

네 가지가 모두 막혀도 붙여넣기와 복사만 되면 과정은 완주됩니다. 실제 가능 여부는 9/12 리허설(`samsung-ax/rehearsal_checklist.md`)에서 확인하며, **파일 업로드 / 코드 실행 / Gemini 에이전트 참조 파일** 세 가지가 슬라이드 4장과 실행 절차를 좌우합니다.

### 1.5 삼성 측 양식 (9/3 첨부 이미지)
- **사전과제 「내가 생각하는 Best AX 실습주제」**: 목적은 *B2B 영업 사원의 영업 여정(Sensing→Action→Analysis)을 1개 시나리오로 통합 설계*. 행은 3개 Agent + ★통합 연계 시나리오(영업 여정 Best 1), 열은 `제안 실습 업무 및 품목(실무 상황)` / `선택 이유 및 필요 데이터 구상(현업 애로, 필요 엑셀 컬럼 헤더)`. 예시: "민수 시장 00기업 EPP몰 개설 영업 (뉴스센싱→입점 제안서→업셀링 실적)". 작성 기준: 정답 없음, 실무에서 해볼 가치 최우선, 정보수집→제안서→실적분석이 하나로 연결. 팀별 Workflow 리스트와 AX T/F 과제 리스트는 별도 파일로 공유 예정.
- **양성과정 결과물 정리표**: 3개 Agent × (최종 실습주제 / 업무상황 / Input 더미데이터 스펙 / Agent 형태 / Output 결과물).
- **제안자료 Agent 공동 설계 슬라이드(STEP 3)**: 공통으로 정할 것 ① 제안서 순서 = 회사소개 → 제안내용 → 제품소개 → 유지보수, ② Agent 종류 = **Gemini 에이전트로 제안서 제작**, ③ 공통 = 프롬프트·출력·검수 기준 / 팀별 = 고객·제품 정보.

## 3. 본 과정 교안 설계 (강사 담당 6시간)

### 3.1 영업 여정 통합 시나리오 (팀당 1개)
사전과제 목적이 "1개 시나리오로 통합 설계"이므로, 팀당 시나리오 1개에서 3개 Agent가 파일로 이어지도록 설계한다. 아래는 9/7 슬라이드의 후보 예시를 기준으로 한 초안이며, 9/8 전달 자료로 확정한다.

```
B2B팀 — 수요처 AX전략 기반 NBM Lead 발굴
  ② Sensing : 업종 뉴스·투자 동향 + 고객 업무 과제 → customer_profile.md (도입 가능성·Lead 후보)
  ③ Action  : customer_profile.md + 제품 카탈로그 → proposal_draft.md (회사소개→제안→제품→유지보수)
  ④ Analysis: Lead·BO 파이프라인 xlsx + proposal 결과 → 진행 단계·매출 예상·전환 보고서
```

인계 규칙: 각 Agent의 출력물은 반드시 파일로 저장해 다음 Agent에 업로드한다. 앞 단계를 못 끝낸 참가자를 위해 팩에 **정답 인계물(`handoff/`)**을 동봉해 다음 모듈에서 바로 시작할 수 있게 한다(50명 규모 진도 편차 대응).

### 3.2 Agent별 도구 배분과 재사용 자산
| 모듈 | 주 도구 | 대체 경로 | 재사용할 기존 자산 |
|---|---|---|---|
| ② Sensing | **Gemini** Deep Research(1인 1회) + NotebookLM | GPT 프로젝트 + 웹검색 | 삼성 GPTS 영업비서 교안의 고객사 분석·페르소나 프롬프트, 제안커리큘럼의 수집→정규화 흐름 |
| ③ Action | **Gemini 에이전트** + 참조 파일 (삼성 지정) | GPT 프로젝트(+GPTs) | 삼성 GPTS 영업비서 교안의 S.T.I.C JD, 가톨릭대 교안의 지시문 블록·지식파일 규칙 |
| ④ Analysis | **GPT** 데이터 분석(파일 업로드) + 프로젝트 | Gemini Flash 파일 분석 | 제안커리큘럼의 감성분석·대시보드·전략보고서 흐름(바이브코딩 제외), 삼라 Gemini 주간보고 패턴 |

비중은 Gemini 4h : GPT 2h. "Gemini 100%" 요구가 확정되면 ④를 Gemini 경로로 바꾸고 GPT는 참고로만 남긴다. 데이터 팩은 도구 중립이므로 슬라이드의 도구 화면 페이지만 교체하면 된다.

공통 방법론(세 모듈 동일): **IPO 명세 → 참조 파일(데이터) 연결 → 지시문 → 테스트 3종(정상·경계·실패) → 사람 승인 지점 → 다음 Agent로 인계**. 가톨릭대·동국대 교안 구조를 가져오되 대학 행정 예시를 B2B 영업 예시로 치환한다.

## 6. 사전과제 — 삼성 양식 + 추가 안내

삼성 양식은 그대로 쓴다. 다음 두 가지만 별도 안내로 붙인다.

1. **엑셀 컬럼 헤더 작성 예시**를 팀별로 1개씩 제공해 헤더 수준을 맞춘다(예: `고객사명, 업종, 규모, 최근 투자 뉴스 일자, 도입 검토 단계, 예상 규모(대), 담당 경로`).
2. **구현 방식 선택 메뉴**(강제 아님): 도구 = GPT 프로젝트 / GPTs / Gemini 에이전트 / NotebookLM / Deep Research, 결과물 = 표 / 보고서 초안 / 제안서 초안 / HTML. 사전과제에서는 희망만 표시하고 확정은 교육 중 강사와 한다.

응답 처리 흐름: 17명 응답 → 표로 취합(팀, Agent, 업무 문장, 헤더, 애로) → 핏코치 판정 → 팀별 통합 시나리오 1개 확정 + 시범강의 주제 4개 선정 → 더미 데이터 스키마 확정.
