# 일을 쪼개는 법 — 에이전트를 만들기 전에 하는 일

> **이 과정의 첫 번째 시간입니다.** 지시문 7블록보다 먼저 옵니다.
> 에이전트를 못 만드는 이유는 프롬프트를 못 써서가 아니라, **무엇을 시킬지 정하지 않았기 때문**입니다.
> 여기서 나온 분해표가 그대로 지시문이 됩니다. 4장에 그 대응이 있습니다.

---

## 0. 순서

```
① 한 문장으로 적는다      "고객 요구조건을 받아 제안 자료를 만든다"
② 동사로 쪼갠다           내가 실제로 하는 손동작 5~10줄
③ 줄마다 꼬리표를 붙인다   🔒 사람만 / ✍️ AI 초안 / ⚙️ AI 반복 / 🔌 밖에서 가져옴
④ 묶는다                 붙어 있는 ✍️⚙️ 줄들 = 에이전트 1개
⑤ 번역한다               묶음 → 지시문 7블록
```

**쪼개기가 끝나면 에이전트 개수와 경계가 이미 정해져 있습니다.** 남은 것은 옮겨 적는 일입니다.

---

## 1. ① 한 문장으로 적기

주어는 나, 목적어는 결과물, 동사는 하나입니다.

```
○  고객 요구조건을 받아 제안 자료를 만든다
○  과거 판매 실적을 보고 신규 수요처에 맞는 제품을 고른다
✗  영업을 효율화한다              ← 결과물이 없습니다
✗  AI로 업무를 자동화한다          ← 무슨 일인지 없습니다
```

한 문장이 안 나오면 아직 일이 하나가 아닙니다. 두 개로 나눠 각각 적습니다.

---

## 2. ② 동사로 쪼개기

**지금 이 일을 할 때 손이 움직이는 순서**를 적습니다. 머릿속에서 하는 일도 한 줄로 셉니다.

규칙 세 가지입니다.

- 한 줄에 동사 하나. "찾아서 정리한다"는 두 줄입니다.
- 5~10줄이면 적당합니다. 3줄이면 너무 뭉쳤고, 20줄이면 너무 잘게 갔습니다.
- **잘 하는 사람이 아니라 지금 내가 하는 대로** 적습니다. 이상적인 절차를 적으면 실제와 안 맞습니다.

---

## 3. ③ 꼬리표 붙이기

줄마다 네 가지 중 하나를 답니다. 이게 분해의 핵심입니다.

| 꼬리표 | 뜻 | 판단 기준 |
|---|---|---|
| 🔒 **사람만** | AI에게 넘기지 않는다 | 대외 확정, 가격·납기, 책임이 따르는 판단, 승인 |
| ✍️ **AI 초안** | AI가 쓰고 사람이 검수 | 매번 내용이 달라지고 판단이 섞임 |
| ⚙️ **AI 반복** | 규칙이 고정되어 매번 같다 | 형식 변환, 추출, 집계, 정렬 |
| 🔌 **밖에서 가져옴** | 사람이 가져와 올린다 | 사내 시스템, 외부 사이트, 파일 |

**꼬리표가 헷갈리면 이렇게 묻습니다.** "이 줄이 틀렸을 때 누가 책임지는가." 내가 책임지면 🔒입니다.

---

## 4. ④ 묶기 — 여기서 에이전트 개수가 정해집니다

```
붙어 있는 ✍️ ⚙️ 줄들       →  에이전트 1개
🔒 줄                     →  에이전트 경계. 여기서 사람에게 넘긴다
🔌 줄                     →  입력 파일. 에이전트 안이 아니라 앞에 놓인다
```

**🔒가 중간에 끼면 거기서 잘립니다.** 한 업무에 에이전트가 여러 개인 이유가 이것입니다.
하나로 묶으면 사람이 확인해야 할 지점을 AI가 지나쳐 버립니다.

---

## 5. ⑤ 번역 — 분해표가 지시문이 됩니다

묶음 하나가 지시문 하나입니다. 자리가 정해져 있습니다.

| 분해표에서 | 지시문 7블록에서 |
|---|---|
| 묶음이 하는 일을 한 문장으로 | ① 역할 |
| 묶음에 들어간 줄 / 안 들어간 줄 | ② 업무 범위 (하는 일 / 하지 않는 일) |
| 🔌 줄이 만든 파일 | ③ 입력 검사 |
| 묶음 안의 줄들, 순서 그대로 | ④ 처리 순서 |
| 묶음의 마지막 줄이 내놓는 것 | ⑤ 출력 형식 |
| 묶음 **바로 뒤**의 🔒 줄 | ⑥ 중단 · ⑦ 사람 승인 |

**"하지 않는 일"은 지어내는 것이 아닙니다.** 분해표에서 이 묶음에 안 들어간 줄이 그대로 들어갑니다.

---

## 6. 해 보기 — C 모듈 (제안자료 작성)

### ① 한 문장
고객 요구조건을 받아 제안 제품 3가지를 고르고 비교 자료를 만든다.

### ②③ 쪼개고 꼬리표 붙이기

| # | 내가 하는 일 | 꼬리표 |
|---|---|---|
| 1 | 고객 메일에서 화면크기·용도·기능·설치환경·수량·예산을 뽑아 적는다 | ✍️ |
| 2 | 네이버·쿠팡·삼성닷컴에서 시장가와 경쟁 제품을 찾아본다 | 🔌 |
| 3 | 찾은 화면을 정리해 표로 만든다 | ⚙️ |
| 4 | 가격가이드 엑셀에서 조건에 맞는 모델을 추린다 | ⚙️ |
| 5 | 추린 모델과 경쟁 제품의 스펙·가격을 비교한다 | ✍️ |
| 6 | 제안 3안을 고르고 비교표를 만든다 | ✍️ |
| 7 | 제안 가격과 납기를 확정한다 | 🔒 |
| 8 | 팀장 승인을 받아 고객에게 보낸다 | 🔒 |

### ④ 묶기

```
 2번 🔌                    →  입력 파일 (사람이 화면에서 가져옴)
 3번 ⚙️                    →  프롬프트 ⓪  수집 정제
 1·4번 ✍️⚙️                →  프롬프트 ①  요구조건 분석 + 모델 추출
 5·6번 ✍️                  →  프롬프트 ②  비교 + 3안 제안
 7·8번 🔒                  →  ⑥ 중단 · ⑦ 승인  ("확정 견적서는 만들지 않는다")
```

**C 모듈의 프롬프트가 세 개인 이유가 여기서 나왔습니다.** 우리가 정한 것이 아니라 일이 그렇게 생겼습니다.
실패 테스트("확정 견적서 만들어줘")가 7번 줄인 것도 마찬가지입니다.

---

## 7. 해 보기 — D 모듈 (데이터 분석)

| # | 내가 하는 일 | 꼬리표 | 어디로 갔나 |
|---|---|---|---|
| 1 | 실적 엑셀을 연다 | 🔌 | 입력 파일 |
| 2 | 숫자가 맞는지 훑어본다 (합계·빈칸) | ⚙️ | ④-0 데이터 점검 |
| 3 | 대상 수요처의 버티컬을 확인한다 | ✍️ | ④-1 |
| 4 | 같은 버티컬만 필터한다 | ⚙️ | ④-2 |
| 5 | 모델별로 수량·금액을 더한다 | ⚙️ | ④-2 |
| 6 | 반복해서 같이 팔린 조합을 찾는다 | ✍️ | ④-2 |
| 7 | 추천 3개를 고른다 | ✍️ | ④-3 |
| 8 | 왜 이 제품인지 근거를 붙인다 | ✍️ | ④-4 |
| 9 | 가격·수량을 가격가이드와 대조해 확정한다 | 🔒 | ⑦ 확인 필요 사항 |
| 10 | 고객에게 제안한다 | 🔒 | ⑦ |

2~8번이 붙어 있어 **에이전트 1개**입니다. 그래서 D는 프롬프트가 하나입니다.

**2번을 빼면 어떻게 되는지가 이 모듈의 시험입니다.** 실제로 사람도 자주 건너뜁니다. 건너뛰면 틀린 숫자로 만든 추천이 나옵니다.

---

## 8. 쪼갠 뒤에 고르는 기준 — 다 만들지 않습니다

분해표가 나왔다고 전부 에이전트로 만들지 않습니다. 첫 번째로 만들 것은 이 셋을 다 만족하는 묶음입니다.

1. **자주 한다** — 주 1회 이상. 1년에 두 번 하는 일은 만드는 시간이 더 듭니다.
2. **입력이 파일로 손에 있다** — 사내 시스템에 로그인해야 보이는 것은 지금은 안 됩니다.
3. **틀려도 되돌릴 수 있다** — 초안이라 사람이 고치면 되는 것.

셋 중 하나라도 아니면 다음 것으로 넘어갑니다. `fit_check.md`의 CANNOT 7항목과 함께 봅니다.

## 9. 워크북에 쓰는 빈 표

내 업무로 옮길 때 이 표를 채웁니다.

```
① 한 문장 : ________________________________________________

②③ 쪼개기
   1. ____________________________  [ 🔒 / ✍️ / ⚙️ / 🔌 ]
   2. ____________________________  [ 🔒 / ✍️ / ⚙️ / 🔌 ]
   3. ____________________________  [ 🔒 / ✍️ / ⚙️ / 🔌 ]
   4. ____________________________  [ 🔒 / ✍️ / ⚙️ / 🔌 ]
   5. ____________________________  [ 🔒 / ✍️ / ⚙️ / 🔌 ]
   6. ____________________________  [ 🔒 / ✍️ / ⚙️ / 🔌 ]
   7. ____________________________  [ 🔒 / ✍️ / ⚙️ / 🔌 ]

④ 묶기  : 에이전트 ___개
   에이전트 1 = ___번 ~ ___번
   경계(🔒) = ___번
   입력(🔌) = ___번

⑤ 첫 번째로 만들 것 : 에이전트 ___   (8장 기준 3개를 다 만족하는가 □)
```

강사는 이 표를 걷어서 봅니다. **꼬리표가 전부 ✍️인 사람은 아직 쪼개지 않은 것입니다.** 🔒이 하나도 없으면 위험 신호입니다.
