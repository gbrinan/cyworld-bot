# HD현대중공업 Microsoft Copilot 실무 교육 (5H) — 교안 설계 & 클로드 디자인 핸드오프 문서 (v2)

> **용도**: 클로드 디자인(슬라이드/교안 시각화) 핸드오프용 스펙 문서.
> Microsoft 공식 문서(Microsoft Learn) 기준을 따르며, 업로드된 실습파일 4종을 실습 소재로 사용한다.
> **v2 변경**: 고객사 검수 관점 비판 반영 — 사전 점검 체크리스트, 플랜 B, 오버셰어링 교육, 운영 시간표, 성과 측정 설계 추가. 내부 제작 메모(콘텐츠 재활용 표 등)는 부록 D로 분리(고객 제출본에서 제외).

## 0-1. 사전 점검 체크리스트 (계약~D-1) ★ 실행 보증 장치

교육 성립의 전제조건. **하나라도 미충족 시 해당 모듈은 플랜 B(부록 B)로 전환**하며, D-7 상태 점검 회의에서 확정한다.

### A. 라이선스·계정 (책임: 고객사 IT / 확인: 강사측, D-14)
- [ ] 수강생 전원 **Microsoft 365 Copilot 유료 라이선스** 보유 여부 명단 대조
- [ ] **Copilot 에이전트 빌더 활성화** 여부 (테넌트 관리자 설정에서 에이전트 생성 허용 확인)
- [ ] Copilot Studio 사용 여부 결정 (미보유 시 전 실습은 에이전트 빌더 경로로 확정 — 실습 3~5는 두 경로 모두 지원하도록 설계됨)
- [ ] 무라이선스 수강생 파악 → **2인 1조 페어링 명단** 사전 작성 (플랜 B-1)

### B. 보안·거버넌스 (책임: 고객사 보안팀 / 요청: 강사측, D-14)
- [ ] 실습파일 4종의 사내 반입·SharePoint 업로드에 대한 **보안팀 사전 승인** (파일은 비식별본임을 명시해 제출)
- [ ] 실습용 **격리 SharePoint 사이트** 개설 (기존 부서 사이트에 얹지 않음 — 오버셰어링 원천 차단, 교육 후 D+30 삭제 약정)
- [ ] 사외 강사·TA용 **게스트 계정 또는 임시 계정** 발급 (승인 리드타임 감안, D-14 신청)
- [ ] "교육 중 실데이터 업로드 금지, 제공된 실습파일만 사용" 수강생 안내문 확정

### C. 환경·리허설 (책임: 강사측 + 고객사 IT, D-1)
- [ ] **D-1 오후 리허설**: 실습용 SharePoint에 모듈 5용 3개 과 가상 주간보고 업로드 → **인덱싱 완료를 실제 질의로 확인** (Knowledge 인덱싱은 수 시간~1일 소요될 수 있으므로 당일 업로드 금지)
- [ ] 강사 계정으로 실습 3·4·5 전 과정 1회 완주 (에이전트 생성→게시→질의)
- [ ] 교육장 네트워크에서 M365 접속·Copilot 응답 속도 확인
- [ ] 플랜 B 파일 세트(부록 B) USB/사이트 양쪽 배치
- [ ] Copilot 분량 한계 수치(요약/Rewrite)를 **Microsoft 지원 문서 최신값으로 재확인 후 슬라이드 확정** — 미확인 수치는 슬라이드에 싣지 않는다

### D. 콘텐츠 확정 (책임: 강사측, D-7)
- [ ] HD현대 **CI 가이드 수령 후** 브랜드 컬러·로고 적용 (임의 색상 추정 금지)
- [ ] 고객사 커스텀 예문 반영분(자사 서식 교체 등) 최종 검수

## 모듈 1 — Copilot 이론 교육 (60분)

**학습 목표**: ① 외부 LLM vs Copilot vs 사내 LLM의 보안 경계를 구분해 도구를 선택한다 ② LLM의 확률적 특성과 한계를 이해한다 ③ GCSE 프레임워크로 프롬프트를 작성한다

| 시간 | 슬라이드/활동 |
|---|---|
| 0–5 | 오프닝: "조선소의 하루에서 Copilot이 끼어드는 지점" — 주간보고·품의·입찰 3장면 예고 |
| 5–15 | **사내 vs 외부 LLM 비교표** + 기밀등급별 도구 선택. HD현대 맥락 토론: 도면·수주정보·선주사 정보는 어디까지? |
| 15–22 | **AI는 확률적 생성기** — N회 생성 편차, Human-in-the-Loop 표(회의록/주간보고/외부메일/계약), 토큰·컨텍스트 윈도우·환각 |
| 22–30 | **비식별화 4원칙**(비식별화·평균화·민감정보 제거·맥락 분절) — Before/After를 조선 예시로: "AA1공장 가소1-2라인 Span 불량" 사례 = 오늘 실습파일이 곧 모범 사례 |
| 30–38 | **오버셰어링과 권한** ★신설 — Copilot은 '내 권한으로 보이는 모든 것'을 답변에 쓴다. 권한 과다 폴더의 위험, 실습이 격리 사이트에서 진행되는 이유, 부서 적용 시 권한 점검이 1순위인 이유 |
| 38–44 | **라이선스 4티어 & Copilot 분량 한계** (수치는 D-1 체크리스트에서 확정한 최신값 게재) |
| 44–52 | **GCSE 프레임워크**(Goal·Context·Source⭐·Expectation) — Microsoft 공식. RACS(범용 AI) 비교. Source 명시 = 품질의 80% |
| 52–57 | **라이브 데모**: 나쁜 프롬프트 vs GCSE — "실습4 입찰내역서 분석해줘" → GCSE 버전 개선 시연 |
| 57–60 | 퀴즈 5문항(Teams 설문) — LLM 비교·보안·분량·비식별화·오버셰어링 |

**공식 문서 근거**: Microsoft Learn "Learn about Copilot prompts", "Data, privacy, and security for Microsoft 365 Copilot".

## 모듈 2 — Copilot 에이전트 교육 (60분)

**학습 목표**: ① 에이전트 = "채용하는 디지털 비서" 개념 ② 핵심 구성요소(Knowledge·Topics·Tools·Channels) ③ S.T.I.C로 Instruction을 작성하고 첫 에이전트를 만든다

**진행 경로**: 사전 점검 A에서 확정한 단일 경로(에이전트 빌더 또는 Copilot Studio)로 **전원 동일하게** 진행한다. 현장 분기 없음.

| 시간 | 슬라이드/활동 |
|---|---|
| 0–8 | **채팅 vs 에이전트** — 매번 GCSE를 다시 쓰는 대신 프롬프트·지식·규칙을 '고용계약서'로 고정한 것이 에이전트 |
| 8–16 | **핵심 구성요소** — Agent = Instruction + Knowledge + (Topics/Tools/Channels) 레고 블록 비유 |
| 16–24 | **에이전트 채용 체크리스트 5단계** (핵심 문제 하나·데이터 유형·모델·도구·한계) |
| 24–34 | **S.T.I.C 프레임워크** — Situation/Task/Intent/Command로 JD(System Instruction) 작성. 예시: "크레인보전부 주간보고 비서" |
| 34–42 | **RAG & Knowledge Source** — 파일을 '먹여야' 정확해지는 이유, 권한 상속·감사 추적, 환각 방지(출처 강제·모르면 모른다·에스컬레이션) |
| 42–56 | **따라하기: 10분 에이전트** — CREATE→CONFIGURE→TEST→PUBLISH. 실습3 품의서를 Knowledge로 연결한 "품의서 검토 비서"를 전원 생성, "이 품의의 구매 사유 3줄 요약" 검증. TA는 뒤처지는 수강생 전담 지원 |
| 56–60 | 오후 실습 3종 예고 + 페어링 조 편성 확인 |

**공식 문서 근거**: Microsoft Learn "Copilot Studio overview", "Build agents with Copilot Studio agent builder", "Knowledge sources overview".

## 모듈 3 — 실습 ①: 주간 보고서 만들기 (60분)

**시나리오**: 크레인보전부 담당자. 흩어진 메모·완료일·이슈(실습2 Span 불량)를 실습1 서식의 주간보고로 변환하는 **"주간보고 작성 비서"** 에이전트를 만든다.

**사용 파일**: 실습1(서식+실데이터), 실습2(금주 이슈) — 격리 사이트에 D-1 업로드·인덱싱 완료 상태

| 시간 | 단계 | 내용 |
|---|---|---|
| 0–5 | 브리핑 | 완성된 주간보고 초안 결과물 시연 |
| 5–12 | Step 1. 데이터 위생 | 파일명 라벨링 규칙(`YYMMDD_과명_주간업무`), "파일 정리→라벨링→프롬프트" 원칙. (업로드·인덱싱은 사전 완료 — 수강생은 확인만) |
| 12–30 | Step 2. 에이전트 생성 | S.T.I.C Instruction 작성(워크북 템플릿 타이핑), Knowledge에 실습1·2 연결. **TA 순회 지원, 15분 경과 시 미완료자는 강사 공유 에이전트에 합류(플랜 B-2)** |
| 30–45 | Step 3. 초안 생성 | "이번 주(26/8/4주) 완료 업무·차주 계획을 서식 그대로 표로. Span 불량은 특이사항란에 3줄 요약" → Iterative 개선 |
| 45–55 | Step 4. 검증 | Human-in-the-Loop 체크리스트로 날짜·담당자·수치 원본 대조. "환각 1개 이상 찾기" 게임 |
| 55–60 | 회고 | 조별 공유, "내 부서 서식으로 바꾸려면?" |

**Instruction 템플릿 (워크북·슬라이드 전문 게재)**:
```
[Situation] 당신은 크레인보전부의 주간업무 보고 작성 비서다.
[Task] 연결된 주간업무 파일과 이슈 보고서에서 금주 완료/진행 업무, 차주 계획,
       특이사항을 추출해 부서 표준 서식(과명/항목/금주·차주 업무/완료예정일/담당자)의 표로 작성한다.
[Intent] 담당자가 매주 금요일 30분 걸리던 보고 작성을 5분 검토로 줄인다.
[Command] 파일에 없는 내용은 생성 금지, 불확실하면 "(확인 필요)" 표기.
          날짜·담당자 이니셜은 원본 그대로 유지. 존댓말 개조식.
```

## 모듈 4 — 실습 ②: 입찰내역서 분석 + 데이터 분석 교육 (60분)

**시나리오**: 시설관리 담당자가 협력사 제출 입찰내역서(실습4: 자재비/노무비/중기비 세부내역)를 검증·비교 분석한다.

**사용 파일**: 실습4 — **원본 + 전처리 완료본(★플랜 B-3) 2종 배포**. 실습3 견적서는 교차 검토 보조.

| 시간 | 단계 | 내용 |
|---|---|---|
| 0–10 | 미니 강의: 데이터 분석 기초 | Copilot이 잘/못하는 것 — 셀 범위 지정이 품질의 80%, Excel 표(Ctrl+T)·1행 머리글이 선행 조건. **집계는 시키고 판단은 검증한다** |
| 10–20 | Step 1. 데이터 정리 | 세부내역서 병합셀 해제·2단 머리글 1행화·표 변환을 **강사와 함께 5분 데모** → 각자 시도. **10분 경과 시 전처리 완료본으로 전원 전환**(여기서 시간을 태우지 않는 것이 원칙) |
| 20–35 | Step 2. Excel Copilot 대화형 분석 | "합계 상위 5개 공종", "노무비 비중 50% 초과 항목 강조", "단가×물량≠금액 행 찾기"(검산), 비목 구성비 차트 |
| 35–50 | Step 3. "입찰 검토 비서" 에이전트 | Knowledge에 실습4(+실습3 견적서) 연결. "총괄표 기준 견적금액 요약, 단가 0인데 금액 있는 항목, '식(LS)' 단위라 검증 불가한 항목을 리스크로 분류해 검토 의견서 초안 작성" |
| 50–60 | Step 4. 리스크 리포트 & 검증 | 임원 보고용 1페이지 요약(GCSE-E: "표+3줄 인사이트"), 수치 3개 샘플 검산. **금액·계약 판단은 사람 승인 필수**(모듈 1 표 재등장) |

## 모듈 5 — 실습 ③: 주간보고서 취합·정리 (60분, Power Automate 없이)

**시나리오**: 파트장이 여러 과의 주간보고(실습1 서식 × 3개 과 사본)와 이슈 보고서(실습2)를 **에이전트만으로** 부서 통합 주간보고로 취합한다. 자동 트리거(Power Automate) 없이 = **폴더를 Knowledge로 물린 에이전트에 "취합해줘" 한 번**으로 대체.

**사전 준비**: 3개 과(크레인과/전장과/배관과) 가상 주간보고를 격리 사이트 `주간보고/26년8월1주`에 **D-1 업로드·인덱싱 확인 완료**(체크리스트 C).

| 시간 | 단계 | 내용 |
|---|---|---|
| 0–8 | 개념: '트리거 없는 자동화' | Power Automate(이벤트 트리거) vs 에이전트(온디맨드 취합) — 라이선스·유지보수·거버넌스 비교, 각 방식의 한계 |
| 8–16 | Step 1. 폴더 설계 | 폴더 규칙(`주간보고/YYYY-WW/과명.xlsx`), 폴더 단위 Knowledge 연결, **권한 = 답변 범위**(오버셰어링 복습) |
| 16–32 | Step 2. "취합 비서" 에이전트 | Instruction: "폴더 내 모든 과별 보고서를 읽어 ① 부서 하이라이트 3개 ② 과별 3줄 요약 ③ 지연 항목(완료예정일 경과) ④ 리스크(이슈 보고서 기반) 순서로 통합 보고서 작성. 과별 원본 파일명을 출처로 명시" |
| 32–45 | Step 3. 취합 실행 & 검증 | 1차 초안 → "지연 항목 표로", "임원용 5줄 버전" 반복. **취합 검증의 핵심 = 3개 과가 전부 반영됐는가**(누락 과 찾기). 파일 많을 땐 "이번 주 폴더"로 Source를 좁혀 맥락 혼합 방지 |
| 45–52 | Step 4. 배포 | Teams 채널 게시 → "이번 주 통합보고 초안 줘". 매주 폴더에 파일만 넣는 운영 루틴 + **부서 적용 시 보안팀 권한 검토가 선행**임을 명시 |
| 52–60 | 전체 랩업 | 5시간 요약 맵(이론→에이전트→3개 비서), 부서 적용 액션 아이템 1개 선언 → **팔로업 세션의 추적 대상**(부록 C) |
