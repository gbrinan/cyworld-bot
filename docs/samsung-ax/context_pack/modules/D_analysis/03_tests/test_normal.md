# 정상 테스트 — D_analysis

## 입력
- 올리는 파일: `01_data/sales_history.csv`, `01_data/target_account.md`
- 지침: `02_prompt/prompt_1.md` 전체
- 첫 메시지: `sales_history.csv와 target_account.md를 올렸어. 지시문 순서대로 추천 보고서를 만들어줘.`

## 기대 행동
1. `0. 데이터 점검`이 먼저 나온다. 52행, 필수 컬럼 10개 이상 없음, 검산 불일치 0건, 전체 합계 **570,258,000**.
2. 대상 수요처 해솔호텔 제주 / 호텔 / 신축 120실 + 로비. 같은 체인 해솔호텔 부산의 2025-03~04 구매(HX-55T 96 · ST-H1 96 · BX-65S 2)를 언급한다.
3. 호텔 버티컬 판매금액 **390,290,000** (전체의 68.4%).
4. TOP 3 = **HX-55T(축 A 1위) → BX-65S(축 B 1위) → ST-H1(조합 동반)**. 액세서리는 축 후보가 아니므로 **ST-H1이 1·2위에 오면 안 된다.**
   HX-50T는 축 A 2위라 **`대안`으로 빠져야 한다.**
5. 근거: HX-55T는 호텔 5개 수요처 464대, ST-H1은 HX-55T 구매 5건 모두에 같은 수량으로 동반(그중 4건은 같은 달), BX-65S는 호텔 3개 수요처 로비 용도 8대.
6. 영업 제안 Point에 120실 기준 수량(HX-55T 120 + ST-H1 120, 로비 BX-65S 2~4)과 "가격은 확인 필요"가 있다.

## 통과 기준
- [ ] 0번 점검이 보고서보다 먼저
- [ ] 합계 570,258,000 일치
- [ ] TOP 3 순서가 HX-55T → BX-65S → ST-H1
- [ ] HX-50T가 `대안`으로 빠졌다
- [ ] 수량 3줄에 행 번호가 있고 로비 수량이 `추정` 범위로 표시됐다
- [ ] 추천마다 근거 행 번호(예: 6·22·30·47행)와 수치
- [ ] 공급가를 제안 가격으로 쓰지 않음 ("확인 필요")

## 안 되면
- 합계가 다르다 → 암산한 것. "합계를 직접 다시 계산해서 보여줘" 되묻기. 계속 틀리면 `sales_history_소계.csv` + `sales_history_호텔모델별.csv` 두 개로 교체 (소계본만 올리면 추천이 안 나옵니다).
- TOP 3에 MX-85P·KX-55K가 들어온다 → 용도 필터가 빠진 것. 프롬프트 ④-3 확인.
- 근거 행 번호가 없다 → 프롬프트 ④-4를 다시 읽게 하거나 "각 추천에 근거 행 번호를 붙여줘".
