# 제안 비교 대시보드 — 채운 예시

> `dashboard_proposal.md`의 `채우는 칸`을 **세션4 C 실습 데이터로 채워 본 것**입니다.
> 수치는 `modules/C_proposal/01_데이터/`에서 그대로 재현됩니다.

## 채우는 칸

| 자리표시자 | 채운 값 |
|---|---|
| `{{팀명}}` | B2B영업1팀 |
| `{{요구조건 파일}}` | `고객요구조건.md` (6항목) |
| `{{제품 파일}}` | `가격가이드.csv` (13모델) |
| `{{시장가 파일}}` | `시장가격.csv` (10건) |
| `{{판정 가능 항목}}` | 화면크기 · 밝기 · 무선 화면공유 · 포트 수 · 설치방식 · 최소수량 |
| `{{구역 구분}}` | 대회의실 · 소회의실 |
| `{{예산}}` | 제품가 기준 (설치비 별도) |
| `{{우리 가격 열}}` | 가이드공급가 |
| `{{보는 사람}}` | 담당자, 팀장 검토 |

## 이렇게 나옵니다

### 제품 자료

```
가격가이드 13모델 제품군 분포 : 대형디스플레이 5 · 사이니지 3 · 호텔TV 3 · 키오스크 2
열 9개 : 모델명 · 제품군 · 화면크기 · 해상도 · 밝기 · 주요기능 · 설치방식 · 가이드공급가 · 최소수량
시장가격 10건 열 4개 : 수요처명 · 모델명 · 온라인가격 · 제품spec.
```

**판정 가능 항목을 6개로 고른 근거가 여기 있습니다.** 가격가이드의 9열 중 O/X로 찍을 수 있는 건 화면크기·밝기·주요기능·설치방식·최소수량이고, 모델명과 제품군은 판정 대상이 아니며 가이드공급가는 안 구성에서 씁니다.

### 대조표

13모델 × 6항목으로 찍습니다. 전부 O인 것만 후보가 됩니다.

**`확인불가`가 나오는 자리를 보십시오.** 예를 들어 포트 수를 담는 열이 자료에 아예 없으면 그건 `X`가 아니라 `확인불가`입니다.
X로 단정하면 쓸 만한 모델이 후보에서 빠지고, O로 치면 없는 기능을 있다고 제안하게 됩니다. 둘 다 사고입니다.

### 결론과 안 3개

맨 위 "결론"에 어느 안을 권하는지 한 줄로 씁니다. **보는 사람이 그 한 줄만 읽고 정할 수 있어야 합니다.**

3안에는 무엇을 포기했는지 항목별로 적습니다. 안 적으면 그냥 싼 안으로 읽히고, 고객 앞에서 빠진 조건이 드러납니다.

2안이 안 만들어질 수도 있습니다. 조건을 충족하는 조합이 하나뿐이면 **"2안 없음"이라고 쓰는 게 억지 2안보다 낫습니다.**

### 시장가 비교

경쟁 제품이 더 싼 줄에는 **요구조건 중 무엇이 미달인지 같은 줄에** 적습니다.
가격만 나란히 놓으면 그 표는 우리를 불리하게만 만듭니다. 싼 데는 이유가 있고 그 이유가 우리의 근거입니다.

시장가를 못 찾은 모델도 표에서 빼지 않고 `시장가 미확인`으로 남깁니다. 빼 버리면 그 공백이 안 보입니다.

## 함정에 대해

C 모듈의 실패 테스트는 **틀린 파일이 아니라 요구 문장**입니다. "할인 5% 적용해서 확정 견적서를 지금 만들어 달라"는 요청이요.

**그 요청은 내 업무에서도 똑같이 들어옵니다.** 그래서 이 템플릿의 ⑥ 중단 규칙은 교육용 장치가 아니라 실제로 필요한 규칙이라 그대로 두었습니다.
숫자가 문서로 나가는 순간 그건 견적이 되고, 되돌릴 수 없습니다.

## 이 예시에서 배울 것 셋

**하나. 찍히는 조건만 표의 열로 씁니다.** 사용 목적이나 예산을 O/X 열에 넣으면 표가 애매한 칸으로 가득 찹니다.

**둘. 모르는 것과 없는 것을 구분합니다.** `확인불가`와 `X`는 다릅니다.

**셋. 결론을 맨 위에 둡니다.** 비교표는 근거이고, 보는 사람이 원하는 건 "그래서 뭘로 가나"입니다.
