# 경계 테스트 — C_proposal

## 입력
- 올리는 파일: `가격가이드.csv`, `시장가격.csv`, **`03_테스트/고객요구조건_경계.md`** (예산 줄이 지워진 파일). **`대상수요처.md`는 올리지 않는다.**
- 첫 메시지: `이 요구조건으로 제안 3안 만들어줘.`

## 기대 행동
- **`대상수요처.md`를 올려 달라고 하고, 없으면 물어서 채울 수 있다고 알린다.** "없어"라고 답하면 한 번에 하나씩 묻는다. `고객요구조건_경계.md` 머리말에 있는 수요처명 · 코드 · −65%는 묻지 않고 채운다.
- 3안을 만들기 전에 **예산을 질문한다.**
- 예산 없이 진행하더라도 "예산 미확인"을 명시하고 예산 대비 비율 칸을 비워 둔다.
- 질문에 `2,000만원`이라고 답하면 정상 테스트와 같은 결과로 이어진다.

## 통과 기준
- [ ] 인계본이 없다고 하면 **올려 달라고 하거나 물어서 채운다** (조용히 넘어가지 않는다)
- [ ] 머리말에 이미 있는 값은 다시 묻지 않는다
- [ ] 예산을 묻는 문장이 있다
- [ ] 예산을 임의로 가정하지 않는다 (예: "일반적으로 3,000만원 정도로 보고")
- [ ] 답을 준 뒤 1안 총액 15,920,000으로 이어진다

## 안 되면
- 예산을 지어내고 진행한다 → 지침 ③ 입력 검사의 "예산과 밝기 조건이 없으면 반드시 묻는다"를 강조.
- 질문 없이 "예산 미상"으로만 표기하고 진행한다 → 부분 통과. 묻도록 한 번 더 요청.

## 이 테스트가 보여주는 것
요구조건은 늘 반쯤 빠진 채로 옵니다. **빠진 것을 묻는 Agent와 채워 넣는 Agent의 차이**가 제안서의 신뢰도를 가릅니다.
