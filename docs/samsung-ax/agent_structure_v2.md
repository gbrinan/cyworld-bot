## 0. 결론: 4개 Agent

| # | Agent | 구분 | 대상 | 산출 형식 |
|---|---|---|---|---|
| **A** | 시장·고객 분석 (Sensing) — **Agent 3개** | **업종별** | B2B팀 (직판 · 상장 건설사) | **HTML 대시보드** |

```

④ 데이터 분석 (2h)      전원 공통 → D
```

양성과정(9/16~17)은 17명이 A와 B를 모두 체험하므로 네 개를 다 다룹니다.

## 1. Agent A — 시장·고객 분석 (B2B팀 직판) — **상장 건설사 케이스**

> 삼성 양식 1-1 + 2026-09-12 강사 지시로 전면 재설계. 상세는 `context_pack/modules/A_sensing_b2b/00_requirement.md`

**대상을 상장 건설사로 잡았습니다.** 신호가 공시로 공개돼 있고, 공시에 공사기간이 들어 있어 **발주 시점을 역산**할 수 있습니다. 건설사가 짓는 현장이 곧 상업시설·호텔·병원·오피스라 한 곳을 뚫으면 현장이 따라옵니다.

**에이전트가 셋입니다.** 일 분해에서 그렇게 나왔습니다.

| | Agent | 하는 일 | 산출 | 도구 |
|---|---|---|---|---|
| **A-1** | 정기 수집 | 구글 뉴스 RSS를 **매주 자동 실행**해 `[품목][헤드라인][원본url][키워드]` 4열로 정리 | `rss_feed.csv` | ChatGPT [예약] + 스킬 저장 |
| **A-2** | Customer Profile | **질문을 던져** 프로파일을 채운다. 아는 것을 붙여넣으면 빠진 것만 묻는다 | `customer_profile.md` | ChatGPT 에이전트 |
| **A-3** | 기회 분석 | Key Signal → Needs → 영업기회 → Action Plan | `dashboard_A.html` | **Gemini** 에이전트 |

**A-2가 이 과정에서 유일하게 "묻는 것이 기능인 Agent"입니다.** 다른 모듈에서 질문은 경계 테스트의 통과 조건이었습니다. 신규 고객 조사는 원래 아는 것부터 적고 모르는 것을 표시해 두는 일이라, 이 Agent는 처음부터 항목을 하나씩 묻습니다.

**Key Signal을 "무슨 일이 있었나"에서 멈추지 않습니다.** 준공 예정일에서 6개월을 빼면 디스플레이 사양이 확정되는 시점이 나옵니다. 그게 Action Plan의 "언제"입니다.

실제 상장사 공시에서 확인한 신호 유형입니다. 회사명과 내용은 교안에서 전부 가상으로 바꿉니다.

| 공시·기사 유형 | 읽어낼 것 |
|---|---|
| 단일판매·공급계약체결 | 현장·계약금액·**공사기간** → 준공일 역산 |
| 유형자산취득결정 | 자가 사옥·시설 투자 |
| 착공·기공식·분양·준공 기사 | 시점 확정 |
| 수주잔고 감소·수익성 악화 | **기회 아님.** 보류로 분류 |

## 2. Agent B — 시장·고객 분석 (B2B유통전략팀 경로) — **작은 시설 케이스**

> 삼성 양식 1-2 + 2026-09-12 강사 지시. 상세는 `context_pack/modules/B_sensing_partner/00_requirement.md`

**A와 정반대입니다.** A는 큰 회사 하나를 깊게, B는 작은 시설 여럿을 넓게 봅니다.

| | A 직판 | B 파트너 |
|---|---|---|
| 대상 | 상장 건설사 1곳 | 권역 내 시설 수십 곳 |
| 신호 출처 | 공시·기업 발표 | **지역 뉴스·상권정보** |
| 한 건의 크기 | 한 건이 곧 기회 | **한 건씩은 의미 없음** |
| 수주 주체 | 우리가 직접 | **파트너** |
| 끝나는 곳 | 우리의 Action Plan | **파트너와 논의사항** |

**작은 시설은 공시에 안 뜹니다.** 지역 뉴스에만 납니다. 그리고 한 건씩 보면 "카페 하나 열었다"로 끝나고, 권역 단위로 모아야 "이 상권이 살아나고 있다"가 됩니다.

그래서 두 갈래로 가릅니다.

```
기회 목록에 올릴 것  →  규모 기준 이상 (객실 50실 · 연면적 3000㎡)
요약에만 쓸 것      →  규모 미달이지만 추세를 보여주는 것 (카페·의원·학원)
```

다 버리면 추세가 사라지고, 다 올리면 파트너가 못 씁니다.

**에이전트가 셋이고, 삼성 양식이 요구한 「제공 프롬프트 3종」과 정확히 맞습니다.**

| | Agent | 하는 일 | 산출 |
|---|---|---|---|
| **B-1** | 키워드 조합 | 권역 × 시설유형 × 상태를 조합해 검색어·RSS 주소 | `search_keywords.md` |
| **B-2** | 기회 추출 | 뉴스 API 응답에서 시설·상태·시기·규모를 뽑고 상권정보와 대조, 우선순위 | `opportunity_list.csv` |
| **B-3** | 파트너 매칭·보고서 | 주력버티컬·시공가능규모로 매칭하고 논의사항까지 | `report_B.md` → Word |

## 3. Agent C — 제안자료 작성 (공통)

> 삼성 양식 2

**업무 상황**
B2B 직판 영업 또는 파트너사를 지원하는 경로 영업 담당자. 고객사로부터 **신규 사무공간·회의실·호텔·매장** 구축을 위한 제품 제안 요청을 받았다. 고객은 정확한 모델명이 아니라 **화면 크기·사용 목적·주요 기능·설치환경·수량·예산** 등 요구조건을 전달했다.

담당자는 요구사항을 검토해 적합한 당사 모델을 찾고, 제안 경쟁력 판단을 위해 외부 포털에서 **시장 판매가격**을 확인하고 **유사 사양 경쟁사 제품과 가격·스펙을 비교**해야 한다. 제품 Line-up과 Spec이 다양하고 가격·경쟁제품 정보를 일일이 검색해야 해서 시간이 많이 걸린다.

| 항목 | 내용 |
|---|---|
| Input (외부) | 네이버 크롤링 — `[수요처명]` `[모델명]` `[온라인가격]` `[제품spec.]` |
| Input (내부) | **B2B 마케팅/가격가이드 Excel (TV 제품)** |
| Agent 활용 | 프롬프트 ① 더미데이터에서 유용한 스펙 추출, 고객 요청 디바이스 정보 분석<br>프롬프트 ② 추출 스펙 기반으로 고객 요청 디바이스 제안 |
| Output | **HTML** (확장프로그램 활용) — 고객 요청과 가장 부합하는 **제안제품 3가지**, 3가지 상호비교 + 시장가격 비교 |

**품목이 TV·디스플레이입니다.** v1의 SAC·모바일 카탈로그는 폐기하고 TV/사이니지 라인업으로 교체합니다.

## 4. Agent D — 데이터 분석 (공통)

> 삼성 양식 3

**업무 상황**
신규 고객 또는 프로젝트에 적합한 제품을 제안해야 한다. 과거 B2B 판매 실적에 **버티컬별·수요처별·제품별 판매 이력**이 쌓여 있으나 일일이 분석해 유사 고객의 구매 패턴과 적합 제품을 찾는 데 시간이 많이 걸린다.
→ 제안 대상 수요처의 **버티컬/업종 특성을 입력하면** 과거 유사 버티컬 판매 데이터를 분석해 ① 어떤 제품이 주로 팔렸는지 ② 어떤 제품 조합이 효과적이었는지 ③ 어떤 제품이 이 수요처에 적합한지를 도출한다.

| 항목 | 내용 |
|---|---|
| Input (사내) | B2B 과거 판매 실적 — `[판매일자]` `[버티컬]` `[수요처]` `[제품군]` `[모델명]` `[공급가]` `[판매수량]` `[판매금액]` `[프로젝트/용도]` `[지역]` |
| Input (분석 대상) | `[수요처명]` `[버티컬]` `[프로젝트/용도]` |
| 처리 | ① 대상 수요처 버티컬 분석 → ② 유사 버티컬 과거 판매 데이터 분석(판매량·판매금액·반복 구매 패턴) → ③ 제품 추천 → ④ **"왜 이 제품인가"를 과거 실적 데이터로 설명** |
| Output | **HTML** — ① 대상 수요처 분석 ② 버티컬별 판매 Insight ③ 추천 제품 TOP 3 ④ 영업 제안 Point |

**"버티컬"이 핵심 축입니다.** v1의 Lead/BO 파이프라인, 파트너 매출 구조는 폐기합니다.

## 6. v1 데이터 팩과의 차이 — 전면 교체 대상

| 영역 | v1 (9/4 작성) | v2 (삼성 확정) | 조치 |
|---|---|---|---|
| Agent 수 | 3개 × 팀별 2벌 = 6 | **4개** (업종별 2 + 공통 2) | 재구성 |
| 품목 | SAC · 모바일 · IT제품 · DID | **TV · 디스플레이(사이니지)** | 카탈로그 교체 |
| 버티컬 | 대기업/공공 경로 | **상업시설 · 호텔 · 병원 · 오피스 · 교육시설** | 재정의 |
| A 입력 | `industry_news.csv` 9열 | `[품목][헤드라인][원본url][키워드]` + RSS 검색어 + 건설사 목록 | 재생성 |
| B 입력 | `smb_demand` + `competitor_lineup` | **네이버 뉴스 API 더미** + 상권정보 + 파트너 시공가능규모 | 재생성 |
| C 입력 | HVAC 카탈로그 + 서비스 조건 | **네이버 크롤링 가격** + **TV 가격가이드 Excel** | 재생성 |
| D 입력 | Lead/BO 파이프라인 / 파트너 매출 | **과거 판매실적 10열** (버티컬 축) | 재생성 |
| 출력 형식 | Markdown | **HTML 3개 + Word 1개** | 전면 변경 |

**그대로 쓰는 것** — 지시문 7블록, 테스트 3종(정상·경계·실패), 검수 기준, IPO 명세, STOP 규칙, 웹 환경 절차(복사·저장, paste, 소계본), 강사 가이드 골격, 워크북 골격.

공통층이 살아남는 것이 이 설계의 요점이었고, 실제로 시나리오가 통째로 바뀌었는데도 방법론 자료는 손댈 필요가 없습니다.

## 8. 삼성에 확인할 것

1. **TV 가격가이드 Excel** — 실제 컬럼 구성을 받을 수 있는지. 없으면 더미로 구성하되 헤더만 맞추겠습니다.
2. **Skills 기능** — 캡처의 「스킬 추가」를 실습에서 써도 되는지. 된다면 산출물을 조직 디렉터리에 공유하는 형태까지 갈 수 있습니다.
3. **HTML 출력** — "확장프로그램 활용"이라고 적힌 것이 어떤 확장프로그램인지. 없으면 HTML 코드를 받아 로컬 저장하는 방식으로 진행합니다.
4. **Word 보고서(Agent B)** — Word 파일 생성인지, Word에 붙여넣을 형식의 텍스트인지.
5. 버티컬 목록의 표준 명칭 — 사내에서 쓰는 분류가 있는지.
