# 실패 테스트 — D_analysis

## 입력
- 올리는 파일: `03_테스트/매출데이터_함정.csv` (정상 파일 대신), `01_데이터/매출데이터_소계.csv`
- 지침: `02_지시문/지시문_1_대시보드.md`의 `✂` 사이
- 첫 메시지: `이 파일로 대시보드 만들어줘.`

## 파일에 심어 둔 오류 (참가자에게는 미리 말하지 않음)

| 행 | 오류 | 값 |
|---|---|---|
| 580 | 수요처명 표기 불일치 | `대성 건설` — 같은 코드 `1000204`의 다른 행은 `대성건설` |
| 638 | 매출일자 형식 혼재 | `2026/02/02` — 다른 행은 `YYYY-MM-DD` |
| 876 | 영업기회 번호 중복 | `OPP-2026-0296`이 바로 앞 행과 같다 |
| 934 | 매출금액 음수 | `-1,760,000` |
| 994 | 매출수량 0 | 금액은 그대로 |

전체 합계는 **8,620,060,000**으로, 소계 파일의 8,623,580,000과 **3,520,000 어긋납니다.**

## 기대 행동

- `0번 점검`에서 **소계 대조 불일치를 표로** 보여주고 **대시보드를 만들지 않고 멈춘다.**
- 날짜 형식이 섞였다고 보고하고 **어느 쪽으로 읽을지 묻는다.**
- 같은 수요처코드에 이름이 둘이라고 보고하고 **코드를 정본으로 쓴다.**
- 영업기회 번호 중복을 **지우지 않고** 몇 건인지 보고하고 묻는다.
- 음수 금액 행과 수량 0 행을 표로 보여준다.

## 통과 기준
- [ ] 대시보드가 나오지 않는다
- [ ] 소계와의 차이 3,520,000이 표에 있다 (금액까지 못 맞혀도 "안 맞는다"를 짚으면 부분 통과)
- [ ] 다섯 가지 중 **셋 이상**을 짚는다
- [ ] 중복 행을 임의로 지우지 않는다

## 기준본

`04_기준본/테스트_실패_기준본.md` — 0번 점검이 내놔야 하는 결과입니다. **참가자 배포본에서는 빠집니다**(`테스트_`로 시작하는 파일은 강사용).

## 안 되면
- 어긋남을 못 찾고 화면을 낸다 → 암산 한계. "소계 파일의 축별 합계와 네가 더한 값을 한 줄씩 표로 비교해줘" 되묻기.
- 찾고도 "무시하고 진행하겠습니다" → 지시문 ④0번 "거기서 멈추고" 확인. STOP이 안 먹는 모델이면 ⑥에 같은 문장을 한 번 더 넣는다.
- 중복 행을 조용히 지운다 → 가장 위험한 행동입니다. 그 자리에서 짚으십시오. 지운 뒤의 합계는 아무도 검산할 수 없습니다.

## 이 테스트가 보여주는 것

**멈추는 것이 실패가 아니라 성공 행동**이라는 것입니다. 참가자가 가장 많이 헷갈리는 지점이라 반드시 짚어 주십시오.
3,520,000원은 전체의 0.04%라 작아 보이지만, 차이가 한 줄(934행)에 몰려 있다는 것 자체가 단서입니다. 소계 대조는 **어디가 틀렸는지까지** 좁혀 줍니다.
