# Skill과 MCP — 오늘 만든 것이 어디로 이어지는가

> 이 문서는 ③ 모듈 마무리 또는 과정 클로징에서 다룹니다.
> 실습 필수는 아니지만, **오늘 만든 지시문이 왜 그런 구조인지**를 설명해 줍니다.

---

## 1. 오늘 만든 것은 이미 "Skill"입니다

오늘 세 모듈에서 이렇게 만들었습니다.

```
지시문 7블록 (agent02_prompt.md)
   +
참조 파일 (team_profile.md, 데이터 CSV, 양식)
```

이 조합에는 이름이 있습니다. **Agent Skill**입니다.

Skill은 폴더 하나입니다.

```
내-업무-스킬/
├─ SKILL.md          ← 이름·설명 + 지시문 본문
└─ (참조 자료)        ← 템플릿, 예시, 양식, 데이터
```

`SKILL.md`는 두 부분입니다.

```markdown
---
name: 파이프라인-현황-보고
description: 월말 Lead·BO 파이프라인 데이터를 받아 단계별 현황과
             전월 대비 증감, 특이사항을 담은 보고서 초안을 만든다.
             합계가 안 맞으면 중단한다.
---

① 역할 — 너는 B2B팀의 데이터 분석 Agent다
② 업무 범위 — ...
③ 입력 검사 — ...
④ 처리 순서 — ...
⑤ 출력 형식 — ...
⑥ 중단·보안 — ...
⑦ 성공 기준·사람 승인 — ...
```

**위가 우리가 쓴 지시문 7블록 그대로입니다.** 새로 배울 게 없습니다.

---

## 2. description이 왜 따로 있나

Skill에서 `name`과 `description`만 **항상 읽힙니다.** 본문은 그 설명과 맞는 일이 들어왔을 때만 읽힙니다.

```
평소:   "파이프라인 보고서 만드는 스킬이 있구나" (설명만)
요청 시: 본문 전체를 읽고 그대로 실행
```

이 방식을 **점진적 공개(progressive disclosure)** 라고 합니다. 긴 프롬프트를 매번 통째로 넣는 것보다 읽는 양이 줄어든다고 알려져 있습니다.

실무에서 중요한 건 다른 점입니다. **description을 모호하게 쓰면 AI가 언제 이 스킬을 써야 할지 모릅니다.**

| ✗ | ○ |
|---|---|
| 보고서를 잘 만들어 줍니다 | 월말 파이프라인 데이터를 받아 단계별 현황과 전월 대비 증감을 담은 보고서 초안을 만든다. 합계가 안 맞으면 중단한다 |

우리 지시문 ②번(업무 범위)을 "하는 일 / 하지 않는 일"로 나눠 쓴 이유가 이것입니다.

---

## 3. 왜 이게 "컨텍스트를 데이터로"의 완성형인가

Agent Skill은 **오픈 표준**입니다. 2025년 12월 공개된 뒤 여러 도구가 같은 파일 형식을 읽습니다 — ChatGPT, Claude, Codex, Cursor, Gemini CLI 등.

이게 뜻하는 바는 이렇습니다.

| | 도구에 종속된 방식 | Skill 방식 |
|---|---|---|
| 도구를 바꾸면 | 처음부터 다시 만듦 | **같은 파일을 그대로 씀** |
| 담당이 바뀌면 | 인수인계가 구두로 | 폴더를 넘김 |
| 팀이 바뀌면 | 새로 작성 | 참조 자료만 교체 |
| 차수가 늘면 | 강사마다 다르게 | 같은 파일로 동일 품질 |

오늘 과정에서 "지시문을 메모장에 따로 저장하세요"라고 한 것이 바로 이 자산을 만드는 첫 단계입니다.

---

## 4. 이 환경에서 되는 것과 안 되는 것

사내 환경은 웹 브라우저로 ChatGPT·Gemini를 쓰는 방식입니다.

| 도구 | Skill 대응 기능 | 상태 |
|---|---|---|
| **ChatGPT** | Skills (Business·Enterprise·Edu 제공) | **확인 필요** — 열려 있으면 등록해 재사용 가능 |
| **Gemini (웹)** | Gems가 대응물 | **사용 불가** (8/18 안내) |
| Gemini CLI | SKILL.md 직접 읽음 | 실습 제외 (설치 장벽) |

### ChatGPT Skills가 열려 있다면

③ 모듈에서 만든 지시문을 그대로 Skill로 등록할 수 있습니다.

```
① 지시문 7블록 앞에 name·description 추가
② 참조 자료(양식, 팀 프로필)를 함께 올림
③ 워크스페이스에 공유 → 팀원이 같은 기준으로 사용
```

이러면 세션이 끊겨도, 담당이 바뀌어도, 다음 차수에도 그대로 씁니다.

### 열려 있지 않다면

지금 방식 그대로입니다. **지시문을 메모장에 `agent02_prompt.md`로 보관**하고 붙여넣어 씁니다. 만드는 내용은 똑같고, 보관 장소만 내 PC입니다.

**어느 쪽이든 오늘 배운 구조는 바뀌지 않습니다.** Skill 기능은 보관·공유를 편하게 해주는 것이지, 지시문을 잘 쓰는 일을 대신해주지 않습니다.

---

## 5. MCP — 이건 무엇이고 왜 오늘 안 쓰나

**MCP(Model Context Protocol)** 는 AI가 외부 시스템에 연결되는 표준 통로입니다. 메일, 캘린더, 사내 DB, 사내 시스템 같은 것들입니다.

| | Skill | MCP |
|---|---|---|
| 무엇 | **어떻게 일할지** 알려줌 | **무엇에 접근할지** 열어줌 |
| 형태 | 지시문 + 자료 파일 | 서버 연결 |
| 누가 만드나 | 현업 담당자 | IT·개발 조직 |
| 오늘 실습 | **함** | **안 함** |

오늘 ② 모듈에서 뉴스 CSV를 직접 올렸습니다. MCP가 연결되면 그 파일을 사내 시스템에서 **자동으로 가져옵니다.** 사람이 올리는 단계가 사라집니다.

### 왜 오늘은 안 하나

| 이유 | 내용 |
|---|---|
| 관리자 권한 | ChatGPT는 워크스페이스 관리자가 켜야 하고 **기본 비활성**입니다. 교육생이 각자 켤 수 없습니다 |
| Gemini | 일반 Gemini 앱은 커스텀 MCP를 지원하지 않습니다 |
| 보안 | 사내 데이터가 외부 서버를 경유합니다. 정보보안 검토 대상입니다 |
| 사내 정책 | 8/18 안내에 **플러그인 사용 불가**로 되어 있습니다. 커넥터도 같은 관리 체계입니다 |

### 그래도 알아둘 것

**MCP는 "연결하면 편해지는 것"이 아니라 "무엇을 열어줄지 정하는 것"입니다.**

연결되는 순간 AI가 그 시스템의 데이터를 읽습니다. 그래서 사내에서 MCP를 도입할 때는 이런 걸 정합니다.

- 어떤 시스템을 **읽기만** 허용할지, **쓰기**도 허용할지
- 누가 쓸 수 있는지 (부서별·역할별)
- 어떤 데이터는 절대 나가면 안 되는지

오늘 지시문 ⑥번(중단·보안) 블록에 쓴 규칙들이, MCP 환경에서는 **훨씬 더 중요해집니다.** 파일을 사람이 골라 올릴 때는 실수해도 그 파일 하나지만, 시스템이 연결되면 범위가 다릅니다.

### 개인이 외부 MCP를 붙이는 것

인터넷에는 개인 계정으로 연결하는 MCP 서비스들이 있습니다. 사내 환경에서는 **개인 판단으로 연결하지 않습니다.** 사내 데이터가 검토되지 않은 외부 서버를 지나게 됩니다. 필요하면 정보보안·IT 조직을 통해 정식 절차로 검토합니다.

---

## 6. 정리

```
오늘 만든 것          지시문 7블록 + 참조 파일
        ↓
이것의 이름            Agent Skill
        ↓
보관 방법              Skills 기능(열려 있으면) 또는 내 PC 파일
        ↓
다음 단계 (조직)       MCP로 사내 시스템 연결 — IT·보안과 함께
```

**오늘 배운 건 맨 윗줄입니다.** 아래 두 줄은 위가 제대로 되어 있어야 의미가 있습니다. 지시문이 모호하면 Skill로 등록해도 모호하고, MCP로 연결해도 모호한 결과가 더 빨리 많이 나올 뿐입니다.
