## 0. 결론: 4개 Agent

| # | Agent | 구분 | 대상 | 산출 형식 |
|---|---|---|---|---|
| **A** | 시장·고객 분석 (Sensing) | **업종별** | B2B팀 (직판·수요처) | **HTML 대시보드** |
| **B** | 시장·고객 분석 (Sensing) | **업종별** | B2B유통전략팀 (경로·파트너) | **Word 보고서** |
| **C** | 제안자료 작성 (Action) | **공통** | 양 팀 | **HTML** (3개 비교) |
| **D** | 데이터 분석 (Analysis) | **공통** | 양 팀 | **HTML** (추천 TOP3) |

본 과정 6시간은 3개 모듈이므로, **② 모듈에서만 팀에 따라 A 또는 B를 진행**하고 ③④는 전원 공통입니다.

```
② 시장·고객 분석 (2h)   B2B팀 → A     |  유통전략팀 → B
③ 제안자료 작성 (2h)    전원 공통 → C
④ 데이터 분석 (2h)      전원 공통 → D
```

양성과정(9/16~17)은 17명이 A와 B를 모두 체험하므로 네 개를 다 다룹니다.

## 1. Agent A — 시장·고객 분석 (B2B팀)

> 삼성 양식 1-1

**업무 상황**
B2B 영업 담당자로서 현재 관리 중이거나 장기적으로 영업 대상이 될 주요 수요처를 특정하고, 해당 산업과 수요처의 최근 언론 기사·업계 미디어·기업 발표자료·시장 조사 자료를 찾아 **어떤 변화가 있었는지 / 고객의 투자·구매 수요가 무엇인지 / 어떤 사업기회가 예상되는지**를 파악한다. 최종적으로 공략 가능한 영업기회를 분석하고 접근 방향까지 제안한다.

| 항목 | 내용 |
|---|---|
| Input 필수 헤더 | `[품목]` `[헤드라인]` `[원본url]` `[키워드]` |
| 수집 방식 | **구글 RSS** 활용, 외부 트렌드 자료 수집 |
| 도구 | **GPT, 제미나이** |
| Agent 형태 | 수요처별 시장 정보 조사 결과를 **대시보드 형태로** 나열·분석, 미래 영업기회 및 Action-Plan 제시 |
| Output | **HTML** — Customer Profile + Key Signal + Needs + Sales Opportunity + Recommended Action |

**v1 대비 변경점** — 기존 `industry_news.csv`(9열)를 삼성 지정 4개 필수 헤더 중심으로 재구성. 출력이 MD → **HTML 대시보드**.

## 2. Agent B — 시장·고객 분석 (B2B유통전략팀)

> 삼성 양식 1-2

**업무 상황**
B2B 경로 영업 담당자로서 특정 **권역**의 여러 파트너사를 관리하며 담당 권역 시장상황을 점검하던 중, 최근 **신규 상업시설·호텔·병원·오피스·교육시설의 개점·이전·신축·리뉴얼**이 증가한다는 정보를 입수. 언론기사·지역 미디어·기업 홈페이지·시장조사 자료·상권정보를 각각 검색해 변화를 확인하고 이를 담당 파트너사의 영업기회와 연결해야 한다.
→ **담당 권역을 입력하면** 시장·상권 정보를 분석하고, 주요 영업기회를 찾아 **수주 확정을 위해 파트너사와 무엇을 논의해야 할지** 제안하는 Agent를 만든다.

| 항목 | 내용 |
|---|---|
| Input | **네이버 뉴스 Data API 더미데이터** (외부 API 연동 가정)<br>API 데이터 예시, 상권정보, 파트너사 통한 정보 |
| 제공물 | 프롬프트 3종 — ① 검색 키워드 작성 ② API 더미데이터 연동해 Agent 제작 ③ 원하는 양식에 맞춰 결과물 출력 |
| Output | **Word 보고서** — 권역시장 요약 / Key Sales Signal(시장·지역별 Insight) / 영업기회 리스트 / 근거 / **파트너사와 논의사항** |

**A와 B의 차이** — A는 *수요처(기업) 단위*, B는 *권역·상권 단위*. A는 직접 영업, B는 파트너를 통한 영업이라 마지막 산출물이 "파트너사와 논의사항"으로 끝납니다.

## 3. Agent C — 제안자료 작성 (공통)

> 삼성 양식 2

**업무 상황**
B2B 직판 영업 또는 파트너사를 지원하는 경로 영업 담당자. 고객사로부터 **신규 사무공간·회의실·호텔·매장** 구축을 위한 제품 제안 요청을 받았다. 고객은 정확한 모델명이 아니라 **화면 크기·사용 목적·주요 기능·설치환경·수량·예산** 등 요구조건을 전달했다.

담당자는 요구사항을 검토해 적합한 당사 모델을 찾고, 제안 경쟁력 판단을 위해 외부 포털에서 **시장 판매가격**을 확인하고 **유사 사양 경쟁사 제품과 가격·스펙을 비교**해야 한다. 제품 Line-up과 Spec이 다양하고 가격·경쟁제품 정보를 일일이 검색해야 해서 시간이 많이 걸린다.

| 항목 | 내용 |
|---|---|
| Input (외부) | 네이버 크롤링 — `[수요처명]` `[모델명]` `[온라인가격]` `[제품spec.]` |
| Input (내부) | **B2B 마케팅/가격가이드 Excel (TV 제품)** |
| Agent 활용 | 프롬프트 ① 더미데이터에서 유용한 스펙 추출, 고객 요청 디바이스 정보 분석<br>프롬프트 ② 추출 스펙 기반으로 고객 요청 디바이스 제안 |
| Output | **HTML** (확장프로그램 활용) — 고객 요청과 가장 부합하는 **제안제품 3가지**, 3가지 상호비교 + 시장가격 비교 |

**품목이 TV·디스플레이입니다.** v1의 SAC·모바일 카탈로그는 폐기하고 TV/사이니지 라인업으로 교체합니다.

## 4. Agent D — 데이터 분석 (공통)

> 삼성 양식 3

**업무 상황**
신규 고객 또는 프로젝트에 적합한 제품을 제안해야 한다. 과거 B2B 판매 실적에 **버티컬별·수요처별·제품별 판매 이력**이 쌓여 있으나 일일이 분석해 유사 고객의 구매 패턴과 적합 제품을 찾는 데 시간이 많이 걸린다.
→ 제안 대상 수요처의 **버티컬/업종 특성을 입력하면** 과거 유사 버티컬 판매 데이터를 분석해 ① 어떤 제품이 주로 팔렸는지 ② 어떤 제품 조합이 효과적이었는지 ③ 어떤 제품이 이 수요처에 적합한지를 도출한다.

| 항목 | 내용 |
|---|---|
| Input (사내) | B2B 과거 판매 실적 — `[판매일자]` `[버티컬]` `[수요처]` `[제품군]` `[모델명]` `[공급가]` `[판매수량]` `[판매금액]` `[프로젝트/용도]` `[지역]` |
| Input (분석 대상) | `[수요처명]` `[버티컬]` `[프로젝트/용도]` |
| 처리 | ① 대상 수요처 버티컬 분석 → ② 유사 버티컬 과거 판매 데이터 분석(판매량·판매금액·반복 구매 패턴) → ③ 제품 추천 → ④ **"왜 이 제품인가"를 과거 실적 데이터로 설명** |
| Output | **HTML** — ① 대상 수요처 분석 ② 버티컬별 판매 Insight ③ 추천 제품 TOP 3 ④ 영업 제안 Point |

**"버티컬"이 핵심 축입니다.** v1의 Lead/BO 파이프라인, 파트너 매출 구조는 폐기합니다.

## 6. v1 데이터 팩과의 차이 — 전면 교체 대상

| 영역 | v1 (9/4 작성) | v2 (삼성 확정) | 조치 |
|---|---|---|---|
| Agent 수 | 3개 × 팀별 2벌 = 6 | **4개** (업종별 2 + 공통 2) | 재구성 |
| 품목 | SAC · 모바일 · IT제품 · DID | **TV · 디스플레이(사이니지)** | 카탈로그 교체 |
| 버티컬 | 대기업/공공 경로 | **상업시설 · 호텔 · 병원 · 오피스 · 교육시설** | 재정의 |
| A 입력 | `industry_news.csv` 9열 | `[품목][헤드라인][원본url][키워드]` + 구글 RSS | 재생성 |
| B 입력 | `smb_demand` + `competitor_lineup` | **네이버 뉴스 API 더미** + 상권정보 | 재생성 |
| C 입력 | HVAC 카탈로그 + 서비스 조건 | **네이버 크롤링 가격** + **TV 가격가이드 Excel** | 재생성 |
| D 입력 | Lead/BO 파이프라인 / 파트너 매출 | **과거 판매실적 10열** (버티컬 축) | 재생성 |

**그대로 쓰는 것** — 지시문 7블록, 테스트 3종(정상·경계·실패), 검수 기준, IPO 명세, STOP 규칙, 웹 환경 절차(복사·저장, paste, 소계본), 강사 가이드 골격, 워크북 골격.

공통층이 살아남는 것이 이 설계의 요점이었고, 실제로 시나리오가 통째로 바뀌었는데도 방법론 자료는 손댈 필요가 없습니다.

## 8. 삼성에 확인할 것

1. **TV 가격가이드 Excel** — 실제 컬럼 구성을 받을 수 있는지. 없으면 더미로 구성하되 헤더만 맞추겠습니다.
2. **Skills 기능** — 캡처의 「스킬 추가」를 실습에서 써도 되는지. 된다면 산출물을 조직 디렉터리에 공유하는 형태까지 갈 수 있습니다.
3. **HTML 출력** — "확장프로그램 활용"이라고 적힌 것이 어떤 확장프로그램인지. 없으면 HTML 코드를 받아 로컬 저장하는 방식으로 진행합니다.
4. **Word 보고서(Agent B)** — Word 파일 생성인지, Word에 붙여넣을 형식의 텍스트인지.
5. 버티컬 목록의 표준 명칭 — 사내에서 쓰는 분류가 있는지.
